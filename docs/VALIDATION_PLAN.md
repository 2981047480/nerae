# 验证计划与证据要求

验收对象先注明：方案合同 / 单元规则 / 真实服务集成 / 平台联调 / 用户与视觉 / 公开上线。不同层级不能互相替代。当前只有合同与规划工具、交互参考可执行；下表应用命令由 F01/F02 建立。

本轮新增：[工程标准](ENGINEERING_STANDARDS.md)的EG01–EG08落实到明确执行卡；[完成定义](DEFINITION_OF_DONE.md)约束接受。37工作包+21执行卡，未细拆工作包和暂缓UI不进入ready。

## 3. 性能和可靠性目标（待基准验证）

- 普通业务 API P95≤500ms；首屏≤1.5s。先登记设备/网络、并发与数据量，再报告分位；不能用 localhost 单次请求宣布达标。
- 初始负载试验场景：100并发读、20并发写、1万条训练会话；这是容量测试输入，不是预计真实流量。慢查询/热点/锁等待达到门槛后再调优，先不拆微服务。
- AI 初始体验预算：1秒内出现可理解状态；15秒仍未完成给继续等待/离开后恢复提示；客户端总等待45秒后展示可恢复超时。技术时间预算需 A05 真测后冻结；不能把15秒当已验证SLA。若同步契约无法可靠恢复，先由共享owner增加任务查询契约，禁止UI假进度。
- 核心链路99.9%为上线后的目标；错误率、队列堆积、恢复时间与费用有观测后才报告实现。训练持久化队列断电重启可恢复，客户端显示同步状态，不承诺“绝不会丢”而无证据。
- 备份初始工程目标 RPO≤24h、RTO≤4h，必须以独立恢复演练证明；最终值由试点损失容忍度与成本批准后冻结。

## 4. 视觉与易懂性门槛

390×844 为主参考，320×568为最小布局压力，430×932和桌面1440×900补充；微信iOS/Android各至少一台，记录版本。不能用浏览器设备模拟称真机。

长中文、三位/小数重量、标题换行、空列表、网络错误、权限失效、键盘弹起和安全区均截图。主要操作44px以上；正文≥16px，辅助≥13px；对比度依据 tokens 校验并看实际页面。减少动态效果不丢状态/反馈，禁无限呼吸CTA和自动滚动。

先人工检查层级、内容真实性、下一步，再做差异比较；动态时间和可变测试内容固定，遮蔽范围记录。初始像素阈值0.5%仅供稳定参考组件，不能拿一个全局数字替代不同设备视觉判断。

认知/执行负担各0–14，按全局AGENTS七项分别计0–2，记录证据和评分者；设计预估与用户实测分栏。>6先改，特殊专家编辑页需说明理由。动作预算列决定/输入/导航/确认/等待/恢复六类，不能把登录或失败路径藏掉。

## 5. 交付证据与接受

每份报告：任务ID、基线/集成提交、实际模型/推理、修改范围、工具/环境、命令退出码、截图路径、通过/失败/跳过、剩余风险、reviewer。真实个人信息与密钥不写日志。证据登记 path+SHA-256+revision，revision必须等于accepted_revision；存在文件和hash一致仅证明未变，不自动证明内容合格。

Lead 对 schema/业务不变量和共享边界做review，QA提交证据，产品/视觉/安全最终接受由高判断角色或Lead完成。完成任务不得自动对外发送消息、推生产或宣布合法上线。每次版本只重跑影响面与必要接缝；新失败或变更才扩测。

## 6. 批内集成与陌生agent验证

F01-I/F02-I检查干净构建、真实隔离环境、生成与中间件；I-A01/02/03和I-B01/02负责真实注册路由的接缝。integration_result必须覆盖直接依赖并指向同一集成提交；新增业务另开卡。I01/I02仍负责完整产品闭环，不能由提前的API卡代替。

F02-01记录陌生执行者的真实额外上下文请求、返工、越界和复跑。冷启动身份/记录/可复跑证据是接受条件；具体返工次数是观测量，不预设成功数字。本轮不启动此试验。

S01-A/S01-B以来源、使用权、适用性/专业复核、未知值、稳定ID和幂等导入验收；缺内容材料不靠测试fixture填满。V01/V03分别要求对应内容卡通过。后台工作流O01/O02/O03按ENGINEERING_STANDARDS责任表逐项检查，不以可构建空壳代替运营可用。
