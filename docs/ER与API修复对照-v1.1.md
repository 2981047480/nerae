# ER 与 API 契约修复对照 v1.1

> 日期：2026-10-22。
> 对象：[OpenAPI 1.1.0](<api/openapi.yaml>)、[ER v1.1](<docs/数据模型与ER设计.md>)、[PRD v1.9](<docs/PRD.md>)。
> 本轮范围：修复上一轮审核的设计和契约缺口，补静态回归与生成验证；**没有实现或部署业务服务器，没有建库或迁移生产数据**。

## 1. 结论

**审核指出的核心缺口已在契约和数据模型层补齐，正式校验、TypeScript 类型生成、Go 接口生成与隔离编译通过。** 现在可以据此拆分业务实现任务，但不能把这些结果当作真实 HTTP、权限隔离、事务并发或健康安全已经验收。

修订保留用户确定的产品方向：不在平台收款、教练自主定价、训练/饮食计划广场、教练与学员分类发布、AI 辅助配置、饮食打卡及辅助筛查；没有通过删掉这些功能来让校验通过。

## 3. 原审核问题逐项闭合

原编号来自[审核报告 v1.0](<docs/ER与API审核报告-v1.0.md>)；该报告是历史快照，旧行号不代表修订稿位置。

| 原问题 | 本次修正 | 验证边界 |
|---|---|---|
| T1 默认值层级非法 | 默认值归 schema；补稳定 operationId 和统一错误响应 | 正式 lint 结构错误消除 |
| T2 枚举被 YAML 误读为数字 | 字符串枚举明确化，静态检查拒绝数字/布尔歧义 | 跨工具生成与静态检查通过 |
| S1 授权撤回旧写覆盖 | grants 强制 expectedVersion，空 scopes 明确撤回；终止关系即时失效；读数据和异步任务必须重查 | 结构/负例通过；原子 CAS、缓存失效仍需运行时测试 |
| S2 模板正文/版本无归属 | 公域 template_version、私域 plan_version 独立完整快照；另存固定版本；回滚生成新版本 | ER 与契约对齐，尚未生成 DDL |
| S3 后台凭据未建模 | 独立 admin_account、凭据哈希/状态/令牌版本、审计主体与独立 audience | 模型与输出类型闭合，鉴权实现待开发 |
| S4 / Q3 训练日没有可用 ID | 读模型返回稳定 TrainingDay.id；按计划开始训练必须带 planId/planVersion/planDayId；自由训练为另一分支 | 正反例及联合类型检查通过 |
| S5 离线键跨账号冲突 | clientEventId 在 user_id 域唯一；组记录使用 session+recordKey；幂等键按主体/方法/路径隔离 | 约束已写，数据库唯一性和并发执行待测试 |
| Q1 缺关系发起 | 新增教练发起关系，服务说明快照/期限/termsHash；教练发起即其确认，学员独立确认同一版本 | 可从新咨询进入服务，不再靠后台预插关系 |
| Q2 缺交付/反馈 | 补教练草稿创建、编辑、确认发布、学员读取、点评；补咨询单隔离消息 | 契约能表达首批闭环，未请求真实服务 |
| Q4 饮食副本不能编辑 | 训练/饮食内容分别具名，个人饮食可改份量并生成新版本；不再用公开模板响应冒充私人实例 | 内容正反例、编辑路径与版本检查通过 |
| Q5 AI 确认无版本证据 | 服务端发布草稿、版本/hash、字段来源、确认集合与最终发布版本绑定；改内容或受众后旧确认失效 | 结构与正反例通过；hash/字段覆盖真实计算待实现 |
| Q6 打卡不能证明摄入 | 餐次自评与可选、经确认的饮食观察分开；固定 planVersion/dayIndex；证据不足返回 insufficient_data | 不再允许用打卡勾选推断实际热量；模型判断仍待专业评测 |

其他同步修正：
- 写模型与读模型分离，关键写入不再接受空对象；来源标签、认证、证据等级设为服务端只读，客户端不能写入可信背书。
- 伤病信息仅写入，普通档案不回显；显式 null 可请求清除。个人过敏信息自愿采集、单独同意、独立 allergy scope，可撤回。
- 计划是学员的数据，不代表学员可以读取教练未发布的草稿；学员读取教练计划必须投影到 publishedVersion。
- AI 信息不足/安全阻断时保留待补字段，不强行编造完整餐单；这类草稿可以回读。只有 ready/submitted 状态必须具备完整内容及哈希。
- 公开/link/private 可见性不同；私有资料不因公开展示标签而暴露；link 分享经不可猜测 token，内容下架后链接失效。

## 4. 现在定义清楚的两条链路

### 教练交付

咨询 → 咨询单内联系 → 教练发起服务说明 → 学员确认同一份快照 → 按范围授权 → 教练创建/修改计划 → 人工确认发布 → 学员读取已发布版本 → 按指定训练日记录 → 教练点评。

### 免费计划与饮食

浏览公开模板 → 按指定版本另存 → 编辑个人训练/饮食副本 → AI 辅助预填发布草稿 → 核对估算字段与公开受众 → 提交审核 → 广场/链接展示 → 按计划版本打卡 → 有证据时辅助筛查、无证据时明确信息不足。

**上述链路是已定义的契约，不是已实现的产品演示。**

## 6. 接下来实施时必须验证

1. **授权和并发**：真实 JWT、主体/角色隔离、数据库 CAS、结束关系撤权、旧客户端重放、异步任务重查、文件下载权限。
2. **状态与数据完整性**：同一套餐版本与 terms、训练日与历史版本、饮食餐次与 slotKey、幂等提交、审核发布和私人实例独立性。
3. **AI 和健康安全**：真实供应商接口/数据条款、模型输出质量、未知信息处理、人工确认覆盖、营养规则专业审查和误报/漏报。模型名、便宜价格或 JSON 合法均不证明这些已通过。
4. **未覆盖功能**：周报自动化、图片打卡与媒体上传全链路、订阅消息、邀请码/海报、后台评价申诉全工作流、学员端 AI 调整“建议→确认→应用”的完整链路，仍需单独细化。
5. **上线准备**：数据库迁移、备份恢复、依赖安全审查、域名/备案/类目/AI手续、监控、数据删除及日志留存，不能用契约通过替代。
