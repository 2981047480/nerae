# Nerae 工程标准

版本 1.0 · 2026-10-23。当前工程规则真源，适用于 API、worker、客户端非视觉代码、后台业务与运维。本文件吸收归档工程规范中适用的细则，架构/业务语义仍分别以 IMPLEMENTATION_PLAN、OpenAPI、APP_FLOW、ER 为准。归档手册仅供查阅，不作为另一套生效标准。

**当前边界**：尚无业务工程、Makefile 或 CI；下列应用命令是各任务必须建立的接口，缺失不能报告已通过。2026-10-24 旧 UI 已清理，UI_SPEC 撤销旧视觉基线；D/U 工作包继续暂缓，本轮只推导设计逻辑，不生成 UI。

## 1. 责任与依赖方向

- HTTP handler 解码、取认证上下文、调用应用服务、映射响应；不直查数据库、不调用模型。
- application 组织用例与事务，domain 保持纯规则；repository 实现消费方定义的窄接口。框架类型不穿过领域边界，不建持有全库的全局 BaseService。
- 模块不得跨域直接写表；必须同步一致的授权/确认/发布在同一事务内完成，事务内 outbox 用于可靠后续动作。Redis 不能成为最终授权真源。
- server/cmd 只负责装配。共享路由、根依赖锁、生成配置、迁移全局顺序必须有单一 owner 和有序任务；模块作者提交变更需求，不在工作区外顺手改。
- 客户端/后台只经生成合同调用 API；端能力放 platform，视图不直连数据库或供应商。不手写一套 any DTO 绕过合同。
- F01-05 建立边界检查，使用语言解析/模块信息识别依赖，并以违规样例验证会失败；不以容易误判的字符串黑名单代替架构判断。

## 2. 工具链与依赖

F01-01 在临时兼容性探针中验证实际 Node/pnpm/Go/uni-app 组合，锁定运行时、包管理器、生成器、测试镜像与依赖。已有契约冒烟使用的版本不自动成为应用版本。应用文档记录工作目录、安装、构建、测试、配置名称和限制；不写真实配置值。

- 根锁文件在共享 owner 手中更新；两个工作区不能独立创造不同锁文件。F01-03/F01-05及F02-01若需变更根/Go依赖，在其明确白名单内由Lead串行收口。
- Go 格式检查、静态分析、race 单测和 TS strict/类型检查使用锁定工具；版本在 F01 实测后记录，不复制旧手册的任意版本清单。
- 生成文件不得手改；唯一 OpenAPI 改动走共享合同任务，再生成、检查所有消费者。operationId 不随意重命名。
- .review、虚拟环境、缓存、构建物、真实 .env、凭据与客户数据不得进入 Git。依赖升级单独变更并跑影响范围回归。

## 3. Go、错误与配置

- 依赖显式注入；禁止包级可变 DB/业务缓存，禁止 init 中连接数据库或读取运行配置。context 由入口传递，尊重取消和超时。
- 领域/仓储返回可识别错误，HTTP 层统一映射 OpenAPI Error 的 code/message/requestId。不比较错误字符串，不把 SQL、堆栈或供应商原文作为用户错误。
- 持久化枚举与 wire contract 一致，不用 iota 表示持久化状态；时间/金额/版本使用明确单位与命名。未经授权的输入字段不能被当作身份或来源背书。
- 配置启动时校验，必要项缺失非零退出；业务 readiness 与进程 liveness 分开。关闭流程处理请求、worker和连接，不假称依赖已健康。
- 正式业务路径不返回演示数据或临时用户；测试替身限明确的单元/故障注入边界，真实服务验收按 VALIDATION_PLAN。

## 4. 数据、事务、迁移与幂等

- 模块拥有自己的迁移与表写入，集成卡维护全局执行顺序；迁移序号/校验和冲突必须失败。禁止生产 AutoMigrate 或启动时重建库。
- 必须证明空库初始化、旧库升级、重复执行与失败恢复。可逆迁移验证 down；破坏性迁移采用扩展/收缩和补偿，不能声称 down 恢复已删除的数据。
- expectedVersion 在事务中比较，唯一约束负责业务防重。幂等范围为主体+方法+路径，摘要不同返回409；技术缓存过期不能撤销业务唯一键。
- 关系结束/撤权即时影响未来读写、模型输入和通知；后台任务提交前重查。列表、分页、缓存、导出和推送均在同一权限模型下。
- MySQL/Redis 集成必须使用真实隔离环境，两连接并发有明确初始状态、最终行数/版本/事件断言；环境缺失是未验证。
- API/worker 重试受限、事件去重、死信可恢复。AI固定既定配置，成本预留和晚到结算幂等，不自动换模型或发布内容。

## 5. 隔离与运行数据

一任务一工作区；F01-01完成真实Git基线前由Lead本地顺序引导。每个工作区使用独立端口、数据库、Redis命名空间与对象前缀；启动命令显示实际工作区，不隐式指向主分支。删除/清理必须限制明确测试命名空间，默认保留数据。

身份、grant与资源版本共同约束缓存；切账号清除私有缓存/队列。日志含requestId、操作、错误码、耗时和必要脱敏标识，健康正文、token、密钥不进入日志/trace/通用埋点。指标和审计不能因为某个后台角色存在就开放全部私人数据。

## 6. 后台运营与内容有独立责任

| 能力 | Owner | 验收依据 |
|---|---|---|
| 教练认证、证据文件、最小审核队列 | O01；I-A03接线 | 身份/audience、受限文件访问、审批状态、操作审计 |
| 内容审核、举报、评价申诉 | O02；I-B01接线 | 权限、时限、超时升级、下架/恢复、历史评价资格 |
| 指标、审计检索、导出与隐私运维 | O03 | 目的/范围限制、日志脱敏、恢复后删除/撤权再应用 |
| 训练交付内容 | S01-A；I-A02/V01使用 | 来源/使用权/适用范围/复核记录、动作快照与幂等导入 |
| 广场训练/饮食内容与食物来源 | S01-B；I-B02/V03使用 | 未知值、营养/过敏信息来源、公开审核与历史版本 |

上述是工作流与责任划分，后台界面设计另由后续阶段完成。内容用 content/seed 与 content/manifests 管理；每项有稳定ID、版本、来源、许可/授权、适用范围、复核人和校验和。专业结论需要真实合适审核人，模型或开发者不能代填资质。

导入先 dry-run 列差异，再验证重复运行/升级/部分失败恢复；不清空库。测试fixture、演示账号与真实交付内容明确分开，不虚构教练/成交/健康事实，不用AI随机内容填满库存。内容数量按试点覆盖确认，缺审核材料则对应内容门槛不通过。

## 7. 自动检查映射

CI只调用同一Make入口。检查脚本或环境未准备好必须非零退出，不能 echo 成功、空测试集或 skip 伪装通过。尚未建立的能力标明未就绪，不能显示为绿灯。

| ID | 检查与反例 | 负责建立 | 完成证据 |
|---|---|---|---|
| EG01 | plan.py check + scripts/tests；循环/越界/缺证据必须失败 | 本轮已有，F01-05接入CI | 当前静态检查与CI退出码 |
| EG02 | contract-check；非法schema/旧版本反例拒绝 | 当前Python检查已存在，F01-05封装 | 对应SHA与固定版本lint/测试 |
| EG03 | check-foundation；Go/TS格式、类型、构建真实运行 | F01-02/03/05 | 干净检出与类型错误注入 |
| EG04 | boundary-check；逆向依赖、跨域写入不可绕过 | F01-05 | 合法与违规依赖样例 |
| EG05 | check-isolation；双工作区端口/库/命名空间隔离 | F01-04/F01-I | 双进程实际写读与恢复 |
| EG06 | codegen-check；两次生成与提交物一致，漂移失败 | F02-01/F02-I | 原schema与生成物hash/编译 |
| EG07 | test-integration / migration-check；并发、重放、升级/恢复 | F02-03及各模块/集成卡 | 真实库、两连接断言与迁移记录 |
| EG08 | e2e-api FLOW=...；真实注册路由和跨模块错误 | I-A01至I-B02 | 同一集成提交可复跑HTTP断言 |

seed-check / seed-dry-run 由 S01 按真实内容建立；它们通过不替代使用权/专业审核。make check 在 F02-I 接齐当前已实现门禁；以后模块新增命令先登记再接入，不偷偷放宽现有门槛。

## 8. Review与变更

适用的完成项见 [统一完成定义](DEFINITION_OF_DONE.md)；任务必须引用证据与接受提交。共享接口、权限、迁移、模型/供应商、依赖与生产配置变化都说明消费者、兼容、风险与回退，不混在普通修复中。指标先实测冲突、返工、上下文请求、复核等待和集成耗时，再设目标，不照搬并发人数/返工率阈值。
