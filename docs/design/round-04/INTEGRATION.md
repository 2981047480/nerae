2026-10-28 更新：K01-01 已开始修订 OpenAPI、ER 和静态测试，见 [实施报告](../../evidence/K01/K01-01/report.md)。下列“现契约需后续合同卡收敛”保留为修订前的历史缺口；合同尚未经过同版接受，真实服务和同步行为仍未实现或验收。

## 本轮本地样机
一个 session.id、一组稳定 set.id、一份 inputs；recordingMode 只管填写方式。最终保存按 session.id 更新记录，归档不再创造 archived- 副本。日期独立存 trainingDate，completedAt 在样机表示录入确认时间；不得当作实际训练用时。旧 localStorage key 保留兼容，恢复时删除旧 rest 状态；不读出计时器。旧第三轮证据不修改，构建必须由当前源码生成。

## 正式业务接入约束（未实现）
- 采用/替换计划仍用既有 training-starts 原子流程与明确确认；补记不能伪造当天训练开始。两个 UI 模式共用 sessions、set batch、finish，不新增两套会话或记录键。
- 本地组 ID 映射稳定 recordKey；相同字段修改必须按同一记录键更新，明确删除需正式契约支持。expectedVersion/412 保留输入，不能静默丢掉另一设备结果。
- 训练日期遵守安排时区及既有补记规则；会话的训练日期与请求接收、录入时间分开。
- 不采集或计算训练计时；durationMin 未知时不能以默认值伪装实际。

## 现契约需后续合同卡收敛
本轮只改 UI 样机与产品文档，未擅改共享 OpenAPI 或宣称后端支持。已读现有 WorkoutCreate/WorkoutFinish/SetRecord：
1. WorkoutFinish 当前必填 durationMin，需改为可缺省/可空，明确未知时长；本次 UI 不为了满足接口编造用时。
2. SetRecord 当前必填 reps；实际秒数和每侧测量语义尚不能完整表达本地样机的 duration/durationPerSide，需一致设计并补有效正反例。
3. 批量 set 写入的明确删除/移除语义、训练日期变更及已结束会话修订规则需合同卡后串行接受，不能用本地成功冒充 API 已闭合。

正式集成前先提交小型合同卡，更新 OpenAPI/ER 及契约测试，再解锁实现。模式字段可保留客户端偏好，不必为了 UI 模式拆服务端资源。本轮不把未实现接口问题藏进页面，也不把历史 D01 任务状态改成新轮次成功。
