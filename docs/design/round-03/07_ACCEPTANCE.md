# 主代理独立验收规范

用户授权主代理验收指定执行者产物。接受的是 UI 交付，不以构建通过代替高级感、美观或交互质量；不以模型自报代替实际执行身份和渲染。

## 1. 来源和文稿完整性

- 55 个来源项和层级关系均有动机、决定、具体落点与检查；没有遗漏视觉子系统或只做五屏。
- 执行环境和精确模型从 Harness 模型选择 / 配置及运行记录交叉核实，记录新会话身份，旧会话完成记录不能代替本轮任务。
- 文稿在派发前冻结并记录文件散列 / Git 基线。代码与接受条件分别由 worker 和 Lead 所有。
- 核对原业务 PRD/API/ER 不被顺手重写；预览代码不冒充正式业务工程。

## 2. 高级感优先的视觉判断

主代理看实际截图和操作，自行做设计判断。每个维度可用1–5级记评审意见，但分数是主代理启发式，不是客观用户偏好成绩。高级感维度出现明显缺陷时，即使美观或功能分较好也不能抵消。

| 维度 | 接受时应实际看到什么 | 返工信号 |
|---|---|---|
| 构图与比例 | 主次有重心，留白承接内容，跨屏有节奏 | 空洞、大数字凑版、卡片堆、主按钮埋没 |
| 中文排版 | 字级、字重、行长、单位和边缘关系精确 | 灰字过小、长标题挤压、粗体满屏、单位错行 |
| 素材与材质 | 图像清晰、裁切有意图，深度来自内容与关系 | 手绘哑铃充摄影、损坏图、模板插画凑质感、过度玻璃 / 光晕 |
| 色彩与状态 | 明暗有秩序，强调有限且可读 | 同屏多主色、暖色小字不对比、状态只靠颜色 |
| 密度与情境 | 探索可比较、执行专注、审阅有证据、会话自然 | 同一白卡模板套所有任务、隐藏全部证据 |
| 细节一致 | 图标、圆角、控件、焦点与按压完整 | 多套笔画、伪按钮、不同页发明不同系统 |
| 动效配合 | 对象连续、状态因果明确，反馈短而有分量 | 全部 stagger、假进度、挡操作、跳闪、失效遮罩 |
| 内容与态度 | 具体、尊重、有真实依据 | 设计理由上屏、营销短句凑版、羞耻漏练、假背书 |

第一批只判四种代表节奏，不在视觉未成立时机械扩页。每个重大问题写明视口、截图、位置、影响和期待变化，交指定执行者返工。

## 3. 布局与可访问性

实际检查 320 / 390 / 430 / 768 / 1440 CSS 宽度，记录实际 innerWidth，不把宿主缩放或截图宽度当成 CSS 视口。检查文本放大、长中文、缺图、焦点、弹层、固定底部动作、safe-area、键盘与滚动。

按钮最低44×44，目标48px；正文可读，普通文字对比4.5:1、关键非文字3:1。一个清楚默认下一步，不能把所有选择都画成主要按钮。无横向溢出、重复 ID、意外 null / object 文本、覆盖与错误点击层。

## 4. 交互与状态覆盖

| 检查组 | 最少需要的证据 |
|---|---|
| F01 / C01 | 匿名浏览 → 条件 → 详情 → 必要确认 → 开始；取消、未成年、下架、重复 |
| F02 / C02/C08 | 已安排 / 进行中 / 完成 / 休息 / 暂停 / 周期结束；日期正确，恢复不改过去 |
| C03 | 无效输入、单侧 / 秒 / 自重、完成一组、真实计时、退出 / 刷新、同步重试不增组、全部完成 |
| C04 | 汇总对明细、时间范围、空 / 单条 / 信息不足、关联反馈返回 |
| F05 / C05 | 教练比较、服务包、预填咨询、取消 / 不可用渠道、服务与健康授权分开 |
| F04 / C06 | 消息草稿、空 / 发送中 / 失败同 ID 重试 / 只读 / 撤权，不泄漏原文 |
| F03 / C07 | 接续草稿、完整编辑、保存回读、缺项、阻断、技术失败、冲突、发布取消与确认；现用版不自动改 |
| F06 | 已有模板候选、过期 / 同建议重复确认、教练计划只交教练、应用不暗改安排 |
| F07 | 自己的内容编辑 / 审阅 / 待审核；改内容旧确认失效；饮食自评不造摄入 |
| S16 | 自主价格和服务说明保存 / 回读；不影响既有约定，不出现收款 |

状态设计可通过独立预览控制复现；不能仅检查控件存在。每个实际断言记录操作和可见结果，异步动作等待终态，避免把观察过早当成实现失败。

## 5. 动效与 Reduce Motion

至少实际操作 M01–M12 的适用触发，检查正常与减少动态效果的等价结果。记录观察方式、源中属性 / 时长、截图或实际过程证据。没有帧率仪器不宣称60fps；只看静态源码不宣称动效验收通过。

动画中重复操作、路由离开、预览重置后，旧计时和异步写入不能污染新场景。不能为了展示动画添加虚假等待。Reduce Motion 可由系统偏好和明确的预览检查开关触发，报告区分两种证据，不能伪称切换过系统偏好。

## 6. 文案、数据与可信度

逐段看产品可见文字，设计 / 实现 / 验收推理不得出现。允许当前用户需要的来源与限制，不能只用禁词替代判断。

对组数、进度、队列、未读、差异、版本和图表做一致性检查。62项旧清理记录等内部数字不应成为产品内容。样例人物和本地状态不能被报告为真实学员、模型输出、成交或健康效果。

## 7. 完成审计与证据

最终报告逐项区分：文稿已推导、UI已实现、主代理已检查、待真实用户验证、正式业务未实现。55项都要能追溯，不能由一个 build 绿勾支持全部目标。

保留构建 / 类型检查 / 必要状态测试命令与退出码；截图与源码散列同版本；运行进程和预览URL现场可用。任务状态仅凭对应证据更新。未完成或重大缺陷不因执行耗时长而视为完成。

若本轮只完成第一批，报告仍为 partial，目标保持 active，等待同一执行者完成后续并验收。最终按完整目标审计通过后才标记 goal complete。
