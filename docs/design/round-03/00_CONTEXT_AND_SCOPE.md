# 第三轮任务卡

## 用户目标

将设计意图逐项推导为产品、交互、视觉与动画，并由指定 DeepSeek 执行，最终交付经过实际验收的高级 UI。

## 责任

- 主代理：上下文、产品与视觉判断、文稿、范围、集成、验收；不代替指定执行模型编写 UI。
- 执行者：待核实 deepseek-harness / OpenCode 订阅中精确模型 ID 后登记，不填默认或猜测型号。
- 用户：整体目标、重要取舍、最后的喜好与接受判断。当前目标已授权推进，不重复询问是否恢复设计。

## 必要上下文与真源

AGENTS、RETRO、CURRENT_STATE、DESIGN_FOUNDATION、PRD 用户 / 价值 / 范围章节、APP_FLOW F01–F07、D01 的 inputs。API / ER 按具体状态问题查阅，不全量灌入执行文稿。

排除已删除旧 UI、历史市场材料和旧 diagrams 的视觉结构；不照搬其他项目品牌。DESIGN_FOUNDATION 是待验证逻辑，不是已批准外观。

## 输出与非目标

输出包括逐项推导、可追踪层级、完整开发文稿、执行身份与日志、UI 源码、预览、截图和验收报告。文稿阐述为什么；产品仅承载用户当前要理解和操作的信息。

本次 UI 交付不自动等于整个业务应用、生产后端、真实支付、微信真机、供应商或专业安全验收。正式开发任务的状态只能依自身证据变更。

## 接受标准

1. 上一步每一项都有明确动机、具体表现、交互规则、关联项和检查方法。
2. 开发文稿能让执行者不依赖聊天历史完成工作；所有重要中间决定有持久文件。
3. 真实使用用户指定执行链及模型，记录可验证身份，不能冒用其他模型。
4. 高级质感、整体美感、动画配合、内容与状态均经渲染和任务走查；可点击与无溢出只是必要条件。
5. 产品界面不出现设计理念、布局原因、实现架构、验收话术等内部推理内容。

## 风险与当前未决

执行入口与订阅模型待现场核实；无 Git 的隔离准备尚未完成；目标用户偏好没有实际研究证据，设计与启发式验收不能伪称用户研究结论。具体 UI 范围由全量情境推导收敛，不能退回只有五屏或换肤。
