# 情境、责任和操作规范

本文件将八种使用情境逐项变成可实施行为，关联 APP_FLOW F01–F07。页面名称是为了分配实现与验收，不是本轮推导的起点。设计理由不进入产品文案。

## C01 第一次找到能开始的内容

动机：用户要判断适合性，避免从零排计划与先填大表。产品表现为匿名探索、少量偏好、完整内容预览和明确开始路径。

信息顺序：训练主题和适用条件 → 周频次 / 时间 / 器械 → 动作与来源 → 开始。列表允许比较，详情仍呈现完整内容，不能只有一张照片和宣传句。训练与饮食来源分类准确；教练内容与学员分享分别标注来源。

用户决定：目标、可用条件、选哪份计划。App 执行：保留偏好与浏览位置，带入当前选择，开始时完成必要衔接。AI 推断：仅可解释已有内容，不能在后台从零生成个人处方。用户确认：开始时必要的登录 / 成年确认；替换已有安排另行确认。系统报告：开始的是哪份内容、今天进入哪次训练、是否已保存。

主路径：发现内容 → 看详情 → 开始 → 必要确认 → 当前训练。已有安排默认提供继续原安排；替换摘要交代取消哪些未来事项、历史保持。取消回到同一内容。

UI / 动效：图片与内容有吸引力，但适配事实容易读；进入详情保留所选内容的视觉连续性。无长入场动画、登录墙和资料问卷。

验收：筛选与撤销、空结果放宽、详情完整、登录取消回跳、未成年终止、重复开始返回同会话、模板下架不能新开始。界面 S02/S03；动作预算：匿名浏览 0 次强制输入，详情到开始 1 个主要决定；首次登录与成年确认单列。

## C02 回来继续训练

动机：系统应记住进度，用户不应再次整理自己做到了哪里。

信息顺序：今天的训练状态 → 当前 / 下个动作 → 开始或继续 → 必要上下文 → 其他内容。无安排、休息、暂停和周期结束各有自己的默认下一步，不能共用“暂无数据”。

用户决定：是否继续、改期或更换。App 执行：恢复同一会话、未提交输入和当前动作，计算当前安排。AI 推断：不需要。用户确认：只有重要更换。系统报告：恢复到哪里、记录与同步是否完整。

UI / 动效：今天应有明确的主任务重心；周日期为背景脉络，不抢动作。主任务接续到训练时减少信息密度；返回恢复原位置。不能给已经完成的训练再次出现“开始”或把完成误写为休息。

验收：刷新与重开恢复；已完成 → 今天保持完成；休息显示下次真实日期；未安排进入探索；暂停恢复遵守日期规则；过期不自动造新周期。S01/S04；预算：已登录进入会话 1 次主要操作、最多 2 次点击，重复资料输入 0。

## C03 正在完成当前一组

动机：身体和注意力用于训练，界面只承担必要记录与提示。

信息顺序：动作名 / 当前组 → 待确认数量与单位 → 完成本组 → 状态 → 动作说明与本次记录。上次数据有日期与来源；没有数据则允许输入，不能造默认成绩。重量、次数、单侧和时长分别处理，自重不出现误导的重量值。

用户决定：本组实际完成情况，必要时修改重量 / 次数。App 执行：预填、持久保存、稳定事件去重、接续下一组与休息、恢复计时。AI 推断：不参与完成事实。用户确认：每组实际完成；退出不用确认墙。系统报告：哪组被记录、在哪保存、是否待同步、下一步。

UI / 动效：执行进入专注模式；数量有足够尺寸，控件和单位配对，单手操作区域清楚。完成后的反馈围绕当前组转为已记录和下组接续，不全屏庆祝。休息计时来源于真实时间，可以跳过；不可仅循环一个装饰数字。

验收：空、零、负数、超界与小数规则；快速重复、退出 / 刷新、同步失败重试不加组；同组冲突保留两边信息；计时暂停恢复；完成所有组后准确汇总。S04；预算：每组 1 次确认，已知值不需重新录入，备注和感受可选。

## C04 练后理解自己的积累

动机：用户需要看懂投入，而非面对仪表盘或单次训练的健康结论。

信息顺序：本次确认事实 → 关联反馈 / 自己的备注 → 时间范围内的同口径记录 → 可选下一步。指标必须有范围、单位、来源和可比条件。无数据显示可开始的路径，不生成占位曲线。饮食自评不变成实际摄入统计。

用户决定：看哪个时间段或动作、是否提问 / 调整。App 执行：聚合确认记录、关联点评、保留范围选择。AI 推断：有证据的解读和信息不足说明。用户确认：改计划另走 F06，不在读图时自动改。系统报告：记录变化和限制。

UI / 动效：记录有时间脉络与可读的个人基线；只呈现能解释的图形，配文本与数据详情。一次有意义的数值变化反馈足够，不自动循环增长，不用排名与身体前后对比制造成绩。

验收：汇总与逐组一致；范围改变、无记录、仅一条、混合单位、延迟完成均无误导；从点评可回到原记录。S05/S08；预算：找到最近训练 ≤2 次导航，理解来源无需再跨屏查找。

## C05 选择教练与服务

动机：选择成本来自适配和信任，不能只把人做成漂亮头像或商品。

信息顺序：身份与擅长 → 服务内容与适用目标 → 响应约定和具体样例 → 价格语境 → 预约咨询。列表给比较必需字段，详情承载证据与条款。资料缺失直接表达未知，不显示精确伪评分。

用户决定：选择谁、哪种服务、是否咨询。App 执行：带入服务包和已知偏好、保留对比与来处、保存咨询草稿。AI 推断：P1 导购不进入本轮核心，不能引入越界个人处方。用户确认：咨询意图与后续服务说明；健康授权另列。系统报告：咨询状态、可用沟通路径、关系是否建立。

UI / 动效：人物和服务有清楚的空间关系，价格不能孤立成促销主角；进入详情保持人物 / 内容上下文。服务确认是短而完整的影响摘要。

验收：筛选空和返回位置、服务包切换、预填可改、取消不丢、渠道不可用、条款版本变化、无计划也能普通交流。S06/S07/S08；预算：咨询中重复已知资料为 0，备注可省；重要确认不省略。

## C06 接受具体指导和计划调整

动机：学员想知道“他看了我什么，我现在怎么做”，而非在消息与计划间自己找差异。

信息顺序：谁在何时回应 → 引用的训练 / 计划 → 具体反馈 → 本次改动 → 对安排的影响与本人决定。回复可以只是普通安排，不强制关联健康记录或计划。

用户决定：回复、查看、是否采用新版。App 执行：关联上下文、恢复输入、稳定发送与重试、保留现用版本。AI 推断：建议须分清身份和来源；教练计划改动由教练审核。用户确认：采用新版 / 授权。系统报告：发送、失败、交付和采用状态。

UI / 动效：普通消息自然可读；计划引用是能打开的上下文，不是堆叠的系统卡片；改动以内容为核心。展开、返回和发送反馈短而连贯。编辑中的消息不因新消息丢失，也不强制打断正在看的历史。

验收：空消息、发送中、失败重试同一 ID、只读、撤权不回显健康原文；发布版本与使用版本区分；新版过期 / 冲突需重新核对。S08/S09/S11；预算：从提醒到具体改动 ≤2 次导航，采用有一次明确确认。

## C07 教练把注意力放在判断上

动机：教练需要有上下文地回应多人，系统应承接检索、整理和重复填写。

信息顺序：待处理原因与优先级 → 学员 / 最近事实 → 未完成工作 → 相关证据 → 完整可编辑方案与改动 → 明确交付。普通操作可快，专业审阅不设不合理速度要求。

用户决定：处理谁、怎样回应、采纳哪些建议、发布什么。App 执行：带入学员、恢复草稿、保留现用版本、保存与回读、衔接上下文。AI 推断：草稿和摘要，不独立确认安全。用户确认：对具体对象的交付。系统报告：草稿保存、交付版本、待回应 / 尚未采用状态。

UI / 动效：工作区有专业判断所需密度，但不是后台指标堆。手机先看到原因与下一步，桌面可同看选中学员和证据。计划编辑是完整内容，审阅能比较改动；“3 处改动”不能代替全部方案。

验收：队列数量来自真实样例集合；无待办不造指标；未授权不显示假 0；重进回读草稿；缺项只补必要项；阻断与技术失败分开；重复发布不重复交付；取消不丢。S13/S14/S15/S16；预算：到原草稿 ≤2 次导航，重复学员录入 0，明确发布确认 1 次。

## C08 暂停、漏练、久未返回

动机：返回的门槛应由系统降低，过去没有完成的事项不成为操作债务。

信息顺序：当前真实状态 → 可保留 / 可恢复什么 → 今天和未来可以怎样继续 → 需要时查看过去。漏练、暂停和周期结束分别处理。

用户决定：恢复、重新安排、自由训练或换内容。App 执行：只接续合法事项，恢复输入与进行中训练，保留历史。AI 推断：不需要，不猜测身体或情绪原因。用户确认：重要替换。系统报告：哪些未来安排改变、哪些历史保留。

UI / 动效：温和、直接地给出可行路径；不放红色失败海报、清零恐吓或追债文案。恢复只更新相关区域；不播放从零重新开始的假进度。

验收：暂停当日正在进行会话可完成；恢复不改过去；过期提示重新安排；服务结束只读；跨设备冲突不静默覆盖。S01/S04/S08；预算：合法恢复 1 次主要操作，过期需重新选择时明确原因。

## 统一行为合同

- 返回保留来处、滚动、当前输入与对象；深链和登录回跳同样处理。
- 默认项来自已知偏好、明确上次记录和当前对象，不暗中推断健康适用性。
- 保存、发布、采用、公开、关系确认是不同动作；UI 不能共用一句成功将其混淆。
- 普通保存少确认；授权、替换、发布、采用给出影响与取消。确认按钮用具体动词。
- 无效字段靠近输入说明，原值保留；不得把错误全部变成弹窗。
- 所有核心控件可操作。未实现的非核心能力直接不放入口，不使用“敬请期待”假按钮。
