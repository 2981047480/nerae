# 指定执行者开发文稿

## 1. 身份与授权

用户明确要求：把逐项设计意图文稿交给 **DeepSeek Harness 内 OpenCode 订阅的 DeepSeek V4.1 Flash** 实现，主代理负责验收；高级质感优先、美观其次，动画与之配套，设计推理不进入产品。

执行环境须为 DeepSeek Harness，provider `opencode-go`，model `deepseek-v4.1-flash`；当前 profile / UI 已核实。不要调用 Codex 子代理或其他模型，不自动更换 provider / 型号，不建设新 Router。若订阅或模型调用失败，记录真实错误并停止该路径，不冒称相同模型执行。

本轮是明确的新授权，覆盖此前 D18“先不生成 UI”的阶段性暂停。业务边界、未满18岁不服务、不收款、健康授权与业务发布条件仍有效。

## 2. 必须按顺序读取

1. 当前工作树 AGENTS、RETRO、CURRENT_STATE，理解最新授权与真源。
2. 本文件及 00_CONTEXT_AND_SCOPE：写入范围、接受与责任。
3. 01_INTENT_TO_EXPERIENCE：G / N / L 动机与决定。
4. 02_SCENARIOS_AND_INTERACTIONS：C01–C08 和责任 / 恢复 / 动作预算。
5. 03_VISUAL_AND_MOTION：B / V 和 M01–M12。
6. 04_TRADEOFFS_AND_VALIDATION：T / H / Q，不能伪造研究结论。
7. 05_UI_BUILD_SPEC：S01–S16、状态、数据、文案和工程形态。
8. 07_ACCEPTANCE：主代理实际检查的方法与阻塞缺陷。

这些文稿不要求重新发明产品，不允许只读风格词便直接开写。PRD / APP_FLOW 按上文引用的问题查阅；不要全量读取市场材料、旧架构图或已删除旧稿。

## 3. 文件所有权与边界

实际 workspace / Git 基线 / 分支 / 会话句柄在 STATUS 和派发消息登记，以实际返回值为准，不能在此填假路径。

执行者仅写隔离工作树内的 `design/prototype/**` 和 `docs/evidence/D01/round-03/worker/**`。可读取冻结的设计文稿与必要产品文档。不得改 AGENTS、设计文稿、任务源、API/ER、scripts/plan.py、正式 apps/*、用户配置或其他项目。不得为通过检查而改接受条件。

局部依赖仅放 prototype 自己的 package / 锁文件；不改根锁、全局模型配置或个人账号，不安装插件 / 浏览器，不开启公开监听或部署。服务只绑定127.0.0.1，端口由主代理派发。不能读取密钥、复制现有认证或输出 token。

## 4. 实施顺序

### 第一批：四种代表情境

建立真实 Vue3 / TS 局部工程、共享视觉与必要状态，先实现今天、探索、训练执行、教练完整审阅（S01 / S02 / S04 / S15），包括进入、返回、记录一组、查看完整内容与变化的实际衔接。建立本地素材与 ASSETS.md。

只把自己完成且可运行的内容报告为完成。第一批报告后停止扩展，等待主代理按渲染和动效检查具体返工 / 接受；不能自行把源码自评当成视觉通过。为等待验收保留服务与稳定任务会话。

### 第二批：全量活动与状态

第一批接受后，沿同一系统扩展 S03 / S05–S14 / S16 与余下状态，补齐 F01–F07。已有共享组件和 token 由一个 owner 串行保持一致，禁止每屏自行发明新皮肤。

发布 / 采用 / 授权 / 替换的动作分开；数据总数、进度、改动和消息 ID 一致；真实本地持久化、计时与恢复。非核心未实现入口不放；核心路径不使用 no-op、“敬请期待”或损坏素材。

### 第三批：根据验收单修复

主代理以文件、视口、截图、复现与期待结果给出缺陷。每个缺陷登记原因、改动与验证，修复后重测受影响路径与共享接缝。不能以扩大范围或重写成另一种风格回避问题。

## 5. 必须随代码提供

- README：真实启动 / 构建 / 类型检查命令、局部依赖、预览边界。
- ASSETS.md：每个实际素材的来源 / 许可 / 本地路径 / 用途，不拿任意人物暗示真实背书。
- 状态和数据来源说明：稳定事件 ID、同一组数来源、角色隔离、版本与预览重置取消机制。
- 实际构建和适量状态 / 交互检查结果；不伪造浏览器、真机、专业审查和真实服务器结果。
- 55 项的实现落点建议与未解决项；最终接受由主代理更新覆盖状态。

## 6. 进度与返回报告

每个批次在 `docs/evidence/D01/round-03/worker/` 写 progress.md，记录最后完成内容、下一步、当前真实活跃句柄 / 会话、文件和错误。长任务按里程碑持续写入，不能仅存在聊天上下文。

每批 report.md / report.json 包含：

- status：success / partial / failed / blocked；attempted_scope；remaining_scope。
- runtime、provider、model、reasoning；由主代理从运行状态交叉核实，不仅靠自报。
- workspace、base_revision、branch、实际提交或文件清单。
- 实际命令、退出码、日志 / 构建 / 测试路径；启动服务 PID / 端口；未验证项。
- 素材、状态、动画、内容审查与已知问题；需要主代理决定的具体事项。

第一次错误区分输入 / 环境 / 范围 / 实现，给具体下一步；同类第二次重评；第三次停止该路径，不循环重试。观察超时不表示任务结束，不重复新建同一任务。没有失败信息不能把状态美化成成功。

## 7. 产品文案红线

产品内不显示本文件、设计矩阵、M/S/G 等编号、布局原因、品牌理论、实现架构、内部接受或思考过程。只显示用户当下的内容与操作。不能用“让你有掌控感”“高级优先”“减少认知负担”“四种节奏”等文稿句子填满页面。

保留真实的用户相关说明：来源、适用条件、AI 草稿、估算、保存 / 待同步 / 失败、影响摘要与必要限制。全局预览身份置于独立的预览控制，不混进产品主要任务。
