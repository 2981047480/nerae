# Nerae UI 实施规格

本稿将 01–04 的设计决定收敛成可以实现的目标。不要把本文的动机、验收、架构和风格解释渲染到产品。业务依据仍为 PRD / APP_FLOW；冲突先报告，不静默选一份。

## A. 交付形态与实现边界

交付完整、可操作的 Vue3 / TypeScript UI 样机，置于独立的 `design/prototype/`，浏览器可预览，组件与状态结构便于后续移植正式 uni-app 客户端。它不是替换既定 uni-app + Go 架构，也不把浏览器交互当作微信真机 / 真实业务联调。正式 apps/client、Go、OpenAPI、数据库与生产依赖均不改。

本轮覆盖下面 16 个界面族及其状态，贯穿八种情境与 F01–F07。不是只有五屏换皮。账号后台、支付、媒体社区、直播、医疗建议和 P1 自动周报不实现，也不放无动作入口。

只使用清楚标注的本地样例数据与预览状态，固定数据可复现、总数可追溯，不随机造指标。保存、编辑、筛选、记录、返回、确认、重试和计时都须真实操作本地状态。AI 与网络场景是可切换的设计状态，不调用真实供应商或发送消息。UI 验收不能写成真实权限和服务器测试通过。

## B. 稳定的活动结构

学员稳定导航：今天 / 发现 / 记录 / 消息；我的计划、饮食和个人偏好由相关任务进入，不能另铺一排系统菜单。教练稳定导航：待办 / 学员 / 消息 / 服务。切换角色只在外部预览控制中进行，不把客户端切换包装成权限提升。

发现内部承接训练内容、饮食内容和教练；切换保留偏好。详情返回原列表位置。训练中隐藏与执行无关的导航干扰，始终有可理解的退出并保留进度路径。

预览控制必须独立于产品任务：右上角小型“预览”入口打开角色 / 情境 / 重置控制，默认关闭，不占主内容一栏、不画手机外框。全局仅一处说明“本地交互预览 · 人物与内容为样例”，不能每个卡片都重复演示免责声明。设计解释不出现在该控制中。

## C. 16 个界面族

### S01 今天

关联 C02/C08、L01/L02/L05、G02/G07。

构图：品牌与日期轻量定位；主体是一份具体训练与可继续的位置，图像、训练主题、时长和主操作形成完整主面；下方的动作概要、关联反馈、饮食自评或我的计划按任务相关性排列。周日期为次要背景脉络，不做占半屏的日历，不用空白欢迎语压主任务。

主要行为：继续同一会话；没有开始则进入当前安排；查看具体计划；打开反馈；进入我的计划与饮食自评。状态：正常、进行中、已完成、未安排、休息、暂停、周期结束、离线内容不可用。每种有唯一清楚默认下一步和可找的其他选择。

首屏文案示例只限事实：“今天 · 10月24日”“上肢力量”“第 4 组，接着练”“约 32 分钟 · 4 个动作”。不写“通过一个主任务让你少思考”。

### S02 发现计划 / 饮食内容

关联 C01、G01/G02、V02/V06。

构图：简洁主题与少量条件，随后是有完整内容摘要的摄影序列；主推内容可以更有张力，次级内容平静可比较，不把每一项套相同巨大白卡。手机允许纵向阅读，横向序列必须有明确可达内容且不造成页面横向溢出。

主要行为：切换训练 / 饮食、选择目标 / 器械 / 时间、搜索、撤销条件、收藏、看详情。来源和条件真实可辨；未登录可浏览。状态：加载、正常、无结果、失败重试、内容下架。空结果有放宽条件，不造占位列表。

### S03 计划详情与开始

关联 C01、G02/G06/G07、M02。

构图：所选封面接续进入，主题与适用条件完整；周期 / 频次 / 时间 / 器械成组；训练日和完整动作内容可展开；来源与不适用提示位于决定前。底部清楚的“开始这次训练”，收藏与分享次级。

行为：看不同训练日，展开动作；必要时成年确认；默认安排摘要；已有安排说明未来替换影响后确认；取消回到原内容。开始同一请求不重复创建。下架版本禁止新开始。

不能只做照片、三枚标签和一个开始按钮。不能要求先去我的计划“另存”再找安排。“开始并保存到我的计划”可作为确认摘要中的具体动作。

### S04 训练执行 / 休息 / 完成

关联 C03、G07、N02、M03/M04/M05。

构图：进入深蓝灰专注空间；顶部退出 / 主题与总体位置，当前动作和组次清楚；少量动作图像或说明；当前数值与单位、上次参考、确认操作；本次记录平面展示，次级动作说明可按需展开。不要复制今天页布局。

行为：重量与次数 / 时长可编辑，增加 / 减少操作与直接输入都有明确单位；上次预填有日期。完成当前组后真实持久化，反馈并接续下一组；可进入真实计时的休息，跳过休息；退出 / 重开恢复；确认事实才计组。

状态：无历史、正常、记录中、已记录待同步、同步失败、同组冲突、全部完成。自重、单侧、秒和 kg 不混用。完成给出本次确认事实与一个回今天动作，不把训练完成改成休息日。

### S05 记录与个人积累

关联 C04、B04、M09。

构图：有意义的时间范围与个人记录，不是虚构 KPI 大屏。一份主要趋势必须对应明确数据、单位与时间，附可读数据明细；最近训练能回到组记录与点评。单条、空和信息不足均有适当表达。

行为：切换范围 / 动作、查看某次训练、读取关联反馈。统计来自确认记录和既定日期口径；延迟完成不伪装按时。禁止将训练量当成身体结果，将饮食自评当成真实摄入。

### S06 发现教练

关联 C05、G03、N01。

构图：人物身份、擅长、服务方式、响应约定与价格语境可比较；图像有来源，内容保持克制。没有精确评价样本时展示“暂无足够评价”，不造 4.9 分和学员数。

行为：筛选目标 / 价格 / 服务方式、查看详情、恢复筛选；城市仅对实际线下履约需要展示。无竞价排名、自动指派与倒计时促销。

### S07 教练详情与服务包

关联 C05、G03/G06。

构图：人物与服务身份；具体能提供什么、适合什么目标、沟通和响应约定；可核对的交付样例；服务包价格与范围相邻；预约咨询固定为可触达的主要行动。

行为：比较服务包、查看样例、带入包进入咨询。详情返回列表原位置。不能把示例人物包装成真实认证或实际效果背书。

### S08 消息列表 / 会话 / 咨询

关联 C05/C06、F04/F05、M08。

构图：列表与当前会话有自然连续，人物 / 服务上下文轻量；普通消息流与可打开的训练 / 计划引用；输入框稳定。桌面可并排列表与会话，手机自然进入与返回。

行为：发送文字、保留未提交文本、同 ID 重试、查看引用、查看服务说明。关系不需要先有计划；普通交流不强制健康授权。咨询包自动带入。未核定联系渠道显示不可用并保留咨询，不出现个人微信、支付或二维码。

状态：空、正常、发送中、失败、未读、只读、撤权占位、关系待确认。确认服务与健康授权分开；健康原文撤权后不能留在可见 DOM / title / 预览摘要中。

### S09 收到计划与采用新版

关联 C06、G04/G07、T04。

构图：谁交付、现用与新版本关系、完整内容与具体变化、影响摘要。主操作“采用这份安排”，其他选择包括暂时保留现有安排和回复教练。

行为：看完整内容、比较变化、明确采用；采用改变未来安排，不重写历史。状态：新版本、已采用、过期、冲突、无权限。取消 / 暂不采用时保持原安排。

### S10 我的计划 / 编辑 / 发布审阅

关联 C01/C04、G02、F07。

构图：自己的内容、在用 / 草稿 / 待审核等可理解状态；编辑围绕训练日和动作，不暴露数据库表。复用已有内容，不从重复资料表开始。

行为：打开自己的计划、调整动作组数 / 名称 / 备注、保存与回读；分享 / 发布进入内容和可见范围审阅，说明将公开什么；确认当前内容后提交到待审核，不能直接假装公开成功。改内容使之前确认失效。

状态：空库、正常、保存中、失败保留、版本冲突、缺必要项、待审核、下架。公开内容不能包含私人的健康备注。分享预览只生成当前样机内的可访问预览，不宣称已对外发布。

### S11 AI 解读与已有模板调整

关联 G05、C06、F06。

构图：当前对象与用户意图，已有内容与候选改动，来源与必要限制，明确确认行动。保持阅读 / 比较的质感，不制作通用机器人聊天首页。

行为：从具体模板进入，输入短意图，查看候选，补必要项，应用同一建议一次。教练交付计划只能转请教练，不能直接自助改。新内容不自动改变当前安排，另有明确启用影响。

状态：ready、needs_input、safety_block、技术失败、额度不足、版本过期、重复确认。预览使用可切换固定候选，不调用真实模型，也不报告真实 AI 质量通过。

### S12 饮食原则 / 计划详情 / 自评

关联 G02、C04、F07。

构图：来源与非医疗内容范围；原则 / 档位示例和可读内容；当天自评只表达是否按计划，补充说明可选。不要用不透明热量环占主位。

行为：看内容，选择“按计划 / 部分按计划 / 未按计划”，保存，重开回读；明确观察 / 估算与自评分开。没有实际食物、份量和确认就显示信息不足，不造宏量摄入。

状态：未记录、已自评、补充观察、信息不足、保存失败、内容风险提示、撤权。此样机不提供个人热量或疾病饮食处方。

### S13 教练待办

关联 C07、G04/G05、M11。

构图：教练身份与当日工作位置，继续未完成的具体工作，按原因排序的待办与最近事实；计数严格来自样例集合。无待办时给可以查看的已交付内容，而非假指标。

行为：接续草稿、查看学员证据、进入回复、标记普通事项已处理并可恢复；健康未授权只说明不可见。选中学员后上下文稳定，不要求再次选择同一个人。

### S14 学员列表 / 详情与证据

关联 C07、L03/L05。

构图：列表清楚找到人；详情显示有效服务、当前计划、可见的最近记录、反馈和未完成工作。信息密度允许专业判断，但不是把全部信息放在五层折叠内。

行为：看不同记录、回复、继续草稿、查看具体授权范围；返回列表位置保留。状态：正常、空记录、未授权、关系结束、数据过期。不可见不展示假 0 或旧缓存健康正文。

### S15 教练完整计划编辑 / 审阅 / 发布

关联 C07、G05/G07、M07。

构图：学员和服务上下文稳定；完整训练日 / 动作 / 组次内容可编辑；审阅模式同时看到实际方案与改动，版本和影响在确认前清楚。禁止用三条摘要替代编辑器。

行为：编辑必要字段、保存 / 重新进入回读、AI 草稿状态、缺项定位、冲突保留差异、手动继续普通内容、明确发布给该学员。发布后学员现用版本不变，直到学员采用。

状态：正常、缺项、安全阻断、技术失败、未保存、保存失败、版本冲突、发布中、已交付。无改动重复保存不制造一堆无意义版本；实际内容变化保存产生新草稿版。

### S16 教练服务内容与自主定价

关联 G03/G06、C05/C07。

构图：服务内容、适用目标、响应约定、价格 / 周期和当前可见状态成组，不像商品 SKU 后台。普通字段可直接理解。

行为：编辑与保存自己的服务说明和价格，回读一致；预览学员将看到什么；价格修改不改已确认关系的原约定。不实现收款、分账或自动续费。

## D. 数据与状态基线

固定预览日期为 2026-10-24（周六），当前周为 10月19日–25日。训练安排可用二 / 四 / 六，过去和未来依据相同日期规则。不要把 24 日写为周五或将三个自然日当成两个计划日。

样例人物为林澈（学员）、顾言（教练）、周岚与安然（其他样例学员）。这些不代表真实用户、认证、健康状况或服务成绩。角色数据与草稿隔离，预览切换不构成真实授权。

当前训练四个动作与组数为 4 / 3 / 3 / 2，共 12 组。稳定组 ID，由同一数组生成总数、进度、列表和完成摘要；初始可设第一动作已确认 3 组。重量 / 次数 / 单侧 / 时长明确，教练草稿与学员现用内容独立。现用版本6、待交付草稿7是可以复现的示例，不在保存 / 发布时无理由改写另一端。

所有图表、队列数、未读数、变化数从对应样例事实计算。禁止添加“25位学员、97%完成率、连续128天”等没有集合来源的数字。资料不足时保留未知，不填 0。

本地状态至少包含 currentActor、preferences、selection/schedule、sessions/sets、drafts、published/selected versions、messages、dietSelfReports 和 reviewScenario。用明确事件处理，视图只读取，不能每个页面自己维护一份相同总数。异步动作与预览重置使用任务代次或等价取消机制，旧操作不能写进新场景。

## E. 文件与工程建议

局部项目包含 package.json、锁文件、src/components、src/views、src/state、src/data、src/styles、public/assets、tests 与 README。Vue3 / TS 组件边界围绕稳定动作和内容，不把全部塞进一个模板。依赖少而成熟，版本从真实安装锁定，不能凭记忆写“兼容”。

使用语义控件和稳定可访问名称。底部操作、弹层、焦点和键盘行为真实实现。计时和动画句柄清理，事件防重，刷新恢复。提供实际可运行的 dev / build / typecheck 与适量有意义的状态 / 交互检查。

素材列表、来源 / 许可、本地文件路径写入 ASSETS.md。所有图片正确加载，字体有可读 fallback。不能在运行时依赖随机图片 API。照片用于内容与人物语境，不能暗示实际 endorsement。

## F. 文案与内部说明隔离

可见产品文字只来自用户任务相关的标题、事实、选项、字段、状态、错误和服务说明。设计文稿和任务文件不得作为文案数据导入。开发期不得把“高级质感”“核心体验”“降低认知负担”“为什么这样设计”“状态机”“组件规范”“Vue/Go/工作树”“验收通过”等写入产品正文。

允许的例子：“今天练什么”“接着第4组”“上次：12.5 kg × 10次”“已记录，待同步”“这次改了3处”“发布给林澈”“暂不采用”“健康内容不可见”。这些是用户当前需要的信息，不是设计理由。

逐段人工检查不能被简单禁词扫描替代。涉及真实内容的理由（例如计划适用条件、服务范围、AI 输出来源）应保留，不能为清除设计解释而删掉用户的判断依据。

## G. 完成条件

全部情境可操作、55 项有明确落点，素材与内容完整，高级感 / 美观 / 动效各自接受；320–1440 宽、长中文、空 / 失败 / 边界 / 重复与减少动态效果有证据。仅通过构建或模型自评不算完成。执行者报告实际命令、退出码、源文件和未解决项，主代理独立看渲染与过程后决定是否接受。
