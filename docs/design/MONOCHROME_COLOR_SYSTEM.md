# Nerae 白、灰、黑色彩系统

状态：2026-11-14 用户确认将白底灰阶方向设为**项目硬性要求**。所有自有界面设计与实现均须遵守并接受验证；各页面落地、具体色值、组件状态和三端视觉仍需设计和验证。本文是 `docs/UI_SPEC.md` 的色彩细则，不替代 PRD、APP_FLOW、记录行为或平台合同。

## 1. 已确认的方向和范围

- 必须以[用户确认的训练记录视觉基准](recording-review/assets/approved-monochrome-baseline-20261114.png)为色彩方向：自有界面的默认浅色页面使用白底，以白、灰、黑组织界面，主要文字及操作用深色，装饰性组卡和组件边框轻且浅。不得擅自用蓝、紫、褐或其他色调替代页面底色或主操作配色；不以旧 R05 橙色样机为新页面基线。
- 必须将该方向应用于学员端、教练端、微信小程序、iOS、Android 和运营后台的自有界面；各页面的构图、内容与功能仍按各自任务设计，**不意味着所有页面视觉已获确认或已实现**。平台系统自带控件和真实内容素材按其实际要求处理，不擅自重绘系统界面或伪造内容。
- 记录页标题偏中文衬线、重量次数偏圆润现代数字是此前选择的视觉方向；正文及实际跨端字体映射、授权和可读性仍需验证。不把生成图片中文字当作可直接交付的字体。
- 首页「最近记录」中动作图与名称之间的竖线必须去掉；用户对[去线后重新调整图文和数值对齐的方向](recording-review/assets/monochrome-home-balanced-20261114.png)表示可以。该认可限于此区域的设计方向，不代表首页其他构图、示例数据或三端实现已验收，也不推导所有页面都必须去除竖线。
- 颜色作用于产品界面；真实教练、食物、计划内容及用户上传图片的彩色/灰度处理需按内容真实性、版权及后续设计确定，不把样稿中灰色人体当成已获授权的动态图素材。示例数据不是实际用户训练数据。

## 2. 色彩角色与候选值

用户确认的是视觉方向与基准图片，并未逐个确认十六进制值。以下是根据基准提出的**工程候选值**，不是从生成图精确读取的定稿；实际落地后须结合三端截图、对比度和用户反馈调整。各组件引用语义角色，不在每个页面各自猜色。

| 语义角色 | 候选值 | 主要用途 |
|---|---|---|
| 页面 / 内容底 | `#FFFFFF` | 页面、白底卡片、半屏主体 |
| 弱层次表面 | `#F6F6F6` | 次级标签、输入底、少量信息区；不是大面积给页面染色 |
| 按下的浅表面 | `#EEEEEE` | 浅色控件按下时的瞬时反馈 |
| 主要文字 / 图标 | `#1A1A1A` | 标题、重量次数、重要说明 |
| 次级文字 | `#626262` | 单位、辅助信息、说明；不能把必要信息压到不可读 |
| 主操作 / 已选底 | `#1A1A1A` | 一个页面中优先的按钮、分段控件已选项 |
| 主操作文字 | `#FFFFFF` | 深色主操作上的文字及图标 |
| 主操作按下 | `#333333` | 深色主操作按下时的反馈 |
| 装饰性边框 / 分隔 | `#E1E1E1` | 用户选定的轻边框、非必要分组线 |
| 必要的控件或状态边界 | `#858585` 起测 | 只有必须依靠边界识别时才用，具体需与相邻背景测试；不能让浅装饰线单独承担识别 |
| 蒙层 | `rgba(0, 0, 0, 0.36)` 起测 | 半屏 / 对话框后方，必须能看清前景；深浅按设备实测 |

层次优先用内容结构、间距和字号建立，再使用轻边界。不要通过整屏灰底、多个大黑块、重复卡片或装饰数据制造“丰富”。图片内的黑色动作人物只是设计示意，不定义正式素材。

## 3. 组件及状态怎么用

| 场景 | 颜色与识别规则 |
|---|---|
| 页面与导航 | 白底；标题和当前导航项深色，非当前项用可读的中灰并保留名称/图标。不要让底部导航仅凭灰度表达当前项，须有形状、字重或选中语义配合。 |
| 主要 / 次要操作 | 主操作黑底白字；次要操作白底深字或清晰的文字加图标。轻装饰边框不是唯一可点击提示；一个屏幕的操作优先级要明确。 |
| 卡片和列表 | 白底、浅边界、黑字；用实际内容分组。可操作卡片需通过文案、图标、可见交互线索和无障碍语义表明可以操作，不仅靠 `#E1E1E1` 轮廓。具体编辑入口不能改变已确认的主路径或增加不必要点击。 |
| 选中 / 未选中 | 黑色勾选框配白勾、清晰文字或其他明确形状；不只靠淡灰底差异。多选数量和用户选中的组一致。 |
| 弹窗与输入 | 白色半屏配中性灰蒙层；当前刻度用清晰深色和形状/粗细，未选刻度保持可读。焦点使用可见深色轮廓或其他达到要求的指示，不能只依赖淡灰线。 |
| 已完成 / 待同步 / 失败 | 用文字、不同图标和操作描述区分，例如「待同步」加云朵符号；失败提供可理解的恢复入口。仅实际本机持久保存成功时才能显示「本机已保存」，仅获得有效服务端确认时才能显示已同步。灰阶不等于抹平状态。 |
| 破坏性操作 | 文案准确标明操作及后果，按既定规则提供确认、撤销或恢复；不要依赖颜色传达风险。是否需要突破灰阶使用特定警示色，应针对具体情境和平台约束另行评审，不自行作为全局默认。 |
| 禁用 / 加载 / 空态 | 用明确文案及系统可访问状态传达原因；有真实数据就展示真实内容，不能使用虚构成绩、教练反馈或占位数字。加载和空态不得伪装成失败或完成。 |
| 报表 / 图表 | 黑、深灰、中灰可作候选；曲线/柱形同时使用标签、线型、点形或纹理区分，并保留单位及数据来源。必要图形线条/图例要测相邻对比度；不把无记录当作 0。 |

## 4. 按页面任务应用

以下编号来自 [PRD 页面清单](../PRD.md#82-页面清单)，覆盖其 1–44；页面优先级和是否实现仍以 PRD、APP_FLOW 与任务图为准。页面外的登录恢复、动作库、冲突等补充状态也要继承同一系统。

| 页面及 PRD 编号 | 应用方法 |
|---|---|
| 登录、建档、数据授权 1/2/24；账号绑定、恢复、注销 | 白底表单，黑色主要提交，输入和同意范围清晰分组；授权对象、范围、撤回和错误以文字说明，不预选授权。 |
| 学员首页 3 | 训练、计划和已有教练反馈按真实状态分组；主任务最突出，有数据才展示数据。[首页示例](recording-review/assets/monochrome-home-balanced-20261114.png)的最近记录去线重排方向已获认可，整页和示例数据并未验收。 |
| 教练发现、咨询及关系 4–9/23 | 白底列表和详情；头像与真实服务交付、价格及版本清楚对应，灰阶标签表达分类；渠道未核定时不得画成已可联系。 |
| 计划广场、详情、创建、分享、我的计划及发布 10–15/43 | 用浅边界区分内容和版本，黑色突出使用/保存/发布等当前主操作；训练计划目标不能被画成实际记录。 |
| 训练记录、完成、历史 16–18；动作库 | 两种记录共用灰阶；[动作选择](recording-review/assets/monochrome-exercise-picker-20261114.png)、[组录入半屏](recording-review/assets/monochrome-set-sheet-20261114.png)、[完成页](recording-review/assets/monochrome-completed-20261114.png)为应用候选；数据和明细在前、动作累计含单位。空组、缺项、计划沿用等以最新用户决定为准，旧图板不是行为真源。 |
| 身体数据 19 | 实际数值、日期和单位优先；趋势采用可区分的线型和标记；授权与是否写入体重曲线按用户选择。 |
| AI 对话、教练 AI 计划生成 20/29 | 用灰阶和明确的来源标签区分用户、AI 建议和已确认内容；生成失败可恢复，建议不冒充已采用。 |
| 打卡、饮食 21/44 | 保留真实的图文与记录状态；表单以白底、浅分组及清楚的主要提交承载，未知数据不显示为 0。 |
| 学员评价 22 | 评分、输入内容及提交状态明确；评分类状态用文字和形状可辨，不单靠颜色深浅。 |
| 教练工作台、学员、计划、点评及服务管理 25–28/30/32–36 | 使用相同文字、线条与操作角色；高密度待办和真实服务资料靠分组、标签和排序辨别，不能照搬学员首页的巨型卡片。 |
| 教练周报 31 | 以真实可追溯内容和单位为先；灰阶图表用直接标签、线型和符号辅助，不凭外观声明效果。 |
| 消息中心 37 及站内对话 | 已读/未读通过字重、标记与文字或可访问语义区分；失败、只读和无权限说明具体原因。 |
| 运营后台 38–42 | 继承语义色彩，不照搬移动端排版；表格、筛选、审核及危险操作保留足够的信息密度、键盘焦点与状态说明。 |

## 6. 调研依据与验证门槛

- 实际复看项目已保存的 Appllama [Airbnb 服务页面](round-05/references/401626263-oth_ub321.webp)：可观察白色页面、白灰分组及突出的主要操作；其彩色素材、价格和强调色不直接进入 Nerae。
- 实际复看主工作区保存的 Appllama [Strong 动作选择](</Users/zephyr/Documents/项目/nerae/docs/design/research/2026-10-27-appllama/references/464254577/oth_qse1t.webp>)与 [Hevy 动作列表](</Users/zephyr/Documents/项目/nerae/docs/design/research/2026-10-27-appllama/references/1458862350/oth_t7svp.webp>)：图、名称、次级说明和选择反馈有明确层级；仅参考信息组织，不照搬其强调色、动作素材、实时训练或计时功能。2026-11-14 新搜索返回了结果，但媒体图无法通过当前工具打开，不视为已观察到的视觉证据。
- [Apple Color](https://developer.apple.com/design/human-interface-guidelines/color)建议对颜色语义保持一致、兼顾不同对比环境，不能只用颜色表示关键信息；[W3C 文本对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)一般要求普通文字 4.5:1；[非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)要求识别控件、状态所必需的视觉线索通常达到 3:1；[颜色使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)要求不能仅用颜色传达信息。具体适用范围和例外按原标准判断，不能凭静态图宣布全部通过。
- 对上面的候选灰阶按 sRGB 相对亮度公式做算术验证：`#1A1A1A`/`#FFFFFF` 为 17.4043:1，`#626262`/`#FFFFFF` 为 6.0997:1，`#626262`/`#F6F6F6` 为 5.6442:1，白字/`#333333` 为 12.6347:1；`#E1E1E1`/`#FFFFFF` 仅 1.3077:1，故只作非必要装饰边框；`#858585`/`#FFFFFF` 为 3.6900:1，可作为必要边界的起测值。数值不能替代组件真实背景、抗锯齿、字体、触控及实际设备测试。
- U01 单 owner 后续将候选角色映射到三端共享主题；现有 `design/prototype/src/state/palette.ts` 仍含旧色和旧外观存储，需设计迁移及回退并在同一版本校验，本文没有修改它。对应 U01–U08 的页面任务仍需实机、状态和截图证据。
- 最小验证：普通/空/加载/失败/选中/禁用/焦点/待同步及冲突状态，文字与必要图形对比、屏幕阅读器标签、字号放大、触控区域；分别在 iPhone、Android、小程序验证，含明亮与暗环境、系统高对比度和平台原生控件。暗色模式是否交付需另定，不能由本白底方案自动推断。
- 强制接受条件：所有涉及自有 UI 的新设计和改动，在对应任务的 Visual Gate / QA Gate 中逐项核对白底灰阶、主次层次、必要控件及状态可辨识性、对应平台截图和本文件适用项；不符合或缺相应证据时不得标记该 UI 范围或三端验收为通过。尚未修改的旧实现不能因已有代码而豁免，实际例外或新视觉方向须由用户明确改变要求后再纳入设计。
