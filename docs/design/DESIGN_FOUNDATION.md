# Nerae UI 设计推导

接续状态：用户已通过新的明确目标恢复逐项设计与 UI 实现，当前文稿和执行计划见 [round-03](round-03/README.md)。本文保留上一阶段的原始推导；下面“本轮不生成 UI / 继续暂缓”描述其形成时的阶段，不覆盖新目标。具体视觉仍须通过实际验收。

2026-10-24 · 当前阶段：回到产品与体验基础。本文记录设计判断、取舍与待验证假设，不是用户已批准的视觉方案，不包含界面、线框、组件样式或 token。

## 1. 上一轮为什么没有成立

上一轮先选风格，再把五个功能装进去。它回答了“页面能不能做出来”，没有充分回答“这种产品为什么应该这样表达，用户为什么会愿意使用”。按钮可点、没有溢出、状态齐全只能说明部分实现问题被处理，不能证明设计有吸引力。

更深的偏差是把 Nerae 缩成“训练接续 + 教练待办”。训练记录是日常核心环节，却不能代表整个产品。五屏可以检验设计，不能反过来定义产品基因。两轮成稿、早期参考、样式 token、生成简报、备份和截图已清理，见 [删除清单](UI_CLEANUP_20261024.json)。它们不再作为设计依据。

## 2. 从产品基因推导体验主张

依据 [PRD §0–3、§4、§5](../PRD.md) 与 [APP_FLOW F01–F07](../APP_FLOW.md)，继承以下事实，而不是某个模板的外观。

| 产品事实 | 用户需要 | 设计上的含义 |
|---|---|---|
| 首期围绕 18–28 岁增肌 / 减脂人群，兼有自助与接受教练指导的学员 | 新手能进入，有经验者不被当成初学者 | 年龄不能直接推出霓虹、游戏化或健身猛男图；熟悉程度更影响操作密度 |
| 免费计划必须独立提供价值 | 不请教练也能开始、记录、调整与分享 | 免费路径不能成为转化广告的前置漏斗，探索和训练都要成立 |
| 学员自行选教练，教练自主经营 | 看懂适配性、服务边界、证据和价格 | 专业感来自可判断的信息，认证和热门不能替代“是否适合我” |
| 线上指导、训练记录和反馈相连 | 训练被看见，指导有上下文 | 人的回应应关联实际训练与具体调整，装饰问候不能冒充陪伴 |
| AI 分层辅助，重要变更由人确认 | 少整理资料，同时保留判断与修改权 | AI 在解读、整理和起草的任务中出现；不因接入模型就把产品变成聊天框 |
| A 阶段不收款，陌生获客仍有外部条件 | 真实理解咨询、约定和服务状态 | 不能用商城式成功反馈伪装已成交或已建立服务关系 |
| 计划、安排、实际记录分离，暂停和撤权有规则 | 换计划、回来训练、结束服务后仍理解历史 | 连续性和掌控感贯穿全程，外观更新不能掩盖真实状态 |

**本轮推导的体验主张：让人有把握地开始训练，逐渐形成自己的训练节奏，需要时获得可信的人类指导。**

这是完整产品的体验方向，不改变 P0-A / P0-B 的交付顺序。如果首发只完成 P0-A，就只能承诺已实现的服务与记录能力，不能把尚未完成的免费广场画成可用产品。

## 3. “用户喜欢”需要拆开研究

至少区分第一次愿不愿意接近、操作时是否顺手、使用一段时间后是否仍愿意回来。新奇外观、低点击数和长期认同不能互相代替。

Hassenzahl 与 Roto 区分实用质量和与身份、刺激、归属有关的体验质量；能完成任务与喜欢一个产品需要分别研究。[Being and doing，2007，页 10–12](https://nissenbaum.tech.cornell.edu/papers/reflection.pdf)

应用到 Nerae，我的判断是：训练中的低干扰、选择陌生教练时的信任、训练后的成长感都要设计。只追求简洁，可能丢掉运动感与人的存在；只做漂亮封面，可能增加真正训练时的负担。不能用一个维度的高分抵消另一个维度。

Ryan 与 Deci 的研究将自主、胜任和关系需要作为理解动机的重要基础。[Self-Determination Theory，2000](https://selfdeterminationtheory.org/SDT/documents/2000_RyanDeci_SDT.pdf) 对 Nerae 的下列应用是设计假设，尚无本产品用户试验支持：

- **自主**：可以自己练，也可以选择教练；能暂停、退出、改主意；自动化不偷偷替换安排。
- **胜任**：逐渐知道怎么练、怎样理解下一步；进步有记录支撑，不只靠夸赞与积分。
- **关系**：接受指导的学员能知道教练具体看了什么、回应什么；自助用户不会因没请教练而被表达成缺少照顾。

因此，希望形成的体验是“我能开始、我有掌控、我的投入有积累、需要时有人认真回应”。这比“年轻、极简、高级”更能指导判断，仍不能直接决定用户喜欢什么颜色或形状。

## 4. 从底层到表层的九个层级

推导顺序是：价值与情境 → 用户判断 → 活动结构 → 信息优先级 → 操作与反馈 → 表达与感受。上层可以暴露底层矛盾，但不能靠配色掩盖它。

| 层级 | 必须回答的问题 | Nerae 的判断 | 不成立的信号 |
|---|---|---|---|
| 价值与身份 | 来完成什么，希望成为怎样的自己？ | 从想练走向能行动、能理解、能持续；教练保留专业判断与服务身份 | 换个产品名仍完全成立，只有工具功能，没有产品态度 |
| 使用情境 | 在哪里，身体和注意力怎样？ | 选计划可比较，训练中注意力短且可能单手，审阅需要证据，回归需要低压力 | 所有任务同样密度、同样节奏，靠折叠和跳页补救 |
| 心理与信任 | 最担心什么，需要什么把握？ | 初学者怕不适合，选教练怕承诺不清，训练者怕丢记录，教练怕错发；分别给依据 | 到处写专业、智能、安全，却没有可判断的信息 |
| 体验结构 | 需求如何自然走向结果？ | 合适内容 → 开始 → 执行 → 理解反馈 → 决定继续 / 调整；真人指导衔接这条链 | 按后端资源划菜单，用户自己拼接计划、安排、记录和消息 |
| 信息层级 | 此刻必须知道什么，什么可以稍后知道？ | 先给当前问题的答案，再给判断证据，之后是替代选择与历史 | 所有内容同样大；删内容留下空白；关键限制被简洁隐藏 |
| 交互责任 | 人决定什么，系统做什么？ | 用户判断适配与重要变更；App 预填、恢复、保存与衔接；AI 给有依据的草稿 | 重复填资料、搬数据、找状态；或为了少一步而越过确认 |
| 内容表达 | 信息怎样被理解，用户被怎样对待？ | 使用能行动的语言，分清事实 / 估算 / 建议 / 未知，尊重休息与失败 | 泛泛鼓励抢主位，长免责声明替代清楚边界，漏练被写成道德失败 |
| 视觉语法 | 哪些关系能表达前七层？ | 字重、尺寸、间距、对比、图像和容器共同建立主次；不同任务共享语言而非模板 | 只换颜色，每块都套同一种卡片，高级只靠黑白、细字或空白 |
| 时间与感官 | 如何感知状态，使用多次后留下什么？ | 保存、同步、完成有可辨反馈；返回接续；积累真实进步与具体回应 | 动效比操作显眼，假成功、假进度，回来像重新开机 |

Apple 的设计讲解也先讨论结构、导航和内容，再进入视觉设计。[Design foundations from idea to interface，WWDC25](https://developer.apple.com/videos/play/wwdc2025/359/) 这里只借鉴推理顺序，不将 iOS 组件、材质或布局直接搬到 uni-app 小程序。

内部的模板、私人副本、安排、版本和授权不必变成等量的导航概念。用户需要在对应决定前理解的是：使用什么、影响哪天、谁能看见、能否撤回、哪些历史保留。技术复杂度由 App 承接，重要后果仍需可见。

## 5. 同一品牌，需要不同的使用节奏

以下区分活动与注意力，不是页面方案或导航草图。

| 情境 | 用户主要问题 | 必须突出 | 应退后 | 目标感受 |
|---|---|---|---|---|
| 第一次找内容 | 有没有适合我现在条件的？ | 目标、经验、器械、时间、来源和内容预览 | 复杂配置、完整身体档案、内部分类 | 能选，也知道为什么选 |
| 回来继续 | 接着做哪一步？ | 当前安排和真实停留位置 | 推荐更新、营销、无关统计 | App 记得我 |
| 完成当前一组 | 怎样少分心地记录？ | 动作、数量与单位、上次参考、本组确认与保存状态 | 续约、长分析、装饰 | 身体在训练，界面配合我 |
| 练后看变化 | 投入形成了什么？ | 有时间范围与比较依据的记录和简短解释 | 单次数据推导的承诺、无依据排名 | 理解积累，不被夸大结论误导 |
| 选择教练 | 是否理解我的目标，服务是否值得？ | 适用范围、服务约定、样例、真实交付证据和价格语境 | 无依据最佳、自报成交数、体型权威 | 能判断，决定权在我 |
| 接受指导 | 他看了什么，我下一步怎么办？ | 被引用的上下文、具体反馈、需要本人决定的改动 | 无关联问候、全量资料和系统状态 | 有回应，知道怎样行动 |
| 教练处理学员 | 谁需要我判断，依据是什么？ | 原因、最近事实、服务上下文与未完成工作 | 总数仪表盘、重复检索与填表 | 注意力花在人与判断上 |
| 暂停后返回 | 还能从哪里继续？ | 可恢复的进度、当前状态和可执行选择 | 追债式提醒、自动补义务、羞耻比较 | 回来是可行的 |

**一致性落在语义、操作习惯和品牌性格上。** 探索需要适量丰富，执行需要减少干扰，判断需要完整证据。密度与节奏可以不同，系统对用户的态度应一致。一个明显的默认下一步，也不等于每种活动都只能有一个选择。

## 6. 产品基因如何转成视觉判断

此处确定评判关系，不决定任何配色、字体名称、圆角、图片或组件。

**专业来自可判断。** 信息完整、主次明确、单位与状态准确、服务边界直白、排版有秩序。低饱和颜色和细线不能担保专业，复杂证据也不能为了高级被藏掉。

**活力来自行动节奏。** 启动、执行、恢复和收束应有不同力度与反馈。图像若存在，要帮助理解真实训练与日常生活。运动感需后续探索，不预设猛男、竞技、游戏 HUD、荧光或几何图案才代表运动。

**陪伴来自真实回应。** 人的身份与具体反馈有恰当权重，AI 内容明确身份；没有回复就表达真实等待，不伪造“教练已关注”。视觉温度应支持真实关系。

**成长来自积累可理解。** 用户认得自己的历史、阶段和已作决定。数量与身体结果、自评与观察分开；没有依据就不画确定的成长曲线。认可投入，但不要求每次训练都突破。

**品牌来自持续的表达。** 后续需要在编排、图像、人像、图标、色彩和动态中找到跨情境成立的语言。不能从 Nerae 名字臆造品牌故事，也不照搬其他项目。Taste Skill 只帮助探索与检查表达，不能替代产品判断。

目前有理由追求“清楚、可信、有训练的活力、尊重人的节奏”；没有证据将全黑白、松绿暖灰、编辑部风格或任何固定皮肤宣布为答案。两轮整体被否定，也不能推出所有黑白或绿色 UI 都不受欢迎。

### 视觉层也要逐项推导

| 子系统 | 在 Nerae 中要表达什么 | 后续怎样判断，而非凭风格偏好决定 |
|---|---|---|
| 排版与字形 | 当前动作容易扫到，数量和单位不混淆，服务内容能认真阅读 | 检查中文长标题、数字与单位、文本放大和短暂扫视；不以细字或巨大标题代替层级 |
| 空间与布局 | 看、理解、操作的顺序符合身体动作；上下文彼此接近 | 在单手、键盘出现、内容变长和返回时检查路径；移动端从实际使用推导，不把桌面双栏缩小 |
| 分组与容器 | 哪些信息属于同一判断、同一对象或同一操作 | 容器需要解释关系；删去或加入边界后观察是否更好理解，不默认一条信息一张卡 |
| 色彩与明暗 | 品牌性格、交互优先级和必要状态各自可辨 | 分配注意力而非装饰面积；状态另有文字；明暗方案结合训练环境与可读性验证，不预选全黑或全白 |
| 形状与材质 | 可操作性、稳定感和亲近程度 | 看触达、辨认与情绪是否一致，再决定形状；不能由“年轻”直接推出大圆角，由“专业”直接推出直角 |
| 人像与训练图像 | 内容可理解，服务者可辨认，普通人能代入 | 使用有来历的素材与真实人物信息；检验是否帮助判断动作 / 适配 / 服务，避免用体型暗示权威或结果保证 |
| 图标与细节 | 快速识别熟悉操作，强化品牌一致性 | 同一动作稳定表达；关键动作配可理解的文字；不为每个名词制造一个符号 |
| 动效、触感与声音 | 动作的因果、确认与节奏可感知 | 反馈跟随真实状态，不抢训练注意力；减少动态效果后信息与结果等价，用户能控制打扰 |

这些系统要一起表达产品，而非各自追求漂亮。单个色块、字体或按钮的偏好，不能代替它们组合后的体验判断。

## 7. 先处理的矛盾

| 矛盾 | 建议的判断规则 |
|---|---|
| 免费价值与真人服务转化 | 先兑现当前任务；选择教练有合理入口和时机，不侵占每次训练，两条路径各自成立 |
| 内容探索与稳定训练 | 入口和操作习惯稳定，权重随情境变化，不频繁搬动主要入口 |
| 教练效率与审阅质量 | 自动收集、整理与恢复，保留证据；专业判断不设不合理速度目标 |
| 少输入与保留掌控 | 已知信息带入且可改；普通保存少确认；替换、授权、发布和 AI 应用说明影响后确认 |
| 激励与压力 | 反馈实际投入和积累，允许休息与回归；不以羞耻、焦虑、强制连续换使用率 |
| 简洁与吸引力 | 内容有作用、主次清晰、表达可识别；不以空白掩盖内容不足，不把装饰当丰富 |

## 8. 确定项与待验证假设

现在可确定：从真实活动建立体验结构；免费与真人指导路径都要成立；状态和证据真实；重要判断留给人；执行减少干扰；中断能接续；具体视觉不继承旧稿。这些不改变现有产品边界。

| 假设 | 提出依据 | 什么证据会促使重做 |
|---|---|---|
| 初次更需要辨认适合性，而非尽可能多内容 | PRD 新手与选计划任务 | 用户已有明确搜索目标，摘要反而妨碍找内容 |
| 连续性比每次推荐更新更影响重复使用 | APP_FLOW 恢复和固定日历规则 | 主要障碍实际是内容耗尽，而非接续困难 |
| 具体交付与响应语境比堆资历更帮助选教练 | 服务适配与信任问题 | 实际决策顺序不同，或样例无法帮助理解 |
| 尊重节奏与可理解积累适合持续关系 | 自主、成长、关系的体验目标 | 用户真实需要更明确的外部约束；仍应保留退出权和真实状态 |
| 同品牌的不同任务节奏优于统一模板 | 执行与专业审阅的注意力差异 | 切换时认不出仍在同一产品，说明共享语言不足 |

没有做本产品用户访谈或偏好试验。两次否定证明旧方案未获用户接受，不足以证明目标人群普遍喜欢某个新风格。

## 9. 恢复 UI 设计前需要的证据

本轮只有文档推导，没有招募、访谈、线框、图片或 UI 生成。后续先核对设计逻辑，不立即进入第三轮页面。

1. 分别了解自助学员、接受指导的学员和教练的近期真实行为：上次怎样开始、在哪里犹豫、切换哪些工具、为什么回来。不要只问喜欢什么风格。
2. 用具体任务核对对计划、安排、记录和指导的理解；检查需要记住什么、自己拼接什么，不把我们的术语当成用户已有知识。
3. 获准探索视觉后，用相同内容比较表达，先记录第一印象及原因，再做任务。愿意尝试、能完成、信任和持续使用分别评价；负责人的审美与目标用户证据分开。
4. 覆盖首次、再次训练、中断返回、收到具体反馈和失败。APP_FLOW 的动作预算仍是目标，不是假装实测的成绩。

后续每个决定都应能写成：**用户处境 → 所需判断 / 感受 → 信息和操作安排 → 视觉表达理由 → 检验方法。** 说不出中间逻辑的颜色、插画、容器或动效不直接制作。

用户明确恢复设计、体验主张与核心情境收敛后，才进入下一阶段。本文不自动触发生成；D01 / U01–U07 继续暂缓，未接受任何视觉、token 或组件。
