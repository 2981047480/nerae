## 2. 五项改进如何落地

| 改进 | 当前实现 | 后续实际执行证明 |
|---|---|---|
| 小任务 | task/integration≤3有效人日；工作包不进入ready，packet只列细化状态与子卡 | 真实小提交、局部验收、复核与必要再拆 |
| 早集成 | F01-I/F02-I；I-A01身份关系→I-A02训练交付→I-A03消息运营；I-B01发布分享→I-B02饮食建议 | 同一集成提交、真实HTTP/DB、覆盖直接依赖、共享路由串行收口 |
| 完成清单 | 七项completion；条件项不适用须理由；pass引用已登记证据 | 适用正反例、同提交path/hash/revision、真实review模式 |
| 工程自动化 | 独立工程标准EG01–EG08，明确F01/F02/集成卡负责接入 | 真实CI入口与失败注入；应用命令缺失不能假绿 |
| 陌生agent上手 | F02-01指定冷启动上下文试验，接受需真实计数与复跑记录 | 未参与方案的执行者、额外上下文请求/返工/边界/复跑证据 |

工程标准覆盖模块依赖、Go/配置/错误、事务/迁移/幂等、环境隔离、日志隐私、CI、后台与内容。归档手册有1904行，本轮提取适用规则与明确命令映射，没有把篇幅作为验收。

## 3. 首批怎么开始

2026-10-23 规划当时的 ready 仅为：

1. **F01-01**：由Lead本地建立Git基线、忽略缓存/密钥，验证并锁工具链。完成前不启动并行worktree。
2. **L01-01**：盘点真实材料与缺口。可接受一份准确缺口清单，不代表主体/类目/联系渠道或AI条款已核定。

F01后续为Go骨架与客户端/后台构建骨架、双工作区环境、CI/边界检查，再由F01-I干净检出验收。F02随后建立生成、错误边界、真实库幂等与F02-I集成。F02-01还需记录陌生执行者上手试验。

L01-02/03取得实际主体/平台/联系渠道与数据条款证据，再由L01-I复核配置。缺材料时保持未通过；公开获客仍需V02与运营/运维条件，L01通过不等于G3自动通过。

完整细拆工作包的effort_days是子卡人日之和，包含此前粗估未展开的集成/复核。它不是日历或agent耗时；外部等待另计，不能把拆卡数量当成提速证明。全部58个节点仍为planned，0 accepted。
