# Nerae 实施计划：从白底训练记录到三端可用

2026-11-14 · 开发基线：`codex/nerae-app-integration-20261031` 的 `a8cd57f` **加上** 11 月 14 日尚未提交的产品决定、色彩规范与两张已确认的参考图。主项目当前的 `main` 和会话所在的回执工作树都不是这份业务代码。先把本轮相关变更单独留成可重复检出的基线，保护其他未提交工作和被忽略的凭据；新工作树不能只从旧提交开工。

**目标是让你用自己的 iPhone、自己的邮箱，记完一次训练，在另一部真实设备接着看、接着改。** 首页、完成页和训练编辑器用同一套白底灰阶。iOS 是最先看效果的设备；Android 和微信同批开发，分别验收。签名试装只验证工程，不能把后台未通的壳、本机草稿或网页交作第一版。

## 2. 交付顺序：每一步你能看到什么

| 步骤 | 工作与依赖 | 交付给你判断的结果 / 继续条件 |
|---|---|---|
| ① 尽早验证能装、能看 | 在受版本控制的基线登记后，同时推进 K01-04 的保存规则、P02-02/03 的原生构建和服务环境只读复查。U01-01 达到任务前置后统一样式，接现有真实登录页；记录组卡先在正式客户端做一小段，首页沿用已确认的最近记录排版 | 第一批给同一构建的登录、记录组卡／半屏和首页最近记录的实际画面，注明哪些可操作、哪些尚未接数据。优先给 iPhone 截图和短录屏；若签名未通，先给标明来源的组件渲染与安装阻塞，不发网页当作 App。字重、密度、对齐和手势在此批一起审，问题先修，不铺到 44 页 |
| ② 打通能登录、能写回的最短路径 | K01 新合同 → F02 生成 → A04 服务端读写 → U02 页面。环境门槛通过后，在独立测试服务部署 API、邮件 worker、MySQL、Redis 和手机信任的 HTTPS；复用既有 QQ 发信与设备确认。先用本人自由训练贯通创建、写组、整次完成及读回 | iPhone 上手输真实邮件码；两种模式切换不丢组；完成后同页看明细、返回重进仍在。另一部设备获本人批准登录，读到同一条记录并改一组，iPhone 能读回。此时可展示实际进度，尚缺下述场景时不报首版完整 |
| ③ 补齐首版记录边界，再交可安装测试版 | 在同一记录上补齐两列动作库、自定义动作、自建／教练创建并发送的计划、组数与历史选择、双侧及自重／助力、修改／移除／恢复、草稿上云与冲突。账号、动作内容和教练授权用同一服务；优先测以前会丢数据的例子 | 一次验收安装、登录、两种记录、计划来源、断网重启和双设备往返。交付绑定构建号的 iPhone 安装及启动证据、手机上可重复的操作、明确的其他端缺项。iPhone 通过可单列；未获得第二部真实设备，不宣称跨设备验收通过 |
| ④ 三端同版及其余页面 | Android、小程序与步骤①～③并行适配同一合同/UI；补 APK 签名、微信真实登录、明确关联和两平台本机安全草稿。三端通过 I-A04 后按既有 M2 教练交付、M3 免费内容/饮食、M4 发布与试点分批扩面 | 同一服务版本下 App↔小程序双向修改，分别记录 iPhone App、Android App、iOS 微信、Android 微信的结果。缺账号/设备标「未验」；申请商店发布、付费开发者账号、公开获客与测试版分开 |

步骤是体验检查点，不是额外审批流程。每一批只集中看一套图／一次操作：**先看登录、组卡和最近记录，再看填写、保存及恢复**。复用的组件已通过本人核对后，其他页面按同一规则实施；只有改变已确认取舍、素材权益或交互明显不同时，再集中请用户判断。

## 3. 首批任务与依赖

下表为集成任务表中的卡。有效人日按**单卡工作量**估计，不含等账号、设备与审核的时间，不是完成日期。无需重做已通过的历史 K01-01 或 D02。开始前用 `scripts/plan.py ready`；active 的身份卡由原负责人续办，不因不在 ready 列表里搁置。

| 任务卡 | 前置 / 估工 | 负责人和可交付结果 |
|---|---|---|
| K01-04 记录规则与兼容清单 | K01-01、D02-I；0.5–1 | 产品/合同负责人用旧数据和已确认例子对表：列保留组、缺项、计划目标、重名分段、恢复、谁能读到什么；明确新旧版本如何共存。仅修订产品要求和差异表，先不抢共享接口写入 |
| K01-05 组、计量及完成合同 | K01-04、进行中的 K01-02；1.5–3 | 唯一接口负责人更新 APP_FLOW、OpenAPI、ER 和合同正反例；涵盖单位、空值、按侧记录、计划范围与动作累计。旧端读不了新语义时拒绝不安全写入或要求升级，不能悄悄删组 |
| K01-06 草稿、移除及冲突合同 | K01-05；1.5–3 | 同一负责人明确草稿版本、未同步删除、恢复快照、完成转草稿、权限和同键重试；新增数据项与原有接口未改动部分均可验证。K01-03 的注销合同在其后串行写；K01-I 汇合复核 |
| U01-01 灰阶样式与登录试点 | F01-03、D02-I、P02-01；1–2 | UI 负责人维护唯一语义色源，先用于原生 App 的现有入口及邮箱登录组件；输出状态截图、真实背景对比及旧外观升级/回退说明。试点开发可与签装并行，接受须 P02-02 实装；其他正式页面仍须满足原依赖，U01 整包仍需双端真机 |
| P02-02 / P02-03 安装链路 | P02-01；各 1–3 | iOS 用现有 DCloud AppID，核对 5.33、AppKey、Bundle ID 和免费 Apple 签名，移除示例资源，真机安装、冷启动；Android 同期对齐签名与 AppKey、产出 APK，缺设备时只报告做到了哪一步 |
| U02-04 首页最近记录 | U01-01、K01-04；1–2 | 页面负责人在现有入口接本人真实历史，落实图名去线及数值对齐，核对无记录、读取失败和切号。验收用真实录入的一条记录；不等待 44 页完成 |
| U02-03 首批界面核对 | U01-01、K01-04、U02-04；0.5–1 | 对集成的正式组件分别检查登录、首页最近记录、记录组卡／半屏，附构建号、状态及画面对照。若 U02-01 或已授权的数据尚未接入，先记录缺项，不造假数据或以效果图过卡 |

首批复核不承担开发：现有 U02-01 在它的写域内接组卡，U02-04 接真实历史读取，再由 U02-03 核对同一构建。签装或真实数据未就绪时先给阶段反馈，不关卡。K01-04 修订 PRD 与兼容清单，不并行修改 K01-02 持有的 OpenAPI/APP_FLOW。

随后按依赖细拆现有 A03/A04/U02 等工作包；**每项开始前**登记 ≤3 人日执行卡、写入范围、同版验收卡，超过就再分；下列是先后顺序，不是已获调度的任务：

1. **服务及回退。** F02 单一负责人生成 Go/TS 类型，验证生成无漂移；A04 在隔离 MySQL 追加迁移，旧记录能读，旧版写不抹掉新字段，备份恢复演练通过再迁移测试服务。禁止修改已执行的历史迁移；不能可靠回退时停写、保留备份。部署前复查共享服务器空间、独立库/用户/命名空间、代理管理入口隔离、HTTPS 续期和手机信任；先经本人授权的小范围测试，不动其他项目。
2. **从录入到结果。** U02-01 负责两种模式共享同一动作段/组键；与 A04/F02 串行接通创建→保存组→整次完成→历史读回。网页样机不接入此链。本人须通过 18+ 及按用途健康采集同意，教练关系和身体授权分开；退出/切号不能遗留可读取的旧账号内容。草稿与待发请求持久化，失败或回执不明保留输入、以同键核实，不产生第二组。跨设备同组冲突提供两份，远端整条删除可保留本机修改另存。
3. **计划和动作接入。** 先使自建计划及教练真实创建→发送→学员选择采用可走通，再接动作选择与历史。计划调的是目标组；逐组模式调本次实际组并可复制；训练后模式可选同动作段的第 1、3 组只改重量，也可新增指定组数。操作候选在首个可用半屏里演示，不能把选数变成必填表单。动作库条目不重名，训练里同名动作可分段交替；图上文下的双列、半屏刻度/键盘、缩略图边界同时核对。
4. **跨端与素材。** 小程序不把 App 邮箱入口或可读明文缓存冒充微信登录及受保护草稿；独立验证登录、关联、恢复。授权与准确性未核定的示意图不发为正式动作素材；先集成有使用权且经复核的一小组，离屏暂停、减少动态效果可读。如需缩小正式素材范围，单列缺口让用户判断，不默默降级。

## 4. 把灰阶推广到所有自有页面

先建可复用的文字、表面、线条、按钮和状态色；各端适配其原生控件，后台共用语义和数值。白灰黑是硬要求，具体十六进制仍是候选；旧样机存储的主题要检查，不能重新染色，也不清除用户记录。不要用全局滤镜改用户照片、食物或授权素材。灰阶表见[规范与 44 页对应表](design/MONOCHROME_COLOR_SYSTEM.md)，不另建第二套色板。

| 推广批次 | 代表页面与组件 | 何时放行 |
|---|---|---|
| 学员首批（1–3、16–18、24 及动作库） | 登录/授权、首页最近记录、动作导航、组卡、刻度半屏、双列选择、完成/离线。最近记录的图和名称靠近，数值列基线对齐；仅此处要求无竖线 | 上述两个体验检查点在真实设备核对后再推广。白底下用勾选、文字、图标或形状标清选中、禁用、失败、待同步 |
| 计划与教练交付（4–15、23、25–30、32–36、43；依各功能实际开放批次） | 私人计划优先；之后是教练工作台、咨询、服务、点评及广场。复用列表和表单规则，计划目标与实绩、草稿与交付分别标明 | 学员/教练权限、无关系和撤权状态可辨；陌生获客未获证据不开放 |
| 身体数据、报告、饮食、反馈、消息（19–22、31、37、44）及后台（38–42） | 图表用标签、单位及线型区分；消息用语义区分未读；后台保留桌面表格密度和键盘焦点 | 缺值与 0 分开；普通/空/错误和权限态可辨。周至年报告先保留可复算的逐组数据，实际出报告另按产品范围排期 |

每批验正常、空、加载、失败、选中、禁用、焦点，以及适用的离线/冲突，检查小屏、长中文、200% 文字、键盘、安全区、读屏、减少动态效果。普通文本以 [4.5:1](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 为门槛（大字等按适用例外）；辨认控件/状态所需的视觉线索以 [3:1](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) 为门槛；浅线只作装饰。桌面后台留真实浏览器截图；移动端分别留真机截图，手势另留录屏。真实内容或平台原生控件不因颜色不同被误判。

## 5. 交付测试：看到什么才算过

| 在实际构建上这样操作 | 期望看到的结果 |
|---|---|
| 本人从手机收邮件、手输验证码；第二部设备同账号登录 | 有效会话、本人明确批准新设备。错误码、过期码、被拒批准都进不去；仅 SMTP 接受或同进程两个会话不算 |
| 自由训练用两种模式分别填写，切换回当前动作；复制一组，保留一张空组，完成后再打开 | 两种模式始终是一份记录。保留的每张卡各计一次，包括空组；空项不是 0，不参与累计；移除的组不计。无计时、无逐组强制二次确认 |
| 普通负重同一动作填 12 kg × 12、14 kg × 10 和一组缺次数；另测两只哑铃各 12 kg × 10 | 完成页顶部显示动作导航及动作数/组数，先列组，再显示「已计算 284 kg，1 组未计入」；双哑铃示例单独累计 240 kg。自重／助力和单侧分别按既定口径测试 |
| 从自建或教练计划进入；计划有 8–12 次；只把第 1、3 组重量改为 45 kg | 计划目标不被改写；实际次数未知不虚构，批量不修改第 2 组或原次数；采用新版不覆盖已填数据。动作段移除或恢复保留原位置、组内容和累计 |
| 已登录断网，产生未完成草稿及离线完成记录，强退、重开、联网；两部真设备修改同一组 | 本机落盘才显示「待同步」，服务端确认后才显示「已同步」。草稿和完成记录均能往返；冲突可选两边、无重复写入；一端删整条不自动复活。真机重启、切号与回执丢失分别留证 |
| 教练查看草稿、只获记录授权、随后撤权；完成记录去掉最后一组 | 草稿不可见；仅记录授权可见记录重量结果，不返回体重/拆分；另获身体授权才显示拆分。最后一组移掉则整条回草稿，教练读不到；本人能恢复 |

**外部依赖与复估。** 用户已有免费 DCloud 账号和 AppID、个人 Apple ID、一部 iPhone；实际 AppKey 与签名要复测。免费 [Apple Personal Team](https://developer.apple.com/help/account/basics/about-your-developer-account) 用于本人设备测试，描述文件 7 天到期，交付时附重新签装步骤；[DCloud AppKey](https://nativesupport.dcloud.net.cn/AppDocs/usesdk/appkey.html) 需与该应用平台配置匹配。腾讯服务器之前的空间数据、IP 证书和域名条件是历史证据，不是今天的可部署结论；复查不通过就暂停该环境部署，继续本机集成。尚无微信小程序账号、Android 真机或已证实的第二部设备；预约独立测试设备/合法账号，不用两次登录一部手机替代跨设备验收。域名及凭据由本人在相应平台配置，不入版本库。短信、商店分发及陌生获客不阻塞邮箱内测，仍是其各自放行条件。

**何时重新估期：** 第一批结束，用实际签装结果、手机到测试服务的真实 HTTPS、合同修订用时给出剩余工作和外部等待两列；第二次在双设备首次写回后校准。每批报「可体验内容／能复跑的证据／阻塞与下一步」，保存同一提交、后端版本、构建号、设备/系统、脱敏日志及截图。若证据缺失，分端写未验；不得将此计划或任何静态图当成上线、已安装或已同步。
