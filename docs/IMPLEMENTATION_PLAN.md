# Nerae 三端同步实施计划

版本 1.4 · 2026-11-14。近期按[首个 iPhone 可用版本与全产品灰阶实施计划](RECORDING_DELIVERY_PLAN.md)执行；本页保留三端 M0–M4 总范围。方案、可安装工程、真实登录、跨设备与各端验收分别记录。

## 1. 目标、范围与当前起点

学员能在任一端查看计划、记录训练、获得教练反馈；教练能管理服务、接续草稿、审阅并交付计划。免费训练/饮食内容、饮食自评和需确认的 AI 建议按 P0-B 进入三端。小程序用微信登录，首个 App 测试版用真实邮箱验证码；手机号在具备供应商条件后由本人确认关联。相同主体可在安全关联后访问同一份获授权数据。

- **交付载体**：微信小程序、iOS App、Android App 同一产品范围、同批次研发和验收。H5 用于开发与辅助检查，不替代上述三个目标。
- **保留边界**：A 阶段平台内不收款、不代收、不分账；免费内容和教练自主定价；18+；健康采集同意与教练授权分开；AI 的建议/草稿经本人或教练确认。
- **记录方式**：首次默认训练后记录，以后记住模式；每组完成后记录与其共用草稿、动作段与组标识。保留在列表的组整次完成时各存一次，缺项不作零、不计缺项组累计。没有播放器或倒计时。
- **当前资产**：正式 uni-app 已有登录、编辑和云端回读；Go/HTTP/数据库已有隔离接缝，按新规则修订和页面写回仍有缺口。见[集成进度与证据](CURRENT_STATE.md)。
- **视觉基准**：所有自有页面必须遵循[白底灰阶规范](design/MONOCHROME_COLOR_SYSTEM.md)。R05 [方向图](design/round-05/app-storyboards/README.md)只参考流程及内容，不能替代真实页面截图。

`docs/tasks/tasks.json` 是唯一任务状态和依赖真源；工作包不可直接派发，单张执行卡最多 3 有效人日。用户已允许对有边界的任务使用 GPT-6 Luna 子代理；Lead 保持产品、架构、安全和最终验收责任，写任务仍按工作树和共享文件规则隔离，下表的依赖关系不等于自动启动任务。

## 4. 三端技术与内容规则

保留既定 **uni-app Vue3/TypeScript + Go/Gin 模块化单体 + MySQL/Redis**。共享领域行为和生成合同，平台差异经 `platform` 适配：登录、账号绑定、权限、存储、推送/通知、分享/深链、键盘/安全区与生命周期。服务端是权限和记录真源；客户端展示、缓存、标签或 AI 输出均不授予权限。

K01-02 包含小程序微信、首个 App 测试版真实邮箱，以及以后可选的手机验证和本人主动关联。备用恢复码与无可信途径时的人工申诉是恢复边界，实际能力须取证。账号关联要验证两侧控制权；不能依赖同一昵称或假定 unionid 始终可用。

K01-01 已收敛未知时长、不同动作计量、删除/修订、日期、版本与稳定记录键，并完成静态和生成探针；F02 的正式生成与 A04/U02 的真实实现仍待依赖和验收。计划采用的既有 `training-starts` 与用户补记/保存实际记录区分；不调用它伪造“开始训练”。

本地记录进入同步队列时绑定主体、会话、recordKey 和基线版本。离线数据明确显示未同步；换账号隔离队列；重放幂等，跨设备同组冲突保留两侧输入并让用户选择。撤权即时阻止后续服务端访问、AI 取数与通知，客户端旧缓存不能当授权证据。

内容由 S01-A/S01-B 提供真实来源、使用权、适用范围与复核；示例账户、截图中的价格和 AI 虚构内容不进入正式种子。O01/O02/O03 分别负责证据与审核、内容/评价申诉、隐私运维与恢复；不能只交后台空壳。

## 5. 集成与验收

每小批使用同一集成版本串行合并共享合同、路由、依赖锁与迁移顺序，登记依赖、实际执行者/模型、命令、退出码、截图/日志、风险和复核方式。需满足 [七项完成清单](DEFINITION_OF_DONE.md)；允许顺序角色复核时如实标注，不虚称独立 reviewer。未通过项回原卡，新增合同缺口另开卡，不在集成卡内扩业务。

| 验证层 | 最低要求 |
|---|---|
| 合同 / 单元 | K01 各正反例；稳定 recordKey、合法度量、未知时长、删除/修订、账号绑定、注销；三端消费者与生成类型一致 |
| 真正的服务 | 真实 HTTP/DB、两主体越权、双连接并发、幂等、expectedVersion 冲突、回滚、撤权与通知/AI 竞争 |
| 设备与客户端 | iOS 微信 + Android 微信的小程序，以及 iOS App + Android App；记录设备/系统/微信版本、包版本、签名方式、截图/录屏。H5 与模拟器单列 |
| 跨端记录 | 小程序记录→App 回读/修订及反向；两种模式往返不造两份记录；断网重启、重复提交、日期/时区、账号切换与冲突恢复 |
| 视觉 / 可访问性 | 真实页面对照白底灰阶基准和首页去线重排；核对各端主操作、素材、对比度、读屏、长中文、200% 文字、键盘、安全区、异常与减少动效 |
| 用户任务 | M1 至少一位同意参与的目标学员独立试用两种记录方式；M2 实际教练核对计划与反馈能否清楚传达交付价值。记录任务完成、输入/导航负担和失败点；缺参与者时不宣称用户验证通过 |
| 账号 / 发布 / 运维 | U08 客户端注销入口和状态，A01 身份/会话与 O03 删除/留存/恢复接线；注册回跳、账户关联、授权分离及各端审核各留证据 |

D02 在 `UI_SPEC.md` 列出实际产出的三端页面/状态规格、R05 参考图和素材索引；U01–U08 工作包已将当前规格与参考列为输入，细拆时执行卡必须引用对应 D02 具体产物和截图，不用已否定的旧稿当视觉基线。

App 采用第三方登录时需按实际方案核对 [Apple App Review 登录条款 4.8](https://developer.apple.com/app-store/review/guidelines/)，不能预设某一种登录组合必然通过；支持创建账户的 App 需按 [Apple 账号删除要求](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion/)提供应用内发起入口。服务/报价展示与平台外联系是否适合各商店的审核规则，由 L01 按真实业务与渠道核定，不从“不收款”直接推论允许公开获客。

uni-app 官方说明平台能力有差异，可用[条件编译](https://uniapp.dcloud.net.cn/tutorial/platform)处理；[uni CLI 文档](https://uniapp.dcloud.net.cn/worktile/CLI.html)区分 App 资源包与原生安装包。具体工具链与打包方式由 F01/P02-01 实测锁定，不能把理论支持当成构建或真机已通过。
