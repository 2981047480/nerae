## 0. 总则

### 0.1 冲突时的优先级

1. [api/openapi.yaml](<../api/openapi.yaml>) 与 [api/tests](<../api/tests/README.md>)：可执行、可复跑的契约事实。
2. 本文：工程结构、编码、测试、安全与协作约束。
3. [系统架构与技术选型](<系统架构与技术选型.md>)、[PRD](<PRD.md>)：方向与背景。
4. 历史评审记录、个人偏好、既有草稿。

**发生冲突必须停下并上报（§12），不得用「实现方便」覆盖契约，也不得为了消除 lint 警告而编造地址、字段或结论。** 本文与现有文档的已知差异集中记录在附录 E；该附录不修改历史文档。

### 0.2 事实边界：不要把目标写成已完成

- 目前没有 HTTP 服务、数据库、迁移、队列消费者、CI、监控、应用代码；文档里的目录、命令、job 都是构建目标。
- `[no test files]` **不是**测试通过；契约静态回归通过、TS/Go 生成通过都**不证明**运行时授权、事务并发、JWT 隔离、健康安全或真实模型质量（见 [API 说明 §5–6](<../api/README.md>)、[修复对照 §2](<ER与API修复对照-v1.1.md>)）。
- 任何「已验证」的表述必须同时给出：可复现命令、执行的提交或文件 SHA、结果输出；不能用「应该没问题」「生成成功所以正确」代替。
- 文档中出现的示例代码只说明写法，不代表仓库已有该文件。

### 0.3 语言、术语与格式

- 术语以 [CONTEXT.md](<../CONTEXT.md>) 为唯一词汇表：**服务关系、数据授权、健康信息采集同意、私人计划版本、公开模板版本、发布确认、字段来源、饮食观察、已确认自述观察、信息不足**等，代码标识符、契约字段、接口文案、UI 文案必须回指同一概念。
- 文档用中文；代码标识符、提交信息、日志字段、指标名、错误码用英文；禁止在公开接口和文档里使用未定义缩写（`rel`、`usr`、`pkg` 除外）。
- 时间：存储与传输统一 UTC ISO 8601；只有 `date` 类业务日期按契约声明的 `timeZone` 解释；金额一律整数分（`*_cents`）；ID 在 API 是字符串，在库是 `bigint unsigned`。
- 所有命令从**仓库根目录**执行。工具版本固定，禁止 `latest` 或浮动范围；本地与 CI 使用同一条命令。

### 0.4 命令的三种状态

| 状态 | 含义 | 本文标注方式 |
|---|---|---|
| 现在可执行 | 只依赖仓库现有文件（契约、Python、npx、Go） | 直接给命令 |
| 脚手架后执行 | 需要 `apps/`、`packages/`、`infra/` 存在 | 给出命令 + 前置条件 |
| 上线前必须建立 | CI、监控、备份演练等流程 | 列为「必须实现」，不写成现状 |

### 1.3 后端分层：handler → service → repo

```text
cmd/api ──► server（路由/中间件/ServerInterface 实现）
                 │ 只做转发与错误映射
                 ▼
          modules/<domain>/handler ──► modules/<domain>/service
                                          │        │
                                          ▼        ▼
                                   modules/<domain>/repo   rules / modules/ai 网关 / platform / 其他模块 service 接口
                                          │
                                          ▼
                                   internal/store（DB/Redis/事务）
```

| 层 | 位置 | 允许依赖 | 严格禁止 |
|---|---|---|---|
| 入口/装配 | `cmd/api`、`server` | `config`、`store`、`middleware`、各模块 handler/service、`gen` | 业务规则、直接 SQL、跨模块 repo |
| HTTP 适配 | `modules/*/handler.go` | `gen`、本模块 service、`middleware` 的 principal、`httpx`、validator | `repo`、`gorm`、`rules` 直接调用、把 request 原文塞进日志 |
| 用例/事务 | `modules/*/service.go` | 本模块 repo 接口、其他模块 service 接口、`rules`、`modules/ai` 网关接口、`platform` 接口、`store.Tx`、`httpx`、`pkg`、`context`/`time` | `gin`、`net/http`、`gen`、`gorm`、读取 HTTP header、直接 `uni`/微信 SDK |
| 持久化 | `modules/*/repo.go`、`entity.go`、`store` | `gorm`、`go-redis`、`store`、`pkg`、本模块领域类型 | service、handler、`gen`、`gin`、业务规则 |
| 规则 | `internal/rules` | 仅标准库（含 `time.Time` 值参数） | 其他 `internal/*`、`pkg/*`、I/O、日志、时钟/随机全局、panic |
| AI 网关 | `modules/ai/gateway` | 供应商 SDK、`pkg/jsonschema`、`pkg/secure`、`config` | `gin`、repo、service、把原始 prompt 写入普通日志 |
| 任务 | `cmd/worker`、`internal/job` | 各模块 service 接口、`store`、`config`、asynq | HTTP handler、gin、直接 repo（维护任务须走专用 service） |
| 公共件 | `pkg/*` | 标准库与少量通用库 | 任何 `internal/*`（防止反向依赖）、业务状态 |

**强制规则**

1. 依赖方向只能向下：handler → service → repo；不允许 repo 反向调用 service，或 service 直接拿到 `*gorm.DB` 拼查询。
2. `internal/rules` 必须纯函数、确定性、可单测：输入结构体 + 显式 `now`/规则版本，输出判定结果与规则码；不访问网络/DB/文件，不写日志，不读环境变量。
3. `internal/gen` 只允许 `handler` 与 `server` 引用；service 与 repo 使用领域类型，枚举在 handler 边界显式转换，未知值返回 `VALIDATION_ERROR`。
4. `server` 负责实现生成接口 `api.ServerInterface`；允许一行的委托（如 `s.auth.WechatLogin(c)`），不得在 `server` 里写业务分支、SQL 或授权判断。
5. `pkg/*` 不得 import `internal/*`；需要业务语义的代码应留在对应模块。

**内部结构与表所有权**

每个模块固定文件职责，避免「一个模块长成一个新单体」：

| 文件 | 职责 | 备注 |
|---|---|---|
| `model.go` | 领域结构体、值对象、状态常量 | 不出现 `json`/`gorm`/`gin` tag；不含 SQL |
| `entity.go` | GORM 实体与表名 | 仅本模块 repo 可见；其他模块不得引用 |
| `repo.go` | 查询与写入、CAS、唯一键冲突识别 | 只返回领域错误，不返回 `gorm.ErrRecordNotFound` 之外的上层错误 |
| `service.go` | 授权、事务边界、版本/幂等、调用规则与网关 | 唯一允许开启事务的地方 |
| `handler.go` | 绑定/校验/调用/响应映射 | 不写重试、不直接发队列消息 |
| `errors.go` | 本模块领域错误与 `httpx` 映射 | 不把内部错误文本暴露给客户端 |

**表所有权**：每张表有且只有一个模块可写。跨模块读取通过对方暴露的只读 service 方法或调用方定义的 port 接口，不直接 `JOIN` 或引用对方 `entity`。跨模块写入一律通过对方 service 的事务性用例。

示例（正确的跨模块依赖方向，由消费方定义接口）：

```go
// relation/service.go：消费方定义自己需要的最小接口，实现由 user 模块提供，在 server 装配时注入。
type userStatusReader interface {
    IsActive(ctx context.Context, userID uint64) (bool, error)
}
```

**禁止**：`relation` import `user/repo`；两个模块互相 import；为图省事把对方表复制进自己的 repo。

### 1.5 前端分层与依赖方向

逻辑分层统一为 `ui / api / domain / platform / stores`。物理目录沿用 uni-app 与 Vue 习惯：UI 层是 `pages/`、`components/`（后台为 `views/`、`components/`），不强制改名为 `ui/`。

| 层 | mini 位置 | admin 位置 | 允许依赖 | 严格禁止 |
|---|---|---|---|---|
| UI | `src/pages`、`src/components` | `src/views`、`src/components` | `api`、`domain`、`stores`、`styles`、`packages/design-tokens` | 直接 `uni.*`/`wx.*`、`uni.request`、`localStorage`、硬编码颜色/间距、直接拼 URL |
| API | `src/api` | `src/api` | `platform` 的请求传输、`packages/api-types` | 页面状态、Pinia、业务规则、DOM/UI 逻辑 |
| Domain | `src/domain` | `src/domain` | 标准 TS 与纯工具 | `uni.*`、Vue、Pinia、网络、存储、组件 |
| Platform | `src/platform` | 无（浏览器差异放 `api/http`） | 宿主 API（`uni`/`wx`）、`domain` 的纯函数 | 页面/组件、stores、业务接口编排 |
| State | `src/stores` | `src/stores` | `api`、`domain`、`platform` | 页面组件、直接 `uni.*`、长期重复缓存服务端事实 |

**强制规则**

1. 页面与组件**禁止直接调用 `uni.*` / `wx.*`**；登录、存储、分享、订阅消息、上传、导航、设备信息一律封装在 `platform/`。平台差异（小程序/H5/App）只允许出现在 `platform/` 内部；UI 层不得用条件编译分支模拟业务。
2. `domain/` 是纯 TS，可在 Node 下直接单测；不 import Vue、Pinia、`uni`、网络模块。业务规则以后端为准，前端 `domain/` 只做展示计算与即时提示，不复制可产生不同结论的规则（如热量处方、过敏判定）。
3. 类型只来自契约：`packages/api-types` 由 OpenAPI 生成；API 请求/响应禁止手写重复 interface、禁止 `any`、禁止对响应做无校验的 `as` 强转。确实需要的窄化必须集中在 `api/` 的解析函数并带运行时校验。
4. 状态边界：Pinia 只放跨页面/会话状态（如当前身份、当前计划、未读计数）；服务端事实要有明确失效策略，不在多个 store 复制同一份数据。页面局部状态用组件内 `ref`，不进 store。
5. 应用之间禁止互相 import：`apps/mini` 与 `apps/admin` 只能依赖 `packages/*`；共享逻辑下沉到包，而不是复制粘贴。
6. 后台路由守卫只是体验优化，**不是授权**：权限判定必须由服务端返回 403/404；前端不得把「按钮隐藏」当作安全措施。

### 1.6 契约生成物与共享包

| 产物 | 生成命令（固定版本） | 落位 | 规则 |
|---|---|---|---|
| TS 类型 | `npx --yes openapi-typescript@7.6.1 api/openapi.yaml -o packages/api-types/src/schema.ts` | `packages/api-types/src/schema.ts` | 提交；文件头保留生成器信息；只允许在 `src/index.ts` 做别名/联合类型包装 |
| Go 接口与模型 | `mkdir -p apps/api/internal/gen && go run github.com/oapi-codegen/oapi-codegen/v2/cmd/oapi-codegen@v2.4.1 -config api/oapi-codegen.yaml api/openapi.yaml` | `apps/api/internal/gen/api.gen.go` | 提交；禁止手改；生成配置见 [api/oapi-codegen.yaml](<../api/oapi-codegen.yaml>) |
| 设计 token | 由 `packages/design-tokens` 的固定脚本生成 CSS/SCSS | `packages/design-tokens/dist/*` | 提交生成物；源文件是唯一修改入口 |

- 契约变更顺序：改 `api/openapi.yaml` → 跑静态回归 → 重新生成 → 实现。**不允许先写 handler 再补契约**；也不允许手改生成文件来「适配」代码。
- 生成物必须可复现：CI 重新生成后 `git diff --exit-code`；diff 非空视为失败（说明源、生成器版本或生成物不同步）。
- `packages/api-types` 不承载业务逻辑；`packages/design-tokens` 不承载组件实现。

## 2. Go 编码规范

适用于 `apps/api` 全部 Go 代码（含 `cmd/`、`internal/`、`pkg/`）。

### 2.1 版本与工具链

- Go 版本以 `apps/api/go.mod` 的 `go` 指令为准（架构要求 1.23+）；本地、CI、镜像使用同一 minor 版本，升级单独 PR 并全量回归。2026-10-22 契约冒烟使用过隔离工具链，那只是契约验证，不构成应用版本声明。
- 禁止使用 `replace` 指向本地路径；禁止在业务代码里 import `testdata` 或构建标签之外的测试辅助包。
- 依赖新增遵循 §12：先批准、再进 `go.mod`，许可证与维护状态写入 PR。

### 2.2 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 包 | 小写单词，不用下划线/复数/`utils`/`common`/`helpers`/`base` | `relation`、`gateway`、`secure` |
| 文件 | `snake_case.go`；测试 `*_test.go`；生成物 `*.gen.go` | `grant_service.go`、`relation_repo_test.go` |
| 类型/函数/变量 | 驼峰；缩写整体大小写一致 | `userID`、`HTTPClient`、`JSONSchema`、`parseDSN` |
| 接口 | 按行为命名，1–3 个方法，定义在使用方；不加 `I` 前缀 | `grantReader`、`publisher` |
| 构造函数 | `NewXxx`；可选参数 >3 个才用 `WithXxx` 选项 | `NewRelationService(...)` |
| 错误 | 哨兵 `ErrXxx`；类型 `XxxError`；禁止比较错误字符串 | `ErrRelationEnded`、`VersionConflictError` |
| 枚举 | 有类型常量，值必须与契约 `enum` 逐字一致；持久化值不用 `iota` | `RelationStatusPendingStudent = "pending_student"` |
| 时间/金额/版本 | `*At`、`*Cents`、`Version`/`ExpectedVersion`、`*Hash` | `activatedAt`、`priceCents`、`offeredVersion` |
| 布尔 | `is*`/`has*`/`can*`；避免双重否定 | `hasInjuryNotes`、`canPublish` |
| 测试 | `TestService_Method_场景`；表驱动子测试用场景名 | `TestGrantService_Put_RejectsStaleVersion` |

- 导出标识符必须有以名称开头的文档注释；不为显而易见的小函数写复述式注释。
- 避免口吃：`user.Service` 而不是 `user.UserService`；避免同义异名（`FindUserByID` 与 `GetUserByID` 只留一个）。
- 领域词必须与 [CONTEXT.md](<../CONTEXT.md>) 及契约字段一致：`serviceRelation` 不写成 `binding`，`dataGrant` 不写成 `sharePermission`。

### 2.3 包设计与依赖注入

- 默认不导出；只有跨包或被生成代码调用时才导出。
- 禁止包级可变状态（`var db *gorm.DB`、业务缓存、全局 map）。依赖通过构造函数注入，便于测试与并发安全。
- 禁止在 `init()` 里做 I/O、读环境变量、连接数据库；生成的注册代码除外。
- 依赖方向遵守 §1.3：service 依赖接口，repo 依赖 `store`，`server` 负责装配。
- 一个接口只有一个实现且无测试替身需求时，不必先抽接口；需要替身时在消费方定义最小接口。
- 不返回具体第三方类型（`*gorm.DB`、`*gin.Context`、`asynq.Task`）穿过层级边界；入口处转换。
- `context.Context` 永远是第一个参数，命名为 `ctx`；错误永远最后一个返回值。

### 2.4 错误与统一错误码

**分层规则**

| 层 | 返回什么 | 不做什么 |
|---|---|---|
| repo | 领域哨兵错误/包装后的基础设施错误 | 不返回 HTTP 状态，不拼用户文案 |
| service | `*httpx.Error`（可映射）或领域错误 | 不写 HTTP 响应，不暴露 SQL/上游原文 |
| handler | 调用 `httpx.WriteError(c, err)` | 不 `c.JSON` 手拼错误体 |

**写法**

```go
// 包装：只在层边界补充上下文，同一错误只包一次，保留 %w 链。
if err := s.repo.EndRelation(ctx, relationID, version); err != nil {
	return fmt.Errorf("relation.end: %w", err)
}

// 登记：业务错误集中定义，handler 只做一次映射。
var (
	ErrRelationEnded   = errors.New("relation ended")
	ErrVersionConflict = errors.New("version conflict")
)
```

**统一错误体**（必须与契约 `Error` 一致）

```json
{"code":"VERSION_CONFLICT","message":"资源已被修改，请重新读取后再试","requestId":"01J...","details":{}}
```

- `code` 是稳定契约：客户端按 `code` 分支；`message` 可改；`details` 只放结构化、非敏感、非健康正文的数据。
- 状态码与错误码的完整登记表见附录 B。**新增或改名 code 属于契约面变更，必须走 §8.4 的流程，不能在实现里临时造一个字符串。**
- 版本冲突（`expectedVersion` 不匹配）固定 `412`；非法状态、幂等同键异摘要、关系已结束等固定 `409`；两者不得互换，也不得自动重试覆盖。
- 对象级未授权默认返回 `404`（不暴露资源存在性）；只有「资源存在性已明确、操作被角色或状态禁止」时才用 `403`。
- 5xx 不返回内部错误文本、SQL、上游响应；完整原因只进日志（带 `request_id`）。
- 业务错误禁止 `panic`；`recover` 只由最外层中间件/任务包装器兜底，记录堆栈并返回 `500 INTERNAL`。
- 不要用 `errors.Is(err, gorm.ErrRecordNotFound)` 穿透到 handler；repo 转成 `ErrNotFound`。

### 2.5 requestId 与 context

- 中间件为每个请求生成 `requestId`（`crypto/rand` ≥16 字节，hex/base32，长度 ≤64），写入 context 与响应；错误体 `requestId` 必填。
- 允许读取客户端 `X-Request-Id` 仅作关联（`client_request_id`），必须校验字符集与长度；**不得用于鉴权、幂等键或审计主体**。
- 建议额外返回 `X-Request-Id` 响应头（契约未禁止的增量头）；但契约内的 `Error.requestId` 才是权威来源。
- context 只承载：请求取消/截止时间、`requestId`、已认证主体（由中间件写入）、事务句柄、logger。禁止把请求体、敏感字段或「当前操作人由客户端传入」塞进 context。
- **授权输入必须显式传参**：handler 从 context 取主体后作为 service 的第一个业务参数传入，例如 `ConfirmRelation(ctx, actor, relationID, in)`；service 不从 context 里偷偷读身份。这样越权用例可以显式构造主体。
- 所有 I/O 必须 `WithContext(ctx)`：GORM `db.WithContext(ctx)`、Redis `WithContext`、HTTP `NewRequestWithContext`；禁止在请求路径使用 `context.Background()`/`context.TODO()`。
- 超时：中间件按路由类别设置 deadline（普通/上传/AI，见 §9）；service 在调用外部服务前再派生更短超时；循环中检查 `ctx.Err()`，取消后不得继续写库或发消息。
- 请求结束后不得再使用该 context（异步一律走 asynq，任务里创建独立 context 并带超时）。

### 2.6 并发、超时与资源

- **不要在 handler 里起 goroutine 做「稍后执行」的事**。异步动作写队列；请求内需要并行时用 `errgroup.WithContext` 并等待全部返回。
- 并发安全优先用数据库约束/CAS，而不是进程内锁；单实例内的 `sync.Mutex` 只保护极小状态，并在注释说明为什么不需要跨实例。
- 分布式锁（Redis）必须带 owner token + TTL + fencing；**不得用锁代替 `expectedVersion`/唯一键**。
- HTTP 服务：设置 `ReadHeaderTimeout`、`ReadTimeout`、`WriteTimeout`、`IdleTimeout`、`MaxHeaderBytes`；上传与 AI 路由单独放宽并在配置中写清。
- 数据库连接池、Redis 池、HTTP 客户端超时全部来自配置；禁止零值超时（无限等待）。
- 列表查询必须分页且上限为契约 `pageSize`（≤50）；批量写按 200–500 行分块；禁止 `Find` 全表。
- 重试只用于幂等操作，指数退避 + 抖动，设置最大次数；重试前先判断错误类型（超时/可重试 5xx/连接错误），业务冲突不重试。
- worker：单任务超时、最大重试、死信告警、并发数均为配置；任务必须幂等并重查授权。
- 退出：监听 SIGTERM/SIGINT，停止接收新请求 → 在 `Shutdown` 超时内完成 → 关闭 DB/Redis/队列；不允许 `os.Exit(0)` 跳过清理。

### 2.7 日志与脱敏

- 统一 `log/slog` + JSON handler；日志从 context 取 logger，字段固定，禁止 `fmt.Println`、标准 `log`、字符串拼接 JSON。
- 必带字段：`request_id`、`actor_kind`、`actor_id`、`route`、`method`、`status`、`latency_ms`；错误日志加 `error_code`、`err`、`module`；AI 加 `ai_scene`、`ai_model`、`ai_run_id`、`tokens_in`、`tokens_out`、`cost_cents`；任务加 `job_type`、`attempt`。完整字段见附录 C。
- **禁止记录**：JWT/Authorization、密码/密钥、openid/unionid、手机号、真实姓名、伤病正文、饮食观察正文、过敏原清单、私信正文、AI prompt/补全中的个人健康内容、签名 URL、完整请求/响应体。
- 需要关联用户时用数值 `user_id` 或加盐哈希；需要展示时用 `pkg/secure.Mask`（手机号 `138****1234`）。**脱敏在写入日志前完成，不依赖日志平台过滤。**
- 失败请求记录原因与堆栈（5xx），4xx 只记 `error_code` 与必要的非敏感 `details`；健康相关业务事件记 ID 与动作，不记正文。
- 审计日志写入数据库 `audit_log`，与普通应用日志分离（§10.7）；不能因为「audit 里有」就在应用日志里记正文。
- 新增涉及敏感域的日志语句必须附脱敏单测；日志字段评审属于 Review checklist（§7.4）。

### 2.8 配置与环境变量

- 配置由 `internal/config` 一次性加载为不可变结构体，注入各组件；业务代码禁止 `os.Getenv`、禁止 import viper。
- 优先级：环境变量 > 配置文件 > 默认值；生产必须显式提供安全敏感项（JWT 密钥、数据库 DSN、加密 key、AI API Key）。
- 变量命名 `NERAE_<AREA>_<NAME>`，时长带单位（`30s`、`24h`），布尔显式（`true/false`），列表用逗号分隔并在启动时校验。
- 启动期校验并 fail fast：必填项缺失、时长非法、生产环境 `debug`、`AutoMigrate` 开关为真、密钥长度不足，一律拒绝启动并给出变量名（不打印值）。
- 配置变更靠重启（或明确列入配置中心的开关）；**不允许**运行时修改业务规则阈值、AI 模型档位或配额上限而不留版本记录。
- `.env.example` 只放占位符与注释；`.env`、密钥、证书一律不入库；不同环境密钥不同。
- 完整变量清单见附录 D；新增变量必须同时更新该附录与部署手册（OPS-01）。

### 2.9 可读性与注释

- 注释解释「为什么」和不显然的约束（并发、兼容、合规），不复述代码。导出符号的文档注释以其名称开头。
- `TODO` 必须带责任人与日期：`// TODO(backend, 2026-11-15): 支持分包加载`；禁止无主 TODO、注释掉的死代码、调试打印。
- 函数优先早返回；参数 >4 个用输入结构体；避免超过 5 层嵌套；一个函数只做一件事。
- 魔法数字必须具名（配额、超时、阈值、长度限制从配置或常量来）；健康相关阈值不得在代码里写死，必须版本化（§3.7、§9）。
- 接口实现处用编译期断言：`var _ api.ServerInterface = (*Server)(nil)`；repo 同理。
- 错误字符串小写、无标点；面向用户的 `message` 放 `httpx` 登记表，不散落在各分支。

### 2.10 硬性禁止事项

1. 生产环境调用 GORM `AutoMigrate`（任何形式，包括测试开关带入生产）。
2. 业务代码 `panic` 兜底、用 `recover` 吞掉错误后继续返回成功。
3. 包级可变全局（DB、配置、`map` 缓存、随机源）；跨请求共享可变状态。
4. `context.Background()`/`TODO()` 出现在请求路径；把 context 存进结构体字段。
5. 在事务内调用外部网络（微信、COS、AI）或发送通知。
6. 手拼 SQL/`fmt.Sprintf("... %s", input)`；`SELECT *`；无 `LIMIT` 的列表/批量。
7. 把 `expectedVersion` 当可选参数，或在 CAS 失败后自动重试覆盖。
8. 在 service/handler 里直接读 body 原文写日志；把健康正文拼进错误信息。
9. 用 `math/rand` 生成令牌/密钥/幂等键；用时间戳做唯一键。
10. 忽略错误（`_ = f()`）除显式关闭资源的 `defer func(){ _ = f.Close() }()`；不得忽略 DB/队列/加密错误。
11. `os.Exit`/`log.Fatal` 出现在 `main` 之外；启动之外的 `init()` 副作用。
12. 直接 import 其他模块 repo/entity；`pkg/*` 反向 import `internal/*`；`rules` import 任何项目内包。
13. 手改 `internal/gen` 或 `packages/api-types` 生成物；复制契约枚举到多处各写一份。
14. 生产配置中启用 CORS `*`、调试日志、无鉴权的 Swagger UI。
15. 未经批准新增依赖、升级 Go minor、替换 AI 模型/供应商（§12）。

## 3. 数据库、迁移与事务

适用范围：`apps/api/migrations/`、`internal/store/`、各模块 `repo.go`/`entity.go`。表结构以 [数据模型与 ER 设计](<数据模型与ER设计.md>) 为准；ER 是设计输入，不是 DDL。

### 3.1 表与字段约定

| 项 | 规则 |
|---|---|
| 引擎/字符集 | InnoDB；`utf8mb4`；MySQL 8 默认排序规则；会话时区固定 UTC |
| SQL 模式 | `STRICT_TRANS_TABLES,NO_ZERO_DATE,NO_ZERO_IN_DATE,ERROR_FOR_DIVISION_BY_ZERO`；迁移与连接都显式设置 |
| 表名 | `snake_case`、单数、与 ER 同名（`user`、`service_relation`）；不额外加 `t_`/`tb_` 前缀 |
| 主键 | `id bigint unsigned` 自增；API 中始终是字符串；不把自增 ID 当公开分享凭据 |
| 引用 | `bigint unsigned`，列名 `<entity>_id`；跨主体引用必须同时校验主体一致（如 `student_id` 属于该关系） |
| 时间 | `datetime(3)`，UTC；业务日期用 `date`，按契约 `timeZone` 解释；禁止用字符串存时间 |
| 金额 | `int unsigned` 分；禁止 `float/double`；成交自报区间 `min <= max` 且成对为空 |
| 枚举 | `varchar(32)`（规则码等可更长），允许集合与契约 `enum` 完全一致；不用 MySQL `ENUM`；可选 `CHECK` 约束 |
| 布尔 | `tinyint(1) NOT NULL DEFAULT 0`；Go 侧 `bool` 显式转换 |
| 哈希 | `char(64)` 小写十六进制 SHA-256；`hash_version` 独立字段；hash 不是访问凭据 |
| JSON | MySQL `json`；写入前按具名 schema 校验（训练/饮食内容、terms、scopes、evidence）；不得用任意 JSON 替代必填列 |
| 审计列 | 可变实体：`created_at`、`updated_at`；不可变版本/事件只有 `created_at`；创建者取认证主体，不接受客户端传入 |
| 软删除 | `deleted_at datetime(3) NULL`；删除不解除历史版本、幂等键、审计和记录引用 |
| 命名 | 索引 `idx_<table>_<cols>`、唯一 `uk_<table>_<cols>`、外键 `fk_<table>_<ref>`；名称 ≤64 字符 |

- 默认建物理外键（生产单库、写量可控）；确因写放大不建时，必须走 ADR，并在同一事务内做引用校验 + 负向测试，不能以「代码会检查」口头豁免。
- `id` 解析只发生在 handler：仅接受十进制、非负、≤ `uint64` 上限的字符串；非法返回 `VALIDATION_ERROR`，不得传给 repo。
- 所有 JSON 列必须有 Go 结构体与校验函数；`json.RawMessage` 只能出现在明确的透传边界。

### 3.2 索引规则

1. 每个外键列、每个高频过滤列必须有索引；联合索引顺序按「等值 → 排序 → 范围」。
2. 列表接口的过滤/排序组合必须有对应索引；PR 里附 `EXPLAIN` 结果与预估行数。
3. 业务唯一键必须建唯一索引，不能只靠应用层查重（并发下必漏）。
4. 禁止在索引列上做函数/隐式转换；禁止 `LIKE '%x%'` 作为主查询（后台模糊搜索除外，并限制范围）。
5. 单表索引数量控制在 5 个以内；新增索引必须说明替代了哪个查询，避免重复索引。
6. 列表分页用稳定排序（`created_at DESC, id DESC`）；`OFFSET` 仅用于契约规定的 page/pageSize；深分页改 keyset（需契约支持时再改）。
7. 计数查询单独设计：广场/后台列表的 `total` 可用近似或缓存，但契约 `Paginated.total` 必须给出明确口径并测试。

ER 已明确的代表性索引（实现时不得遗漏）：

| 表 | 索引/唯一键 |
|---|---|
| `user` | `UK(openid)`；状态/`token_version` 有查询索引 |
| `admin_account` | `UK(username_normalized)`；口令哈希、`token_version`、锁定字段按 ER 实现 |
| `service_relation` | `(student_id,status)`、`(coach_id,status)`、`(end_at,status)` |
| `relation_confirmation` | `UK(relation_id,offered_version,side)` |
| `data_grant` | `UK(relation_id)`；`data_grant_revision` `UK(grant_id,version)` |
| `conversation` | `UK(appointment_id)`、`UK(relation_id)` |
| `idempotency_record` | `UK(actor_kind,actor_id,route,key)` |
| `message` | `UK(conversation_id,sender_kind,sender_id,request_key)` |
| `diet_checkin` | 按 ER 唯一键（用户+日期+计划版本/日）实现，具体以 ER 为准 |
| `workout_session` | `(user_id,status)`、`(plan_id,plan_version,plan_day_id)` |
| `audit_log` | `(actor_kind,actor_id,created_at)`、`(target_type,target_id)` |

### 3.3 迁移（golang-migrate）

**文件与顺序**

```text
apps/api/migrations/
├─ 000001_init_users_profiles.up.sql
├─ 000001_init_users_profiles.down.sql
├─ 000002_coach_service_packages.up.sql
└─ 000002_coach_service_packages.down.sql
```

- 版本号 6 位、单调递增、永不复用；文件名 `{version}_{slug}.{up|down}.sql`，slug 小写下划线。
- 一个迁移只做一件事（建表/加列/加索引/回填分开）；已合并或已应用的迁移**禁止修改**，修正用新迁移向前修。
- 每个 up 必须有 down，除非明确不可逆。不可逆必须：写 ADR、提供补偿脚本、在预发做备份恢复演练；App 侧必须兼容 N-1 版本。

**向前兼容（expand → migrate → contract）**

1. 先加可空列/新表/新索引（旧代码可忽略），部署 N。
2. 回填用独立任务分批执行，幂等、可重入、限速；回填期间双读或旧路径继续可用。
3. 切换读路径并在预发验证后，再在后续版本加 `NOT NULL`/唯一约束/删旧列。
4. 删除列/表/收紧类型必须在功能已下线且观察期结束后单独发布，不与依赖它的代码同版。

**执行与校验**

- 应用启动**不执行**迁移；由部署流程/运维显式执行。启动时只校验 schema 版本：落后或高于二进制预期都拒绝启动并告警。
- 本地使用 F01 的隔离环境（`make bootstrap` / `infra/compose/`）与任务卡给出的迁移命令；迁移前 CI 在空库执行 up → down → up，并在含数据副本上做一次兼容检查。
- 大表 DDL 使用 online DDL（`ALGORITHM=INPLACE/INSTANT`）并在副本验证；设置 `lock_wait_timeout`，不允许长时间阻塞线上写。
- 禁止在迁移中使用存储过程、触发器、事件调度器；禁止把种子内容写进迁移（种子放 `content/seed/`，由单独任务导入）。

### 3.4 事务边界

- **一个 service 用例 = 一个事务**；handler 不开事务，repo 不自行提交。事务入口统一 `store.Tx(ctx, fn)`（或等价物），嵌套事务一律报错。
- 事务内禁止调用外部网络（微信、COS、AI）与发送通知/入队；这些动作在提交后执行，失败可重试且不重复副作用。
- 需要「提交后通知」时用事务性 outbox 或提交后 hook；asynq 任务必须带业务唯一键并幂等，消费时重查授权。
- 授权/版本/幂等这类路径，事务内必须**重新读取并校验**关系状态、grant scopes、当前版本，不能只依赖事务开始前的检查（TOCTOU）。
- 审计事件、幂等完成状态、业务结果引用、版本推进必须在**同一事务**内提交；不允许先返回成功再补写审计。
- 默认隔离级别 `REPEATABLE READ`；确需锁行时用 `SELECT ... FOR UPDATE` 并保持锁范围最小；禁止长事务与全表锁。
- 死锁/锁等待（MySQL 1213/1205）只在幂等用例内做有限重试（≤2 次、新事务、重新 CAS），其他情况直接失败并记录。

### 3.5 乐观锁（expectedVersion CAS）实现要求

**必须满足**

1. 每条版本化写入都带 `expectedVersion`；服务端用「目标资源当前版本」原子比较，不做「先读后无条件写」。
2. 使用单条条件更新并检查 `RowsAffected`：

```sql
UPDATE service_relation
SET status = 'active', activated_at = ?, version = version + 1, updated_at = ?
WHERE id = ? AND version = ? AND status = 'pending_student';
```

3. `RowsAffected = 0` 时不得自动重试或合并。在同一事务内回读当前行，按不变量区分：
   - 行不存在或无权可见 → `404`；
   - 行存在但 `version != expectedVersion` → `412 VERSION_CONFLICT`；
   - 版本相同但状态不允许 → `409 STATE_CONFLICT`（关系已结束、已撤销等）。
4. 首次写入按契约要求 `expectedVersion=0`：采用「插入 + 唯一键兜底」；并发两笔 0 只能一笔成功，另一笔返回 `412`（不得静默合并、不得 upsert 覆盖）。
5. `version` 只在成功写入时 +1；失败/重放不推进版本；幂等重放返回首次结果。
6. 禁止用 GORM `Save()`/无版本条件的 `Updates()` 更新版本化聚合；禁止把 `expectedVersion` 当查询提示而非 WHERE 条件。
7. 结束关系/撤权必须在一个事务内完成：关系终态 + 授权清空与版本推进 + 授权历史 + 审计；即使此前无授权也要写撤回墓碑，阻断迟到的 `expectedVersion=0`。
8. 缓存/任务/摘要不得延长权限；读取与异步执行都要重查当前版本与授权。

**必须存在的测试**：两设备并发写同一版本（一笔成功、一笔 412）；旧客户端重放（412 而非复活）；结束关系与 grant 并发（终态后无新授权）；关系过期后立即拒绝（不等定时任务）。

### 3.6 幂等记录

实现 ER §9.2 的 `idempotency_record`，协议固定如下：

1. 先鉴权与校验请求，再用 `(actor_kind, actor_id, route, key)` 唯一键原子取得执行权。
2. **同键同摘要且已成功** → 原样重放首次状态码与响应快照，不再执行副作用；响应头带 `Idempotency-Key-Expires-At`。
3. **同键同摘要且 processing** → 不启动第二次执行；按 `409 REQUEST_IN_PROGRESS` 返回（该 code 未在契约枚举，状态码与 code 均待附录 B 的契约评审确认，不得由实现单方面冻结）。
4. **同键异摘要** → `409`，不得覆盖首次结果。
5. 业务变更、幂等完成状态、结果引用必须同一事务提交；跨系统投递要有可恢复的唯一业务事件。
6. 结果未知时先查业务事实与 `result_type/result_id`，不得因进程重启重复建关系/发消息/发布。
7. 重放前重新检查当前主体权限与敏感结果可见性（撤权后不得返回健康正文）。
8. 保留期默认 24 小时（配置项，属于**待确认实现默认值**，不是业务承诺）；窗口内不删除 processing 记录，过期清理只清已完成记录。
9. 请求摘要规范化：方法 + 含具体资源 ID 的规范路径 + 排序后的业务 query + 规范化 JSON body（含 `expectedVersion`）；不含 token、`requestId`、`Idempotency-Key` 本身。规范版本写入 `hash_version`。
10. 缺失、空串或非法字符的 `Idempotency-Key` → `400 VALIDATION_ERROR`；不得用空字符串兜底。

### 3.7 加密、规范化与软删除

**加密字段**（与 ER 一致）：`user.phone_enc`、`coach_profile.real_name_enc`、`student_profile.injury_notes_enc`、`personal_allergen_profile.allergens_enc`、`message.body_enc`、`check_in.content_enc`、`idempotency_record.response_body_enc`，以及任何落库的健康/AI 输入。

- 算法：AES-256-GCM；随机 12 字节 nonce 与密文一起存；`key_id` 必填。
- AAD 至少绑定 `table|column|row identity`，防止密文搬移；解密失败按数据损坏处理并告警，不返回空值。
- 密钥来自 KMS/环境变量，按环境隔离；轮换时新写用新 `key_id`，读支持旧 key；**密钥不入库、不入镜像、不进日志**。
- 健康正文只在必要时解密到内存，用后不缓存；禁止把明文放进错误、审计 detail、trace attribute。
- 加密单测：roundtrip、篡改必失败、AAD 不匹配必失败、轮换后旧数据可读。

**规范化哈希**（`content_hash`、`terms_hash`、`request_hash`）

- 固定一个规范化版本（`hash_version`）并写测试；规则至少包含：键排序、数值唯一表示、字符串 NFC、数组顺序保留、显式 null 与缺省区分、不包含只读字段/计数/时间。
- 发布 `content_hash` 覆盖 `planType/title/goal/content/visibility` 及字段来源元数据；可见性变化必须改变 hash（ER §2.2）。
- 任何人不得用「重新计算 hash」掩盖内容变更；hash 不一致 = 旧确认失效。

**软删除与保留**

- GORM 查询默认带 `deleted_at IS NULL`，绕过必须显式 `Unscoped()` 且仅限清理/审计任务。
- MySQL 唯一索引视 NULL 为互不相等：`UK(col, deleted_at)` **不能**保证存活行唯一。需要软删除且需唯一性的表，必须在 ADR 中选择：物理删除 + 墓碑表、或应用层事务内唯一键行；不得假定数据库会拦住。
- 删除是异步流程：先标记、立即停止业务读取与模型使用，再按保留策略清理；撤回授权不等于立即物理删除，但必须立即停止新增读取（ER §13）。
- 删除过敏资料后保留最小版本墓碑；不得转换成 `none_reported`。

### 3.8 查询与数据访问

- repo 方法只接受领域参数，返回领域错误；不暴露 `*gorm.DB`、不返回 `sql.Rows`。
- 所有查询使用占位符；禁止把用户输入拼进表名/列名/排序字段（排序字段用白名单映射）。
- 查询必须带 `WithContext(ctx)`；列表必须 `LIMIT`；批量必须分块；禁止在循环里逐条查（N+1）。
- 只 select 需要的列；大 JSON 列按需读取，不在列表接口返回完整正文。
- 计数与聚合查询单独限流/缓存；`total` 口径必须在响应测试中固定。
- 时间比较统一 UTC；跨日业务按契约 `timeZone` 在 service 计算后再落库。

### 3.9 数据库禁止事项

1. 生产 `AutoMigrate`；任何「启动时顺手建表」。
2. 修改已合并/已应用的迁移文件；跳过版本号；手写 `schema_migrations`。
3. 在事务内调用外部服务、发消息、跑长时间回填。
4. 迁移里做数据导出、删除、含健康明文的 UPDATE。
5. 使用 MySQL `ENUM`、触发器、存储过程、事件调度器。
6. 用 `float` 存金额/版本；用字符串存时间戳；用 0/NULL 混合作「未知」。
7. `SELECT *`、无 `WHERE` 的 `UPDATE/DELETE`、无 `LIMIT` 的列表。
8. 用应用层查重替代唯一索引；用软删除掩盖唯一性冲突。
9. 在日志/审计 detail 中写健康正文或加密前的明文。
10. 未经批准新增迁移（迁移目录按任务卡 `write_allowlist` 单列任务，合并顺序由 Lead 串行控制，见协作规范 §4）。

```text
apps/mini/src/

├─ stores/                   # Pinia
├─ styles/                   # 主题入口、语义样式；引用 tokens 生成物

依赖方向固定：`ui → api/domain/stores/styles`，`api → platform（仅 mini 的请求传输）/packages`，`stores → api/domain/platform`，`domain → 无应用依赖`。禁止 `api` 反向 import `ui`，禁止 `domain` import 任何应用层模块。

### 4.2 页面与组件规则

- 页面只做「取数 → 组装视图 → 响应用户动作」；业务计算放 `domain/`，请求放 `api/`，平台调用放 `platform/`，跨页状态放 `stores/`。
- 每个页面必须实现四态：加载、空、错误/重试、无权限（适用时）；另有离线/弱网提示。状态文案来自统一常量，不在模板里散写。
- 页面文件建议 ≤300 行；超出拆组件或 composable（`useXxx.ts`）。组件只通过 props/emits 通信，不直接读取页面路由或全局 store（容器组件除外）。
- 组件命名：`PascalCase.vue`，多词（`PlanCard`、`CoachHeader`）；基础组件 `BaseButton`、`BaseEmpty`、`BaseSkeleton`；领域组件用业务前缀（`Plan*`、`Coach*`、`Diet*`）。后台页面 `XxxView.vue`，表格页/详情页/确认弹窗复用 `components/patterns/`。
- props 用 camelCase，模板中 kebab-case；事件名 kebab-case；禁止 `v-html`（除非内容由本系统服务端产出且已白名单清洗，仍需评审）。
- 组件不得直接调用 `uni.*`；不得直接 `uni.request`；不得自己拼 API URL。
- 复用优先：W2 的 `Button/Card/List/Empty/Skeleton/ActionBar` 与后台表格模板建立后，新页面必须优先复用；新增基础组件需任务卡与设计确认。

### 4.3 平台差异与 `platform/`

平台差异**只能**出现在 `src/platform/`：

| 模块 | 职责 | 典型宿主 API |
|---|---|---|
| `login` | 微信登录 code、静默登录、会话恢复 | `uni.login` |
| `storage` | 统一键前缀、加密/过期、清理 | `uni.getStorageSync` 等 |
| `navigation` | 路由跳转、返回、参数序列化 | `uni.navigateTo` |
| `share` | 分享菜单、海报参数、链接拼接 | `uni.showShareMenu` |
| `subscribe` | 订阅消息授权与结果回传 | `uni.requestSubscribeMessage` |
| `upload` | 选择文件、压缩、上传凭证、进度 | `uni.chooseImage`、`uni.uploadFile` |
| `request` | 传输层：超时、取消、header 注入 | `uni.request` |
| `device` | 安全区、网络状态、系统信息 | `uni.getSystemInfoSync` |
| `h5`/`app` | 未来端差异的适配实现 | 浏览器/原生 |

- 每个能力定义窄接口，UI 只 import 门面（如 `platform/share`），不 import 具体端实现。
- 条件编译（`#ifdef MP-WEIXIN` 等）**只允许**出现在 `platform/` 内；页面/组件不得用条件编译模拟业务差异。
- 新增平台能力必须同时给出：小程序实现、H5 降级行为、失败返回、单测/手工验收步骤。
- ESLint 必须禁止 UI/domain/stores 直接使用宿主全局（目标配置）：对 `src/{pages,components,domain,stores}/**` 设 `no-restricted-globals: ["error","uni","wx","getApp","getCurrentPages"]`；`src/platform/**` 豁免。规则名以 W1 的 ESLint 配置为准，但效果不能缺。

### 4.4 API 层与类型

- 类型唯一来源：`packages/api-types/src/schema.ts`（openapi-typescript@7.6.1 生成）。业务代码只 import 包入口别名；禁止手写与契约重复的 interface，禁止 `any` 作为接口数据类型。
- 请求函数签名显式：`getPlan(id: string): Promise<PlanDetail>`；路径参数、query、body 类型都来自生成类型；错误用统一错误类型返回/抛出，不用字符串匹配。
- 鉴权：token 由 `platform/storage` 安全存取；请求层注入 `Authorization`；401 触发重新登录/刷新流程；admin 与 mini 使用不同 token 与 base URL，禁止混用。
- **幂等请求**：契约标记需要 `Idempotency-Key` 的写操作，前端必须为一次用户动作生成一个键（UUID/随机 ≥128bit），重试/弱网重发**复用同一个键**，成功或明确失败后再清；不得每次重试生成新键。
- **版本冲突**：写请求携带 `expectedVersion`；收到 412 时停止自动重试，提示「内容已更新」，重新拉取最新版本让用户确认；收到 409 时按 `code` 给出具体提示（进行中/状态不允许/幂等键冲突）。禁止静默覆盖或自动合并。
- 客户端不得写入可信字段：`sourceTag`、`coachCertified`、`evidenceLevel`、审核结果、作者归属、服务端只读 ID；服务端应忽略/拒绝（以契约与负向用例为准）。
- 响应解析：直接使用生成类型；对 `additionalProperties: false` 的请求严格构造对象，不多传字段。日期保持 ISO 字符串，在 `domain/` 格式化；金额保持分，在展示层转换。
- 重试：GET 可有限重试（超时/网络错误，≤2 次，指数退避）；写请求只允许用同一幂等键重试；不得对 4xx 自动重试。

### 4.5 状态管理（Pinia）

- store 只放跨页面/会话状态与动作；服务端事实不要在多个 store 复制。派生值用 getter（纯函数），不缓存可漂移的副本。
- 目录按域：`stores/session.ts`、`stores/profile.ts`、`stores/plan.ts` 等；每个 store 暴露明确的 actions，组件不直接改 state（`strict` 模式下禁止）。
- 登出/切换账号必须清空所有含个人数据的状态与本地缓存；健康相关缓存不落持久化存储（除契约明确允许的最小离线数据）。
- 页面局部状态用 `ref/reactive`；不要为了「以后可能共享」把一切塞进 store。
- store 中禁止调用 `uni.*`（经 `platform/`）、禁止直接发请求（经 `api/`）、禁止写 UI 提示（返回结果由页面展示）。
- 后台权限状态只用于渲染；实际授权以服务端响应为准；路由守卫失败时跳登录/无权限页，不能靠隐藏菜单保安全。

### 4.6 样式与 design tokens

- `packages/design-tokens/tokens.json` 是色彩、间距、圆角、字体、阴影、语义状态的唯一来源；生成 SCSS 变量（mini）与 TS 常量/CSS 变量（admin）。生成脚本必须可重复运行、两次结果字节一致（D01/U01 验收；tasks.json 的 `design/tokens.json` 归属见 E16）。
- 组件样式只允许使用 token 变量或语义类：禁止硬编码 `#RRGGBB`、`px/rpx` 魔法间距、随意 `box-shadow`。确需新值 → 提给设计任务改 tokens，不在页面里加。
- 语义 token 优先于原语 token：用 `color-text-primary`、`color-danger`、`space-4`，不直接用 `blue-500`。
- mini 使用 `rpx`（按设计稿 750 基准）；admin 使用 `px`；单位换算由 tokens 生成物提供，不在组件里手算。
- 全局样式只允许在 `styles/` 定义；页面/组件用 `scoped`。禁止覆盖组件库内部类名（如需覆盖，封装基础组件并说明原因）。
- 状态不能只靠颜色表达（草稿/已发布、AI 估算、信息不足、待复核、授权未开启等），必须有文案/图标/标签（开发计划 §10）。
- 组件库：mini 用 Wot Design Uni，admin 用 Element Plus；在 `components/base/` 做一层封装以隔离升级，不在业务页面散落库特有 class 或主题覆盖。

### 4.7 命名、文案与可访问性

- 英文标识符、中文用户文案；术语遵循 [CONTEXT.md](<../CONTEXT.md>)：用「服务关系」「数据授权」「发布确认」「信息不足」「饮食观察」，不用「绑定」「解锁」「审核通过=健康安全」等替代词。
- 文案不得暗示医疗诊断、疗效保证或平台收款；AI 结果必须标注「AI 生成/建议」并保留人工确认入口（PRD 与审核 R10）。
- 可访问性：可点击区域 ≥44×44pt（小程序按 88rpx 设计）；文字对比度达到设计系统要求；表单有 label/错误提示；动效支持减弱设置（H5/App）。
- 错误提示必须可操作：说明发生了什么、能否重试、下一步；不得只弹「系统错误」。

### 4.10 前端禁止事项

1. 页面/组件/stores/domain 直接调用 `uni.*`、`wx.*`、`getApp`、`getCurrentPages`。

8. 把客户端字段当作可信来源（来源标签、认证、证据等级、审核结果）。
9. 引入全量图表/日期/工具库；主包超 2 MB；大图/视频进包。
10. 在页面里复制后端业务规则（热量处方、过敏判定、异常筛查）；只做展示与即时提示。

## 5. 测试策略

原则：**测试证明行为，覆盖率只作下限；关键负向用例是硬要求。** 能用一条负向用例证明的越权/串号/撤权问题，不能用十个快照测试代替。

### 5.1 分层与归属

| 层 | 位置 | 运行时机 | 依赖 | 证明什么 |
|---|---|---|---|---|
| 单元（Go） | 各模块 `*_test.go`、`internal/rules/*_test.go` | 每次提交 | 无 DB/网络，时钟注入，AI 用 fake | 规则、状态机、映射、边界 |
| 单元（TS） | `src/domain/**/*.test.ts`、`src/api` 解析函数 | 每次提交 | Node/JSDOM，mock `platform` | 计算、格式化、错误映射 |
| 组件测试 | `apps/mini`、`apps/admin` 邻近 `*.spec.ts` | 每次提交 | `@vue/test-utils` + Vitest | 基础组件 props/emits/状态 |
| 契约静态回归 | `api/tests/` | 每次提交 | Python 3.11 + 固定依赖 | 契约结构、正反例、operationId |
| 集成 | `apps/api/test/`（`//go:build integration`） | 每次 PR（CI service 容器） | 真实 MySQL 8 + Redis 7 | 迁移、repo、事务、CAS、幂等、授权 |
| API E2E | `tests/e2e/`（旧 `tools/e2e/` 见 E15） | 合并前 / nightly | 起服务 + 真实 DB/Redis | 两条闭环 + 失败/恢复 |
| 性能 | `tests/perf/`（k6） | 里程碑 / nightly | 预发环境 | P95、AI 独立预算 |
| 视觉/多端 | `docs/evidence/` 清单 + 真机 | 每批 / 里程碑 | 微信开发者工具 + 真机 | 四态、tokens、可用性 |

### 5.2 契约测试（api/tests）不可削弱

现有基线（2026-10-23 实测）：当前契约 OpenAPI 1.2.0（SHA `5ec5ff6cfb4abd08194e11c052d7a743700c80c482f9837633b63d98176aac8d`）**72 个测试方法通过，0 failure/error/skip**；同一套测试对旧稿必须保持 RED（历史证据见 [api/tests/README](<../api/tests/README.md>)、[当前状态](<CURRENT_STATE.md>)）。

**禁止**：

1. 删除/跳过/`xfail` 既有断言；用更宽的正则、`additionalProperties: true`、去掉 `required`、放宽 enum/oneOf 让样例变绿。
2. `|| true`、`continue-on-error`、只跑部分文件、在 CI 里用 `if: always()` 掩盖失败。
3. 只改 `api/tests/operation_ids.json` 而不改实际 `operationId`（或反之）；重命名/删除既有操作必须显式评审。
4. 用从 schema 自动生成的「必过样本」替代独立合成反例；数值样例当成健康建议/阈值。
5. 修改 `api/openapi.yaml` 后不新增对应用例；契约测试文件变更必须由 Contract Steward 复核。

**要求**：每个新增/修改的契约点至少 1 个正例 + 1 个负例（缺字段、错类型、越权伪造字段、非法枚举、空值语义）；先对旧稿 RED、再对新稿 GREEN。契约测试只证明静态约束，**不替代**运行时授权、并发与事务测试（api/tests/README「尚未验证的风险」）。

### 5.3 单元测试

- 表驱动优先；每个子用例有独立名称，失败信息包含输入与期望。
- 注入时钟（`pkg/clock` 或函数参数），禁止 `time.Sleep` 推进时间；禁止真实网络、真实 AI、真实微信。
- `internal/rules`：每条规则码至少 1 个正例 + 1 个反例 + 边界（空数据、信息不足、未知过敏原、极端数值、版本退役）。规则输出必须包含 `rule_version`；测试固定版本，不能随实现悄悄变化。
- 发布/授权：幂等键解析、hash 规范化、状态机转换、字段来源过滤、可见性/确认失效必须有单测。
- 前端 `domain`：所有展示计算（单位换算、分页游标、状态标签、空态判定）单测；不测样式细节。
- 测试数据合成：虚构姓名、动作、食物、份量；**不得使用真实用户健康数据或真实个人信息**。

### 5.4 集成测试（真实 MySQL/Redis）

- 使用 `infra/compose/` 的固定版本 MySQL 8 + Redis 7（F01 建立；或等价 testcontainers-go 编排；二选一，但 CI 必须真实数据库）；连接串走测试环境变量，不连开发/生产库。
- 每个用例使用独立库/前缀并在结束时清理；迁移在空库执行 up → down → up，验证可重入。
- 必须覆盖：CAS 并发（两写一成功）、首次 `expectedVersion=0` 并发、幂等重放/异摘要/processing、撤权与结束关系原子性、旧客户端重放、唯一键冲突映射、事务回滚、死锁重试。
- 授权负向：跨学员/跨教练/跨关系、猜测 ID、结束/撤权后读取、`profile` scope 不得带出身体/伤病/饮食/过敏、通知/摘要/签名 URL 不能绕过。
- 后台任务：任务重查授权、重复执行不产生二次副作用、失败重试与死信。
- 测试必须可在 CI 无人工干预运行；跳过集成测试不算通过（除非该 PR 明确不涉及后端且经 Lead 批准）。

### 5.5 E2E 与性能

- API E2E 覆盖两条闭环（以 [API 说明 §2–3](<../api/README.md>) 与 [APP_FLOW](<APP_FLOW.md>) 为准）：
  1. 登录 → 建档 → 咨询 → 教练发起关系 → 学员确认 → 授权 → 教练建/发布计划 → 学员读取 → 训练记录 → 点评。
  2. 浏览公开模板 → 另存 → 编辑训练/饮食 → AI 预填草稿 → 确认 → 提交审核 → 分享/广场 → 按版本打卡 → 信息不足路径。
- 每条闭环必须有：正常、空数据、失败与恢复（412/409/429/503、网络中断、重复提交）、无权访问。
- 小程序：手工清单覆盖首次路径、返回、弱网、授权拒绝、订阅消息拒绝；可选自动化工具需单独评审，不能把「开发者工具能跑」当验收。
- 性能：k6 基线分开测量普通接口与 AI 请求；报告给 P50/P95/P99、错误率、并发数与环境说明；阈值见 §9。
- E2E/性能脚本列入版本库（`tests/e2e/`、`tests/perf/`），不把一次性脚本留在 `.review/`。

### 5.6 覆盖率：务实目标

| 范围 | 目标 | 门槛性质 |
|---|---|---|
| `internal/rules` | 行/分支 ≥80%，且每条规则码有正反例 | **硬门槛**（开发计划 §12） |
| 安全关键 service（auth/relation/grant/publish/delivery/idempotency） | 分支 ≥70%（目标 80%） | 硬门槛 ≥60%；低于需 PR 说明 |
| 其他 Go service/repo | 行 ≥60%（目标） | 参考，不单独阻断 |
| `domain`（TS） | 行/分支 ≥80% | 硬门槛 |
| 基础组件/关键交互 | 关键 props/emits/状态转换有测试 | 人工评审 |
| 页面/视觉 | 不设覆盖率门槛 | 用走查清单 + E2E |

- 覆盖率命令：`(cd apps/api && go test ./... -coverprofile=coverage.out && go tool cover -func=coverage.out)`；前端 `pnpm --dir apps/mini exec vitest run --coverage`、`pnpm --dir apps/admin exec vitest run --coverage`。阈值写进配置，PR 不得下调。
- **覆盖率不得替代**以下必测项：越权读写、撤权即时生效、412/409、幂等重放、事务原子、404 隐藏存在性、健康字段不泄露、AI 信息不足、伪造可信字段、过期 token/audience 混用、上传类型/大小拒绝、限流 429。

### 5.7 每个模块的最低测试清单

模块名以当前任务 DAG 的 `write_allowlist` 为准（§1.4）。下表是**最低**要求；任务卡或风险分析可以加，不能减。

| 模块 | 单元必测 | 集成/负向必测 |
|---|---|---|
| `middleware`/`server` | requestId、错误映射、鉴权上下文注入、幂等适配器、未知路由 | 401/403/404、请求校验、schema 漂移、并发幂等 |
| `auth` | 微信 code2session 成功/失败、JWT 签发/校验、audience 隔离、token_version 失效 | 用户 token 访问后台、过期/吊销 token、禁用账号、角色不升权 |
| `user` | 年龄声明、最小档案、伤病只写不回显、null 清除、采集同意/撤回 | 无同意写敏感资料、public 档案不含健康、跨用户读写 |
| `relation` | 发起/确认状态机、termsHash、offeredVersion、撤权/结束原子性 | 错 hash 412、非本人确认、结束与授权并发、旧版本复活 |

| `privacy` | 删除/导出任务、撤回同意、墓碑 | 撤权后仍被读取、备份恢复后复活、删除不彻底 |

### 5.8 测试质量与稳定性

- 测试名描述行为；一个测试一个主题；断言给出可读上下文。禁止 `sleep` 等待异步、依赖执行顺序、共享可变全局状态。
- 时序/并发用例使用同步原语（channel/barrier）而非固定 sleep；必要时 `-count=10` 验证稳定性。
- flaky 测试必须标 Issue、3 天内修复；不得长期 skip。修复前不得合并依赖它的功能。
- 契约/集成/E2E 失败优先修复实现，不改测试期望；确属测试错误的修改必须在 PR 说明原因并请 Reviewer 确认。

### 6.4 文档与配置校验

```bash
# Markdown 代码块配对（本仓所有 md，排除历史缓存）
python3 - <<'PY'
from pathlib import Path
bad = []
for p in Path('.').rglob('*.md'):
    if any(part in {'.review', '.pnpm-store', 'node_modules', 'dist'} for part in p.parts):
        continue
    fences = sum(1 for line in p.read_text(encoding='utf-8').splitlines()
                 if line.lstrip().startswith('```'))
    if fences % 2:
        bad.append((str(p), fences))
print('unbalanced fences:', bad)
raise SystemExit(1 if bad else 0)
PY

# YAML 可解析（OpenAPI 另由 redocly 校验；此处防基础语法错误）
api/tests/.venv-py311/bin/python -c \
  "import yaml; yaml.safe_load(open('api/openapi.yaml', encoding='utf-8')); print('yaml ok')"

# 文档链接可达：同时支持「相对当前文件」与「相对仓库根」两种写法；
# 跳过外链、绝对路径、带行号的引用（历史审核记录）与 .review/ 证据。
python3 - <<'PY'
import re
from pathlib import Path
root = Path('.').resolve()
bad = []
for p in root.rglob('*.md'):
    if any(part in {'.review', '.pnpm-store', 'node_modules'} for part in p.parts):
        continue
    text = p.read_text(encoding='utf-8')
    for m in re.finditer(r'\]\(<?([^)<>]+)>?\)', text):
        target = m.group(1).split('#')[0].strip()
        if not target or target.startswith(('http://', 'https://', 'mailto:', '/')):
            continue
        if re.search(r':\d+(?:-\d+)?$', target) or target.startswith('.review/'):
            continue
        if not ((p.parent / target).resolve().exists() or (root / target).exists()):
            bad.append(f"{p.relative_to(root)} -> {target}")
print('dead links:', bad)
raise SystemExit(1 if bad else 0)
PY
```

### 6.5 CI 必须执行的 job（目标：W1 建立，未建立前不得声称有 CI）

| Job | 触发 | 必须执行 | 阻断条件 |
|---|---|---|---|
| contract | 所有 PR | `make contract-check`、`make codegen-check`；`scripts/plan.py check`；生成物 `git diff --exit-code` | lint error、回归失败、生成物未提交、任务 DAG 非法 |
| backend | 改 `apps/api/**` | `make check-foundation`、`make test MODULE=...`、相关 `make test-integration MODULE=...` | 任一失败 |
| frontend | 改 `apps/client/**`（或 `apps/mini/**`，E15）、`apps/admin/**`、`packages/**` | `make typecheck-client`、`make test-client FEATURE=...`、`make build-client`、`make visual-ui` | 类型错误、测试失败、超预算、视觉阻塞 |
| docs | 改 `docs/**`、`AGENTS.md`、`README.md`、`CONTEXT.md` | markdownlint、代码块配对、链接检查、`scripts/plan.py check`、术语一致性人工复核 | 结构/死链/任务图失败 |
| security | 所有 PR | `govulncheck`、依赖审计、密钥扫描（工具在 W1 固定版本） | 高危漏洞、疑似密钥 |
| e2e/perf | 合并到 `main` 或 nightly | `make e2e BATCH=...`、`make security-negative BATCH=...`、k6 基线 | 闭环失败、越权用例失败或超 §9 阈值 |

- CI 禁止 `continue-on-error: true`、`|| true`、跳过 job、只对文档失败放行。
- 分支保护：`main` 必须有上述 required checks、至少 1 个 Reviewer（契约/迁移/权限改动 2 个）、禁止 force-push 与直推。
- 缓存 key 与镜像 tag 必须固定；CI 中的工具版本与本文一致，升级需单独 PR + 全量回归。

### 6.6 提交前自检与 CI 的关系

- 可选 pre-commit 只做快速格式化/明显错误；**不能替代 CI**，也不能自动修改后静默提交。
- 本地至少跑：`scripts/plan.py check` + 与改动相关的 lint/单测/契约/集成命令；PR 描述附命令与结果。
- 如果本地无法运行（无 Docker/无网络），必须在交付说明写清缺失验证；不得用 CI 通过代替功能负向验证。

## 7. Git 与协作

Git 尚未初始化（F01 负责）。以下规则在首次提交前建立，之后不得绕过；与[多 Agent 协作规范](多Agent协作规范.md)冲突时，以更严格者为准。

### 7.1 仓库初始化（F01）

- `git init -b main` 后先提交基线：`.gitignore`、`.editorconfig`、`README.md`、`AGENTS.md`、`CONTEXT.md`、`api/`、`docs/tasks/`、`scripts/`、`backlog/`（历史任务板）、`docs/`（不含缓存、虚拟环境、密钥）。
- `.gitignore` 至少包含：`.review/`、`.pnpm-store/`、`node_modules/`、`dist/`、`build/`、`*.log`、`.env*`（示例文件除外）、`api/tests/.venv*/`、`__pycache__/`、`apps/api/coverage.out`、本地数据库数据目录。
- `.editorconfig`：UTF-8、LF、行尾空白清理、Go 用 tab、Web 用 2 空格。
- `docs/adr/` 模板与命名规则由 F01 建立（见 §8.2）；`docs/tasks/tasks.json` 与 `scripts/plan.py` 是当前任务/校验入口（E17）。
- 被文档引用的**契约证据**（如 `api/tests/results.json`）必须入库；`.review/` 是本地复核产物，按规则忽略，不把大日志/工具链提交。
- 首个提交后开启分支保护（§7.6）；Git 初始化完成前，不得以「没有 Git」为由跳过快照/回滚说明。

### 7.2 分支模型（trunk-based）

- `main` 始终可构建、可部署；禁止长期 `develop`/`release` 分支。
- 一个任务一个短分支：`task/<任务ID>-<slug>`（例：`task/REL-02-grant-cas`），生命周期 ≤2 天；超过则拆任务。
- 开发中定期 rebase 到最新 `main`；合并前必须 rebase 并重跑自检（协作规范 §6）。
- 发布用 tag（`release-YYYYMMDD-N`）与镜像 digest 标识，不靠分支名区分环境。
- 只在自己的分支上 force-push；**`main` 禁止 force-push、禁止直推、禁止删除**。

### 7.3 提交规范（Conventional Commits）

格式：`<type>(<scope>): <subject>`，subject 用祈使句、≤72 字符、不加句号；正文写「为什么」与影响面。

| type | 用途 |
|---|---|
| `feat` | 新增能力 |
| `fix` | 修复缺陷 |
| `test` | 测试新增/修正 |
| `refactor` | 不改变行为的重构 |
| `perf` | 性能优化 |
| `docs` | 文档 |
| `chore` | 构建、依赖、工具 |
| `contract` | 契约与生成物 |
| `migrate` | 数据库迁移 |
| `security` | 安全修复（不得在标题泄露细节） |

- scope 使用域/应用：`api`、`mini`、`admin`、`contract`、`db`、`ai`、`docs`、`ci`、`deps`。
- 破坏性变更：`feat(contract)!: ...`，正文必须有 `BREAKING CHANGE:` 段，说明影响、迁移与审批人。
- 一次提交一件事；禁止把格式化、重构、功能混在一个提交。生成物单独提交：`chore(gen): regenerate types from contract`。
- 禁止 `WIP`、`fixup`、临时调试提交进入 `main`（合并前 squash）。

示例：

```text
feat(relation): confirm service relation with frozen terms

Requires expectedVersion and termsHash from the offer snapshot.
Rejects stale versions with 412 and re-checks student ownership
inside the transaction. Adds integration cases for concurrent confirm.
```

### 7.4 Pull Request

- **规模 ≤400 行改动**（不含生成物、lockfile；迁移与测试计入）。超过需拆分；确需例外由 Lead 在 PR 说明并指定 Reviewer。
- 标题含任务 ID：`[REL-02] confirm relation with CAS`；描述使用任务卡 `deliverables`/`acceptance`，并附：
  - 改动范围与不在范围；
  - 验证命令与结果（含失败数、退出码）；
  - 契约/迁移/权限/视觉 tokens 影响；
  - 风险与回滚方案；
  - 截图/录屏（UI 变更）；
  - 未完成项与原因。
- 生成物 diff 过大时单独 PR；契约 PR 必须包含：`api/openapi.yaml`、`api/tests/` 新用例、生成物、说明文档（`api/README`/ER 对照）。
- PR 未通过 CI 不得请求 Review；Review 通过后作者不得自行合并（由 Lead 或指定集成者合并）。
- 关闭/放弃的 PR 写清原因；不把半成品长期挂在 `main` 之外。

**PR 描述模板**（建议 F01 后落库为 `.github/pull_request_template.md`，内容不得省略验证与影响面）：

```markdown
任务：<ID> <title>
改动：<文件列表/目录>
不在范围：<明确不做什么>

验证：
- <命令> → <退出码/失败数/关键输出>
- <命令> → ...

契约/迁移/权限/视觉 tokens 影响：<无 或 具体说明 + 审批人>

截图/录屏：<UI 变更必填>

```

### 7.5 Review checklist（默认必查）

| # | 检查项 | 不通过示例 |
|---|---|---|
| 1 | 契约一致：路径/字段/状态码/错误码与 OpenAPI 一致 | 自造字段、返回 200 代替 412 |
| 2 | 对象级授权：主体、归属、关系、scope、版本逐层校验 | 只校验登录，不校验资源归属 |
| 3 | 负向用例：越权、撤权、404 隐藏、猜 ID、过期 token | 只有 happy path 测试 |
| 4 | 版本与幂等：expectedVersion CAS、幂等键、409/412 语义 | 失败后自动重试覆盖 |
| 5 | 事务边界：原子提交、事务内无外部调用、审计同事务 | 先返回成功再补写 |
| 6 | 迁移安全：向前兼容、down/补偿、索引与锁、N-1 兼容 | 与代码同版删列 |
| 7 | 敏感数据：日志/错误/审计/trace 不含健康正文与令牌 | 打印完整请求体 |
| 8 | 前端边界：页面不调 `uni.*`、类型来自生成、无魔法值 | 页面里 `uni.request` |
| 9 | 测试有效性：新增测试能否在旧实现上失败 | 只加快照或断言恒真 |
| 10 | 生成物与文档：生成已更新、README/ADR/术语同步 | 生成物未提交 |
| 11 | 性能：列表分页/索引、无 N+1、无阻塞外部调用 | 循环查库 |
| 12 | 回滚：镜像回退、迁移补偿、开关/灰度 | 无法回退的破坏性变更 |

- 契约、迁移、权限模型、AI 模型/密钥、CI 规则变更需要**两名** Reviewer（其中一名 Contract Steward/Lead）。
- Reviewer 必须独立复核证据，不只看作者描述；发现问题退回 `in_progress` 并写清复现方式。
- 禁止作者自我批准、禁止用「口头同意」代替 Review 记录。

### 7.6 合并与分支保护

- 只允许 squash merge，保持 `main` 线性历史；合并后删除任务分支。
- 合并顺序：契约/迁移/生成物 → 依赖它们的实现 → 该波 `tail` 接线；同波次冲突由后合者 rebase 解决并通知先合者（协作规范 §6）。
- `main` 必需状态检查：contract、backend（如涉及）、frontend（如涉及）、docs（如涉及）、security；禁止跳过。
- 合并前确认：任务板状态为 `review`、CI 全绿、Reviewer 通过、无跨作用域修改。
- 回滚：优先 revert 合并提交（新增迁移用补偿脚本，不直接回滚已应用迁移）；线上事故用镜像回退，见 §9.6。

### 7.7 发布与 hotfix

- 发布从 `main` 的 tag 构建；镜像 tag 使用 git SHA + 环境，保留最近 3 个可回滚版本（架构文档 §10）。
- 发布前：迁移兼容检查、契约回归、关键闭环 E2E、备份确认、回滚步骤演练。
- hotfix 从 `main` 开 `task/HOTFIX-*`，走同一套检查与 Review；完成后合并回 `main`，不长期维护补丁分支。
- 事故后 48 小时内补事故记录：时间线、影响、根因、修复、防复发任务；不把「已修复」当复盘。

### 7.8 Agent 协作（与任务板一致）

- 任何实现前：读 `AGENTS.md`、[当前状态](<CURRENT_STATE.md>)、任务卡（`docs/tasks/tasks.json`）、相关规范与契约；确认 `depends_on` 全部 accepted、`write_allowlist` 无冲突（§7.8 的「scopes」同指写作用域）。
- 只改 `scopes` 内文件；共享文件（`api/`、`routes.go`、`modules.go`、`go.mod`、依赖清单、`tokens.json`、迁移）未持有时停止并上报。
- 工作按 D12：原生 Agent + 任务 DAG + 文件所有权 + 隔离 worktree + 串行集成；不得自行合并、不得自动改写他人分支。
- 领取/状态/证据格式按[多 Agent 协作规范](多Agent协作规范.md) §7–§8；完成后把任务板改为 `review`，交付说明含命令与结果。
- 遇到 `FS_STALE_VERSION`：重新读取并基于新内容重做，不覆盖他人修改；无法合并时停下报告（协作规范 §9）。

### 8.2 ADR：何时写、怎么写

**必须写 ADR**（难以逆转 + 有真实替代方案 + 未来读者会问「为什么」）：

- 破坏性契约变更（路径/字段/语义/状态码）、接口版本化与弃用策略；
- 数据库破坏性迁移、软删除唯一性方案、数据保留/删除策略；
- 权限模型、audience、授权 scope、关系状态机变化；
- 引入/替换第三方依赖、AI 供应商/模型/档位、加密与密钥方案；
- 幂等窗口、成本熔断阈值、审核抽检比例等需要解释的运行时策略；
- 基础设施与部署形态变化（单机 Compose、队列、存储）。

**不写 ADR**：可逆的小重构、样式调整、任务拆分、一次性排期。

**位置与命名**：`docs/adr/NNNN-kebab-title.md`（NNNN 四位递增，不复用；模板由 F01 建立）。建议结构：

```markdown
# ADR-0007 服务关系结束与授权撤回的原子边界

- 状态：proposed | accepted | superseded by ADR-00xx | rejected
- 日期：2026-10-23
- 决策者：Lead / Contract Steward / 安全负责人
- 关联：任务 REL-02、契约 /relations/{id}/end、ER §4.4

## 背景与约束
## 决策
## 备选方案与取舍
## 后果（正向/负向、可逆性）
## 迁移与验证
## 重开条件
```

- 已接受 ADR 不重写；变更用新 ADR 并标 `superseded`。
- ADR 必须写「未选方案」与「重开条件」，否则只是公告，不是决策记录。
- 破坏性变更的 ADR 必须包含数据/客户端迁移和回滚方式。

### 8.3 每个应用的 README 必备内容

`apps/api`、`apps/mini`、`apps/admin`、`packages/*` 各自 README 必须回答：

1. 这个应用是什么、当前状态（脚手架/可用/试点）与负责人。
2. 前置条件与固定版本（Go/Node/pnpm/微信开发者工具/数据库）。
3. 本地启动、环境变量（指向 `.env.example`，不写真实值）、依赖服务。
4. 如何跑测试、lint、构建、生成物；对应 CI job。
5. 目录结构与分层（链接本文 §1、§4）。
6. 数据边界与授权模型摘要（哪些数据敏感、如何鉴权）。
7. 已知限制与未实现能力（明确写「未实现」，不写「后续支持」了事）。
8. 发布/回滚步骤或指向 `docs/ops/` 手册。
9. 变更记录（§8.6）。

### 8.4 契约变更流程

**顺序固定，不可颠倒**（协作规范 §5）：

1. 由 Contract Steward 在独立任务中修改 `api/openapi.yaml`；破坏性变更先获 Lead 批准并写 ADR。
2. 同步 `api/tests/`：新增/修正正反例，先确认旧稿 RED、新稿 GREEN；必要时更新 `operation_ids.json` 并说明理由。
3. 更新 [api/README](<../api/README.md>) 的调用顺序、错误/幂等/版本语义；数据模型变化同步 [ER](<数据模型与ER设计.md>) 与映射表。
4. 运行校验并保留输出：`redocly lint` 0 error、契约静态回归全绿（当前 OpenAPI 1.2.0，72 方法）。
5. 重新生成 TypeScript（openapi-typescript@7.6.1）与 Go（oapi-codegen v2.4.1），提交生成物。
6. 实现层按生成类型改代码；不得手改生成物或私自定义字段。
7. PR 描述标明：兼容性（新增/破坏）、受影响客户端、迁移/弃用窗口、回滚方式。
8. 合并顺序：契约 → 生成物 → 实现；`tail` 接线最后。

**兼容性判定**

| 变更 | 判定 | 要求 |
|---|---|---|
| 新增可选字段/新路径/新枚举值（客户端可忽略） | 非破坏 | 仍需契约 Review；客户端兼容性说明 |
| 新增必填请求字段、删除/重命名字段、收紧校验、改语义/状态码 | 破坏 | Lead 批准 + ADR + 迁移/版本化；未上线期可修订但须重跑全部回归 |
| 改 `operationId`、删除操作 | 破坏 | 显式评审 + 更新 `operation_ids.json` + 客户端发布计划 |
| 仅描述/示例修正 | 非破坏 | 保持生成物不变或可复现 |

- URL 大版本（`/v1`）在破坏性且无法兼容时升级；旧版本至少保留一个客户端发布周期，并写弃用时间表。
- 公开接口的 `Error.code` 新增/改名按契约变更处理（§2.4、附录 B）。
- **契约未投产**（当前状态）允许直接修订，但必须保留历史证据与 SHA，不能假装旧稿已兼容。

### 8.5 CONTEXT.md 词汇维护

- 一词一义：每个概念一个规范词，格式沿用现有 `**术语**：定义` + `_Avoid_：`。
- 新增词条前先确认：概念在 PRD/契约/代码中真实存在、不是实现细节、不会与既有词冲突。
- 规范词必须落到：契约字段名、Go/TS 标识符、UI 文案、测试名称；不允许文档一套、代码一套。
- `_Avoid_` 中的词禁止作为公开文案或标识符出现；发现同义词在代码中扩散，先改词表再改代码。
- 重命名术语 = 影响契约/接口/UI 的变更，需 ADR 或契约评审；不得只改文档。
- 词表不写实现方案、不写营销口号；有争议的概念先讨论再入库，不靠「以后解释」。

### 8.6 变更记录与历史文档

- **契约变更**：记录在 [api/README](<../api/README.md>) 的版本说明 + PR + 生成物 diff；破坏性变更另写 ADR。
- **产品/工程决策**：短决策进 [DECISION_LOG](<DECISION_LOG.md>)（D 编号，含未选方案与重开条件）；需要解释的长决策进 ADR。
- **应用变更**：各 app README 的「变更记录」段，格式：`YYYY-MM-DD · 版本/范围 · 影响 · 迁移/回滚`。
- **文档版本**：长文档头部保留版本与日期；修改时更新版本，不静默改结论。
- **历史文档不可改写**：审核报告、复核记录、修复对照保留原貌；如口径变化，新建文档或加「历史快照」横幅并链接新结论。不得把旧失败记录改成通过。

### 8.7 文档质量门

- 结构：标题层级不跳级；长文档开头说明「这一节能回答什么」（协作规范 §11）。
- 格式：代码块配对、表格有表头、链接可达、YAML 可解析；命令固定版本、可直接复制。
- 事实：区分「已实现/已验证」与「目标/必须遵守」；引用外部事实给来源与日期；不把估算写成报价，不把契约通过写成运行时通过。
- 术语：与 CONTEXT 一致；中英文混排规范；时间用绝对日期与 UTC 标注。
- 安全：文档不含真实密钥、个人健康数据、可复用的签名 URL。
- 更新：新增文档必须加到 [README 文档索引](<../README.md>) 或对应子索引；删除/迁移文档需更新所有引用。

## 9. 性能与可观测性预算

### 9.1 预算总表

预算按**接口类别**定义，不能把普通接口的 500ms 套到 AI 生成请求（[审核 R10](../docs/方案审核-2026-10-23.md)、[开发计划 §12](<开发计划-v1.0.md>)）。

| 类别 | 指标 | 目标 | 测量点/说明 |
|---|---|---|---|
| 普通同步接口（非 AI） | 服务端 P95 | ≤500ms（PRD） | 服务端中间件；不含网络与客户端渲染；P99 ≤1000ms 为工程目标 |
| 普通接口错误率 | 5xx 比例 | <0.5%（5 分钟窗口） | 指标告警；不含客户端 4xx |
| 列表接口 | 单次响应体 | ≤200 KB（目标） | pageSize ≤50；大字段按需返回 |
| AI 短请求 | P95 / P99 | ≤8s / ≤15s | `/ai/chat`、`/ai/interpret`、`/ai/analyze`、`/coach/ai/comment-draft` |
| AI 长请求 | P95 / P99 | ≤30s / ≤45s | `/coach/ai/plan-draft`、`/coach/ai/weekly-report` |
| AI 请求超时 | 单次上游 / 总预算 | 12s / 20s（短）；25s / 55s（长） | 客户端超时：短 30s、长 60s；超时返回 `503 UPSTREAM_UNAVAILABLE` 并记录 `ai_run` |
| AI 失败率 | 失败/总调用 | ≤5%（正常），>20%（5 分钟、≥20 次）触发熔断 | 熔断见 §9.5 |
| 异步任务 | 入队 / 排队 / 执行 | 入队 P95 ≤100ms；排队 P95 ≤30s（通知类）/≤5min（重任务）；单任务 ≤60s | asynq；重试 ≤5 次，指数退避 + 抖动；死信告警 |
| 小程序首屏 | 内容可见 / 可交互 | ≤1.5s（PRD）/ ≤2.5s（目标） | 中端 Android + 4G 冷启动；详见 §4.8 |
| 后台首屏 | 内容可见 | ≤3s（PRD 工作台） | 生产构建；初始 JS ≤300 KB gzip（目标） |
| 数据库 | 单查询 P95 / 慢查询 | ≤50ms / >200ms 告警 | OLTP；慢日志 + 指标；列表必须有索引 |

- AI 预算是**工程目标**，需在 AI-01 用真实供应商延迟实测后校准（当前契约 AI 接口为同步 200 响应，见 openapi.yaml `/coach/ai/*`、`/ai/*`）。若真实延迟无法满足，必须由 Lead 决定调预算或改契约为异步，**不得**在实现里静默改成异步或无限延长超时。
- 所有预算在 `tests/perf/` 有对应 k6 场景；结果记录到 `docs/evidence/`，注明环境、并发、数据量与构建版本。
- 性能回归不作为单次 PR 的硬门（避免噪声），但里程碑必须复测；明显退化（P95 +30%）需说明或修复。

### 9.2 指标（Metrics）

命名 `nerae_<domain>_<name>`，标签低基数（**禁止** user_id、关系 ID、原始路径）。至少采集：

| 指标 | 类型 | 标签 | 用途 |
|---|---|---|---|
| `nerae_http_requests_total` | counter | `route`（模板化）、`method`、`status_class` | RED 指标 |
| `nerae_http_request_duration_seconds` | histogram | `route`、`method` | P50/P95/P99 |
| `nerae_db_query_duration_seconds` | histogram | `operation`、`table`（白名单） | 慢查询定位 |
| `nerae_db_pool_in_use` / `_wait_total` | gauge/counter | — | 连接池饱和 |
| `nerae_redis_errors_total` | counter | `op` | 缓存/队列异常 |
| `nerae_asynq_queue_depth` | gauge | `queue` | 积压告警 |
| `nerae_asynq_job_duration_seconds` | histogram | `task`、`outcome` | 任务健康 |
| `nerae_idempotency_replays_total` | counter | `result`（replay/conflict/in_progress） | 幂等协议 |
| `nerae_version_conflicts_total` | counter | `resource` | 客户端版本问题 |
| `nerae_ai_calls_total` | counter | `scene`、`model`、`outcome` | 成功率 |
| `nerae_ai_latency_seconds` | histogram | `scene`、`model` | 独立预算 |
| `nerae_ai_tokens_total` | counter | `scene`、`direction`（in/out） | 成本 |
| `nerae_ai_cost_cents_total` | counter | `scene`、`model` | 预算与告警 |
| `nerae_ai_fallback_total` | counter | `scene`、`reason` | 降级可观测 |
| `nerae_ai_circuit_state` | gauge | `model` | 0 关闭 / 1 半开 / 2 打开 |
| `nerae_moderation_backlog` | gauge | `status` | 审核积压 |
| `nerae_audit_write_failures_total` | counter | — | 审计不可丢 |

- 路径标签必须模板化：`/v1/relations/{id}/grants`，不能带真实 ID。
- 每个新接口上线必须同时加请求量/延迟/错误指标；关键失败模式必须有告警，否则不算完成（§11）。
- 仪表盘与告警规则由 OPS-03 落到 `docs/ops/`，至少覆盖：API 健康、AI 成本/质量、队列积压、审核积压、数据库连接、备份/证书。

### 9.3 日志

字段与脱敏见 §2.7 与附录 C。补充：

- 访问日志只记录模板化路由、状态码、耗时、`request_id`、主体类型；**不记录**请求/响应体。
- 业务关键事件（登录、关系确认、授权变更、发布、审核、后台敏感访问）必须可审计；应用日志记事件与 ID，正文进数据库审计表，不进日志。
- 错误日志保留堆栈（5xx），4xx 不刷屏；相同错误限流采样。
- 日志保留期、审计保留期、普通通信历史可见性**尚未核定**（ER §13），实现不得自定「永久保留」；先按配置实现并标注待核定。

### 9.4 追踪（OpenTelemetry）

- 全链路使用 W3C `traceparent`；HTTP 入口创建 server span，DB/Redis/外部调用创建 client span；`request_id` 与 `trace_id` 同时返回/记录，便于对齐。
- span 名称：`HTTP POST /v1/relations/{id}/confirm`、`DB UPDATE service_relation`、`AI plan-draft`、`ASYNQ comment-notify`。
- span 属性只放低基数、非敏感值（`http.status_code`、`db.table`、`ai.scene`、`ai.model`）；**禁止**健康正文、token、openid、prompt 全文。
- 采样：错误 100%，成功目标 5%（可配置）；采样不能影响错误与成本统计（指标独立计数）。
- 追踪不可用时降级为仅 `request_id`，不得因 collector 故障阻塞业务。

### 9.5 AI 成本计量、额度与熔断

**计量（每次调用一条 `ai_run`）**：场景、模型与版本、prompt 版本、输入/输出 token、当时单价快照、`cost_cents`、延迟、结果（ok/schema_invalid/upstream_error/blocked）、是否降级及原因、是否重试、关联主体与资源 ID（不存健康正文）。

- 单价按供应商官方页与[开发计划 §13.1](<开发计划-v1.0.md>) 的快照配置（MiMo v2.6 Flash，2026-10-23：缓存命中输入 ¥0.02/百万 token、未命中输入 ¥1/百万、输出 ¥2/百万）；**价格变动只改配置并留生效日期，不写死在代码里**。
- 成本公式固定：`Σ(输入 token × 输入单价 + 输出 token × 输出单价) + 重试成本 + 审核/存储成本`；缓存命中单独统计。
- 估算参考（不是报价）：免费问答约 ¥0.004/次、计划生成约 ¥0.012/次（开发计划假设 3,000+500 / 8,000+2,000 token）；用于预算与回归，不作为真实账单。

**额度**

- 用户维度：日/月调用次数与 token 上限（Redis 计数，TTL 对齐窗口）；场景维度：单场景并发与日预算；全局维度：日预算硬上限。
- 超限返回 `429` + 明确 `code`；全局预算达到 100% 时按配置**硬停**或降级为规则/模板（不得静默继续烧钱）。
- 50% / 80% / 100% 阈值告警；高使用用户单独统计，不用平均值掩盖（审核 R10）。

**熔断与降级**

- 触发：连续 5 次失败，或 5 分钟内错误率 >20% 且样本 ≥20；打开 60 秒，半开只放 1 个探针。
- 重试：同一模型最多 1 次（受总预算约束）；超时/5xx 才重试，schema 不合法不盲目重试。
- 降级顺序：同模型重试 → 规则/模板/静态说明 → 明确提示稍后重试或人工继续。**不自动升档、不自动切换供应商**（[DECISION_LOG D11](<DECISION_LOG.md>)、api/README §1、用户约束）。
- 若实现供应商适配器用于「降级备」，默认必须关闭自动切换；启用属于配置变更，需 Lead 决策并记录（附录 E5）。
- AI 输出必须：过 JSON Schema 校验、过规则包、经人工确认才可发布；失败时保留待补字段与信息不足状态，不编造完整内容。

### 9.6 告警、运行与回滚

| 告警 | 条件（建议初值） | 动作 |
|---|---|---|
| 5xx 升高 | >0.5% 持续 5min 或 >5% 持续 1min | 值班查日志/最近发布，必要时回滚 |
| 接口 P95 超预算 | 普通 >500ms、AI 超独立预算持续 10min | 查慢查询/上游/队列 |
| AI 失败/熔断 | 失败率 >20% 或熔断打开 | 检查供应商状态、切降级、限额 |
| AI 成本 | 日预算 50/80/100% | 通知 → 限流 → 硬停/降级 |
| 队列积压 | depth > 阈值 或最老任务 >10min | 扩容 worker/查失败原因 |
| 审核积压 | pending 超时限（待核定） | 通知运营，暂停公开入口（如适用） |
| 数据库连接 | 使用率 >80% 或等待增加 | 查连接泄漏/慢查询 |
| 迁移版本不一致 | 启动校验失败 | 停止发布，人工处理 |
| 备份失败 | 任一备份失败 | 当日修复并记录 |

- 告警渠道：企业微信机器人；值班与升级路径写入 `docs/ops/`（OPS-01/OPS-03）。
- 回滚：镜像保留最近 3 版；先回滚镜像（N-1 必须兼容当前 schema），再评估迁移补偿；数据回滚用补偿脚本 + 备份，禁止直接 `git reset`/删表。
- 每个里程碑必须演示一次回滚；没有回滚方案的发布视为未完成。

### 9.7 可观测性完成标准

新增/修改接口或任务必须同时提供：

1. 结构化日志字段（含 `request_id`、错误码、耗时；无敏感正文）。
2. 请求量/延迟/错误指标；AI 另加 token/费用/降级指标。
3. trace span（入口 + 关键依赖）。
4. 失败模式的告警或明确「不告警」的理由（写入 PR）。
5. 仪表盘/查询语句（若属于新业务域）。

缺任一项，不得标记为可上线；监控未覆盖的功能在 DoD 中按未完成处理。

## 10. 安全基线

安全默认值：**默认拒绝、失败关闭、最小权限、服务端唯一权威**。任何「先上线再补授权」的方案不通过 Review。

### 10.1 信任边界

- 客户端输入一律不可信：包括 `studentId`、`coachId`、`actor`、`sourceTag`、`role`、`status`、`evidenceLevel`、审核结果、版本号、时间、价格、文件 URL。
- 服务端从认证主体推导身份；资源归属、服务关系、授权 scope、版本、审核状态一律从数据库当前状态判定（ER §4.4、api/README §1）。
- 公开接口只返回已发布且 public 的内容；link 内容只经受控令牌读取；未公开/无权资源返回 `404`，不泄露存在性。
- 身份（是谁）≠ 关系（能否接触）≠ 授权（能看哪些字段）≠ 版本（看哪一版）；四者分别校验，不能互相替代。

### 10.2 鉴权与对象级授权分离

**认证（Authentication）**由中间件完成：

1. 校验 JWT 签名、issuer、audience（`nerae-users` / `nerae-admin`）、`exp/nbf`、`token_version` 与账号状态。
2. 用户 token 永远不能获得后台能力；admin token 不适用于用户接口；两类 token 使用独立密钥与 issuer。
3. 认证成功只写入 `Principal{Kind, ID, Roles, TokenVersion}`，**不做资源授权**。
4. 失败返回 `401`；token 过期/吊销不得靠前端判断。

**对象级授权（Authorization）**由 service 完成：

1. 先按主体限定查询（如 `WHERE student_id = ?`），再校验关系状态、有效期、scope、版本；列表不得「先全查再过滤」。
2. 每个敏感用例有独立 `authorizeXxx` 逻辑与表驱动测试；授权失败默认 `404`（隐藏存在性），已确认存在且动作被禁止时用 `403`。
3. 教练身份不等于可读健康数据；有效关系 + 当前 scope + 未撤回同意才可读；结束/撤权立即失效，缓存与异步任务重查。
4. 后台权限是独立主体与 RBAC；**审核角色不自动获得健康正文读取权**，敏感客服访问需审批、限定范围、留审计（ER §4.2、`conversation_access_approval`）。
5. 客户端角色只影响界面，不授予教练认证、管理员或数据权限。
6. 公开分享、通知摘要、签名 URL、AI 上下文都按同一授权矩阵校验；不能从旁路绕过。

**负向用例是硬门槛**：跨学员/跨教练、猜 ID、撤权后访问、结束关系后访问、用户 token 调后台、admin token 调用户接口、伪造来源标签、旧版本重放。缺少这些用例的 PR 不合并（§5.7、SEC-01）。

### 10.3 输入校验与输出编码

- 所有请求先按 OpenAPI 与 validator 校验：类型、范围、长度、枚举、必填、`additionalProperties: false`；未知字段拒绝（`400 VALIDATION_ERROR`）。
- 业务约束返回 `422`（内容不满足规则），语法/结构错误返回 `400`；不得把数据库错误当 400。
- 请求体大小限制：JSON ≤1 MB；上传按用途限制；超限 `413`/`400`，不读入内存后再判断。
- JSON 解析拒绝重复键歧义（自定义 decoder），数值/字符串类型严格；ID 只接受规范十进制。
- 文本统一 NFC、去控制字符；长度按 Unicode 字符计；富文本仅后台白名单，前端禁止 `v-html` 渲染用户内容。
- SQL 一律参数化；排序列用白名单；文件路径禁止 `..`；命令行/模板不拼接用户输入。
- 输出编码：HTML 上下文转义、JSON 正确序列化；错误信息不泄露表名/堆栈/上游响应；CORS 只允许配置的来源。
- 发布内容 `content_hash` 基于规范化内容（§3.7）；客户端不能通过顺序/空白差异伪造「未变」。

### 10.4 文件上传与下载

- 私有 COS 桶；上传使用服务端签发的短期凭证，限定 `object_key`、content-type、大小与用途；禁止把长期密钥下发客户端。
- 允许类型白名单（图片：jpeg/png/webp；证件按需），同时校验扩展名、Content-Type 与实际文件头（magic bytes）；拒绝 SVG/HTML 等可执行内容。
- 图片剥离 EXIF/GPS；压缩在服务端或客户端受控进行；原始文件保留策略按用途与保留期核定。
- 上传后状态 `pending/quarantined`，经内容安全（`mediaCheckAsync` 等）通过后转 `available`；未通过下架并通知。
- 下载/预览必须重新鉴权（所属资源 + 关系 + scope），使用短时效签名 URL（≤5 分钟），不返回永久公开链接；知道 URL 不等于有权限。
- 文件名不直接用于存储键；对象键随机化；禁止目录遍历与覆盖他人对象。
- 删除/撤权后，签名 URL 到期即失效，缓存与 CDN 不缓存私有健康文件。

### 10.5 SSRF 与外部调用

- 服务端**禁止**请求用户提供的任意 URL（头像外链、导入链接、webhook 回调地址等）；确需时走域名白名单 + 人工审核。
- 出站请求必须：仅 HTTPS、解析后校验 IP（拒绝私网/回环/链路本地/云元数据 `169.254.169.254`）、禁止重定向跟随、连接/读取超时、响应体大小上限。
- 微信登录/内容安全/订阅消息、COS、AI 供应商只允许官方域名与固定 SDK；代理与镜像地址需批准。
- 回调必须验签（签名、时间戳、nonce），防重放；回调处理幂等，且不因回调内容自动扩大授权。
- AI 网关不提供工具调用/浏览器/任意 URL 拉取能力；知识上下文来自服务端受控数据。

### 10.6 密钥与配置安全

- 密钥只放腾讯云 KMS 或环境变量，按环境隔离；不入库、不入镜像、不入仓库、不进日志/错误/trace。
- JWT 用户/后台密钥分离；加密主密钥与数据密钥分离；轮换流程与 `key_id` 兼容（§3.7）。
- `.env.example` 只有占位符；生产配置由部署平台注入；本地开发使用独立测试密钥，禁止复用生产值。
- 启动校验密钥长度与存在性；生产禁止默认值/空值；发现泄露立即轮换并评估影响面（不先删日志）。
- CI 必须有密钥扫描；依赖/镜像凭据使用短期令牌；构建日志不打印 secret。

### 10.7 健康数据访问审计

必须写入 `audit_log`（只追加）：

| 事件 | 记录内容 |
|---|---|
| 登录/失败/锁定 | 主体类型与 ID、结果、IP/UA、`request_id`；不记密码/验证码 |
| 健康信息采集同意/撤回 | 用户、purpose、notice 版本、时间 |
| 数据授权创建/变更/撤回 | 关系、scope 变更前后、版本、操作者、`request_id` |
| 教练读取敏感字段（伤病/身体/饮食/过敏） | 教练、学员、关系、字段类别、用途、`request_id` |
| 后台敏感访问 | admin、目标资源、审批记录、范围、有效期 |
| 导出/下载/删除请求 | 主体、范围、结果 |
| 审核/下架/申诉 | 审核人、目标版本、动作、依据 |

- `audit_log.detail` 只存最小差异与引用，**禁止健康正文、消息正文、令牌、密钥**。
- 审计写入失败必须告警并视为业务失败（尤其是授权、发布、审核）；不能「审计失败但操作成功」。
- 审计查询本身受权限控制并有审计；保留期未核定前按配置执行，不默认永久保留。
- 撤权/结束关系后立即停止新增读取；审计与本人记录保留不恢复教练访问权（ER §13）。

### 10.8 日志与错误禁止项（摘要）

禁止记录：JWT/Authorization、密码、API Key、openid/unionid、手机号、真实姓名、伤病正文、饮食观察/日记正文、过敏原清单、私信正文、AI prompt/补全中的健康内容、签名 URL、完整请求/响应体、加密前明文。完整字段规则见 §2.7 与附录 C。

### 10.9 依赖与供应链

- 依赖清单与 lockfile 入库；Go 用 `go.sum`，前端用 `pnpm-lock.yaml`；CI 用 `--frozen-lockfile`、`go mod verify`。
- 新增依赖（Go module、npm 包、外部服务/SDK、镜像）必须批准，说明用途、许可证、维护状态、体积与安全记录；禁止来源不明的包与 `curl | bash` 安装。
- 固定精确版本与镜像 digest；禁止 `latest`；升级单独 PR 并跑全量测试/契约回归。
- CI 执行 `govulncheck` 与依赖审计；高危漏洞阻断；中危需修复计划。
- 容器镜像最小化、非 root、只读文件系统（可行时）；构建可复现，产物附 SBOM（目标）。
- 不使用带 postinstall 脚本的未知包；确需时审查脚本内容并在 CI 禁用自动执行。

### 10.10 内容安全与 AI 安全

- 文本：微信 `msgSecCheck` + 自建词库 + 规则；图片：`mediaCheckAsync`；首次饮食发布人工审核（比例待核定）；举报 24h 内先下架（PRD，需运营落实）。
- 审核动作与结果只由服务端生成；来源标签、教练认证、证据等级是服务端只读字段。
- AI 输入最小化：只发送必要字段；未授权字段、健康正文不进 prompt；发送前脱敏并记录 `ai_run`。
- Prompt 注入防护：用户内容放数据区、加分隔与指令隔离；不执行用户提供的「系统指令」；输出只按 JSON Schema 解析。
- 输出过滤：医学诊断/处方/极端饮食/用药建议必须拦截或降级；信息不足返回 `insufficient_data`；不把 JSON 合法当安全。
- AI 结果必须标注来源与「AI 生成/建议」，保留人工确认；不得自动发布或替代教练确认。
- 模型固定 mimo-v2.6-flash，失败降级不升档/不自动切供应商（D11、§9.5）；变更需配置决策 + 回归。

### 10.11 限流、防滥用与账号安全

- 登录/验证码/敏感查询按 IP + 主体限流；连续失败锁定（阈值与时长待核定）；后台登录加 TOTP（P1 目标，按架构文档）。
- 写接口限流 + 幂等键；AI 有独立额度；上传有频率/大小限制；导出/审计查询限流。
- 防止枚举：登录、找回、分享令牌、预约查询的响应不区分「不存在/无权限」。
- 管理员无共享账号；权限最小化；离职/停用立即递增 `token_version`；敏感操作需二次确认。
- 客户端 token 存在平台安全存储，登出清理；不把 token 放 URL、Referer 或分享链接。

### 10.12 数据删除与保留

- 注销/删除异步执行：立即停止业务读取与 AI 使用 → 按保留策略删除/匿名化 → 保留必要墓碑与审计。
- 撤回授权立即停止新增读取/处理，不等于立即物理删除；删除请求、历史服务证据、审计必要性与本人记录分别处理（ER §13）。
- 备份中的删除按备份周期过期；恢复演练必须验证删除不会被旧备份「复活」到业务可读状态。
- 保留期、日志/健康数据/幂等窗口/审核抽检比例未核定时，不得写成「永久」或对外承诺；配置化并标注待核定。

### 10.13 安全负向验收清单

每个涉及敏感资源的 PR 至少回答（未涉及则写「不适用」）：

- [ ] 未登录、过期 token、错误 audience → 401，且无数据泄露
- [ ] 他人资源/猜 ID/跨教练/跨学员 → 404/403，且响应不区别存在性（按契约）
- [ ] 结束关系/撤权后立即访问 → 拒绝，缓存/异步任务不返回旧数据
- [ ] 客户端伪造 `sourceTag`/认证/证据等级/角色 → 被忽略或 400/403
- [ ] 健康字段未授权组合（profile≠body≠injury≠diet≠allergy）→ 不越界返回
- [ ] 日志/错误/审计/trace 无健康正文与令牌（含脱敏单测）
- [ ] 上传类型/大小/文件头/EXIF/下载鉴权符合 §10.4
- [ ] 外部 URL/回调/重定向无 SSRF 与重放风险
- [ ] 幂等重放、412、409、限流 429 行为符合契约
- [ ] AI 未授权上下文、prompt 注入、信息不足、超预算、熔断路径有测试或人工验证记录

### 10.14 安全禁止事项

1. 只做页面级/按钮级权限控制，服务端不校验对象归属。
2. 用角色名、JWT 自定义 claim 或客户端 `role` 直接授予教练/管理员/数据权限。
3. 信任客户端传入的 `actor`、`sourceTag`、`coachId`、`status`、价格、审核结果。
4. 把健康正文、token、openid、签名 URL 写入日志/错误/审计 detail/trace。
5. 公开 COS 桶、永久下载链接、把密钥下发客户端。
6. 请求用户提供的 URL 或允许任意重定向；未校验回调签名。
7. 明文存储手机号/真实姓名/伤病/过敏原；自造加密算法或复用 nonce。
8. 关闭校验、放宽 CORS、生产开 debug/Swagger、关闭限流来「联调方便」。
9. 未经批准新增依赖/镜像/外部服务；使用 `latest`。
10. 删除审计、伪造审计、审计失败仍继续授权/发布/审核操作。

### 11.2 里程碑/发布级 DoD

- 可演示：按验收脚本走通目标闭环，含空数据、失败、恢复；不靠口述。
- 可回滚：上一版镜像可部署；迁移有 down 或补偿；开关/灰度可用。
- 可观测：核心指标、日志、告警、Dashboard 已上线；成本可计量。
- 安全：授权矩阵与越权用例通过；日志脱敏检查通过；无高危依赖漏洞。
- 文档：README、契约说明、ADR、运行手册、变更记录同步；任务板全部 `done` 且附证据。
- 证据：命令输出、测试报告、截图存入 `docs/evidence/`；`.review/` 只作本地复核，不作为交付证据。
- 数据：迁移/备份/恢复演练记录；删除与匿名化流程可执行。

### 11.3 判定规则（什么不算完成）

1. `[no test files]`、只编译通过、只生成成功 → 不算测试通过。
2. 删除断言、加 skip、放宽 schema、改期望值才变绿 → 不算修复，按事故处理。
3. 只有 happy path、无越权/撤权/412/409 负向用例 → 不算完成。
4. 契约改在代码里、未回写 OpenAPI/生成物 → 不算完成。
5. 日志/监控/告警缺失 → 不算可上线；先在任务卡标明缺口并获 Lead 批准，才能拆分后续任务。
6. 迁移无回滚、无法在预发验证 → 不算完成（破坏性变更必须 ADR + 补偿）。
7. 「本地跑不了所以没验证」且未说明 → 不算完成；必须写清缺失项与替代验证。
8. 用「后续再补」「应该没问题」「CI 会兜」交付 → 退回。

### 11.4 常见伪完成

- 页面能打开但没有四态（加载/空/错/无权限）。
- 接口返回 200 但错误码/状态码与契约不符。
- AI 生成「看起来完整」但未确认字段、未标注估算、绕过人工确认。
- 把计划量当实际摄入、把自评当证据、把 JSON 合法当健康安全。
- 后台隐藏按钮即认为权限完成；分享链接靠猜 ID。
- 前端类型手写、字段名与契约不一致但「能跑」。
- 迁移能 up 不能 down；索引缺失但「数据少」。
- 数据脱敏靠日志平台规则，代码里仍打印正文。

## 12. 子 Agent 与自动化协作边界

目标：让子 Agent 在明确边界内自主推进，同时把**不可逆、跨契约、影响成本/合规**的决定留给人。判定原则：**默认自主执行可逆的小步；任何难以回滚或会改变对外承诺的事，先停上报。**

### 12.1 可以自主决定

| 场景 | 边界 |
|---|---|
| 模块内实现 | 在任务卡 `scopes` 内按契约实现 handler/service/repo；选择内部数据结构、函数拆分 |
| 重构 | 不改变外部行为、契约、数据库结构、权限语义；测试保持通过 |
| 测试 | 新增单测/集成/负向用例；修正错误期望需说明理由（不得削弱） |
| 文档 | 补充说明、示例、README 现状描述（不得改写已确认决策与历史结论） |
| 样式实现 | 使用既定 tokens 与基础组件完成布局；不新增 token 值 |
| 本地工具 | 临时脚本放在 `.review/` 或 `scripts/`（可复用才进仓库） |
| Bug 修复 | 在既有契约与权限模型内修复；补复现测试 |
| 性能优化 | 同语义下加索引（非迁移）、减 N+1、缓存只读数据；不改外部行为 |
| prompt 文案 | 仅在不改变输出 schema/安全策略时调整；版本号与 ai_run 记录必须更新（若涉及模型/policy 见 12.2） |

### 12.2 必须升级给人（Stop & Ask）

| 变更 | 为什么必须升级 | 需要谁 | 必要产物 |
|---|---|---|---|
| **契约破坏性变更**：删除/重命名字段、改类型/语义、改状态码、改 `operationId`、删除路径、新增必填请求字段 | 客户端、测试、迁移与对外承诺同时受影响 | Lead + Contract Steward | ADR/变更说明、兼容/迁移方案、全部回归结果 |
| **数据库破坏性迁移**：删表/删列、改类型、收紧唯一键、回填健康数据、不可逆 down | 数据不可恢复、线上不可回滚 | Lead + 数据负责人 | 迁移脚本、备份/恢复演练、N-1 兼容证明、ADR |
| **权限模型变化**：新增/修改 scope、角色、audience、关系状态机、后台权限、健康数据可见范围 | 越权与合规风险，不能用测试「看起来通过」替代 | Lead + 安全/合规 | 授权矩阵、越权负向用例、审计方案 |
| **新增第三方依赖/外部服务**：Go module、npm 包、SDK、镜像、AI/短信/存储供应商 | 供应链、许可证、成本、数据出境 | Lead | 用途、许可证、维护状态、安全记录、替代方案 |
| **视觉 tokens 变更**：颜色/字号/间距/圆角/阴影/语义状态、组件库替换 | 全端返工、品牌与一致性 | Lead + 设计 | 变更清单、对比截图、影响页面 |
| 生产配置/密钥/成本阈值/保留期/审核比例/SLA | 影响线上安全、成本与合规 | Lead/Ops | 配置变更单、回滚方式、监控 |
| CI 门禁放宽、删除/跳过测试、改测试基线 | 质量门失效 | Lead + Reviewer | 原因、替代保障、限时恢复计划 |
| 新增模块/顶层目录、修改共享文件所有权 | 破坏并行边界 | Lead | 任务拆分与 scope 更新 |
| 产品语义变化（不收款边界、AI 自动发布、医疗建议、联系路径） | 违反已确认方向/合规 | 产品负责人 | 决策记录/ADR |

**处理方式**：不要先改再问，也不要自己「折中」。在任务板标 `blocked`，按 12.3 格式报告；在获批前只做不受影响的部分。

### 12.3 升级消息格式

```text
任务：<ID> <标题>
阻塞点：<一句话>
现状/证据：<命令、文件、契约行、错误>
影响：契约 / 迁移 / 权限 / 成本 / 客户端 / 合规（逐项说明）
可选方案：
  A. <方案>（影响、成本、风险）
  B. <方案>（影响、成本、风险）
建议：<A/B 及理由>
不可逆点：<如果做了会怎样，能否回滚>
需要决定：<Lead / 产品 / 设计 / 安全> 在 <时间> 前确认
已暂停：<哪些工作已停止，哪些可继续>
```

- 阻塞期间不得静默改需求、不得绕过契约写「临时字段」、不得把未验证代码合入。
- 若 Lead 决定不做，记录到 DECISION_LOG/ADR；任务卡关闭原因写清。

### 12.4 与 Lead/Reviewer 的交接

- 开始：确认任务板状态、依赖、scope、共享文件所有权（协作规范 §4、§7）。
- 过程：只改 scope；遇到他人文件/`FS_STALE_VERSION` 停下重读并上报，不覆盖。
- 完成：跑验收命令 → 写交付说明（改动/验证/风险/影响）→ 任务板改 `review`。
- 复核：Reviewer 独立检查 §7.5 清单；不通过退回 `in_progress`，写复现方式。
- 合并：由 Lead/集成者执行；子 Agent 不自行合并、不改 `main`、不 force-push。
- D12 工作方式：隔离 worktree + 任务 DAG + 串行集成；同一文件同一时间只有一个写者。

### 12.5 子 Agent 硬性禁止

1. 修改 `api/openapi.yaml`、`api/tests/`、`migrations/`、`tokens.json`、`routes.go`、依赖清单，除非任务卡明确授权且有人复核。
2. 删除/弱化测试、改测试基线、用 `skip`/`|| true` 让流水线变绿。
3. 先实现再补契约，或在业务代码里私自定义字段/状态码。
4. 自行新增依赖、模型、供应商、外部服务、镜像。
5. 修改权限模型、审计范围、数据保留策略、AI 额度/熔断阈值。
6. 把未验证能力写成「已完成」；用「应该可以」作为交付结论。
7. 在日志/错误/prompt 中放健康正文、token、openid、签名 URL。
8. 跨 scope 修改、覆盖他人改动、自行合并或 force-push 到 `main`。
9. 为了让样例通过而放宽 schema/校验/授权判断。
10. 在未获批准时执行生产迁移、部署、改线上配置或调用真实付费资源。

## 附录 B · 统一错误码登记表

契约 `Error.code` 目前是自由字符串（OpenAPI 只给 `VALIDATION_ERROR` 示例，**没有 enum**）；ER §9.2 提到 `REQUEST_IN_PROGRESS`。本表是服务端**登记表**，不是契约已枚举的证明：

- 客户端只能按本表已登记的 code 分支；`message` 可改，不能作为判断依据。
- 新增/改名 code = 契约面变更，走 §8.4；实现里临时造字符串视为缺陷。
- `details` 必须是非敏感结构化数据；禁止健康正文、SQL、上游原文。

| HTTP | `code` | 场景 | 客户端建议处理 | 来源/状态 |
|---|---|---|---|---|
| 400 | `VALIDATION_ERROR` | 语法/类型/未知字段/缺失或非法 `Idempotency-Key`/非法 ID | 修正请求后重试 | 契约示例 |
| 401 | `UNAUTHENTICATED` | 未登录、token 过期/吊销、`token_version` 不符、audience 不符 | 重新登录 | api/README 401 |
| 403 | `FORBIDDEN` | 已认证，资源存在性已明确但角色/状态禁止操作 | 提示无权限，不重试 | api/README 403 |
| 404 | `NOT_FOUND` | 不存在，或无权查看而需隐藏存在性 | 返回列表/重新导航 | api/README 404 |
| 409 | `STATE_CONFLICT` | 当前状态不允许（关系已结束、重复完成、草稿状态不符等） | 刷新最新状态后由用户决定 | api/README 409 |
| 409 | `IDEMPOTENCY_KEY_REUSED` | 同键不同请求摘要 | 提示重复提交冲突，不自动换键重放 | ER §9.2 |
| 409 | `REQUEST_IN_PROGRESS` | 同键同摘要仍在处理 | 稍后查询/等待首次结果 | ER §9.2（状态码待契约确认） |
| 412 | `VERSION_CONFLICT` | `expectedVersion` 与当前版本不符 | 重新拉取最新版本，禁止自动重试覆盖 | api/README 412 |
| 422 | `CONTENT_CONSTRAINT` | 内容不满足业务规则（份量/证据/估算字段/发布条件） | 修改内容后重新提交 | 契约 422 |
| 429 | `QUOTA_EXCEEDED` | AI 额度/配额耗尽 | 等待额度恢复或按运营策略处理 | 契约 429 |
| 429 | `RATE_LIMITED` | 频率限制 | 指数退避，不立即重试 | 工程约定 |
| 500 | `INTERNAL` | 未预期错误 | 有限重试；带 `requestId` 报障 | 契约 500 |
| 503 | `UPSTREAM_UNAVAILABLE` | AI/微信/COS 等上游不可用或熔断 | 稍后重试/提示降级能力 | 契约 503 |

**契约缺口（待 W0/后续契约任务处理）**：`Error.code` 增加 enum 与说明；明确 `REQUEST_IN_PROGRESS` 的状态码；413（请求体过大）/415（媒体类型）若要使用，必须在统一错误响应中登记，否则先用 400 `VALIDATION_ERROR`。
