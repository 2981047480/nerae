# 任务板使用说明

任务源：[tasks.yaml](tasks.yaml)。规则依据：[多 Agent 协作规范](../docs/多Agent协作规范.md)。总计划：[开发计划 v1.0](../docs/开发计划-v1.0.md)。

## 一条命令自检

```sh
python3 backlog/validate.py
```

校验内容：编号唯一、依赖存在且方向正确、依赖无环、同波次写作用域不重叠、字段与枚举合法、每波有足够并行任务。退出码 0 才允许领取任务。

## 状态流转

```
todo → claimed → in_progress → review → done
                      ↘ blocked
```

- **claimed**：已确认依赖完成、作用域无人占用；在任务卡外不要改别人的文件。
- **in_progress**：开始写代码/文档。
- **review**：自检通过（lint/测试/生成物一致），等待另一个 Agent 复核。
- **done**：复核通过且 Lead 验收命令通过。`done` 必须附证据（命令与结果），不能只写"已完成"。
- **blocked**：写明阻塞原因、需要谁决策、已尝试什么；不要静默停摆。

## 领取前的四查

1. 所有 `depends_on` 均为 `done`。
2. 同一波次内，`scopes` 与已领取任务不重叠（校验器只能查静态表，实际领取时还要看当前所有者）。
3. 任务规模 ≤ L；若实际超过 3 天，先拆分再开工。
4. 需要的契约或设计输入已存在（OpenAPI、ER、设计 tokens、页面模板）。

## 波次与并发

| 波次 | 主题 | 建议并发 |
|---|---|---|
| W0 | 契约与决策收口 + Git 基线 | 契约链 1 人；文档决策 3 人 |
| W1 | Go 骨架 / 设计 tokens / CI | 3 |
| W2 | 本地基础设施 / 小程序骨架 / 后台骨架 | 3 |
| W3 | 身份与档案 | 5 + 1 收尾 |
| W4 | 教练与服务包、双广场 | 6 + 1 收尾 |
| W5 | 关系、交付、个人计划（首个闭环） | 6 + 1 收尾 |
| W6 | 训练记录、免费发布、AI 网关 | 6 + 1 收尾 |
| W7 | 饮食与异常筛查 | 3 + 1 收尾 |
| W8 | 审核与运营后台 | 4 + 1 收尾 |
| W9 | 质量门 | 5 |
| W10 | 试点准备 | 3 |

同一波次的 `tail` 任务（INT-*、DIET-02）只做路由接线与冒烟，不实现业务，且必须等该波并行任务完成后执行。

## 共享文件所有权

以下文件同波次只能有一个所有者，未被指派时任何 Agent 不得修改：

| 文件/目录 | 所有者 |
|---|---|
| `api/openapi.yaml`、`api/tests/` | W0 契约链持有人（串行） |
| `apps/api/internal/server/routes.go` | 该波 `INT-*` / `DIET-02` 收尾任务 |
| `apps/api/migrations/` | SETUP-05；后续波次新增迁移须单列任务 |
| `packages/api-types/`、`packages/design-tokens/` | 生成物，只由生成命令更新，不手工编辑 |
| `README.md`、`AGENTS.md`、`docs/开发计划-v1.0.md` | Lead |

## 失败与冲突

- `FS_STALE_VERSION`：重新读取，基于新内容重做本轮改动，不覆盖他人修改。
- 需要修改别人作用域内的文件：停止，向 Lead 报告，由 Lead 调整任务或合并。
- 契约需要破坏性变更：先改 W0 契约链，重新生成并跑回归；不允许在业务任务里顺手改契约。
