# Nerae 开发计划 v1.0

> 日期：2026-10-23
> 适用：本仓库的人类与 AI 协作者
> 配套：[多 Agent 协作规范](<多Agent协作规范.md>)、[任务板](<../backlog/tasks.yaml>)、[工程规范](<工程规范.md>)、[设计系统](<设计系统与UI规范.md>)
> 性质：开发计划，不是交付承诺。工期与成本是区间估算，外部审核与人员到位情况会改变结果。

## 0. 摘要

项目已具备**可校验的契约与数据模型**，但**没有一行应用代码、没有 Git 历史**，且 2026-10-23 的方案审核指出 7 个 P1 流程缺口。因此计划分两步：先用一个波次关掉契约与决策缺口，再按「契约先行 + 垂直切片 + 波次并行」交付。

- 任务板：**11 个波次、59 张任务卡**，每卡 ≤3 人日、写作用域互斥、依赖可机器校验
- 关键路径：W0 契约收口 → W5 首个交付闭环 → W9 质量门
- 交付形态：小程序（学员/教练）+ 运营后台 + Go 服务
- 预计日历：**12–15 周**（3–5 个 Agent 并行，含质量门）；若只求试点验证可压缩到 **8–10 周**（见 §6.2）
- 成本：基础设施 + AI 约 **1,000–5,900 元/月**（按规模分档，见 §13），原「首年 3,000–8,000 元」口径已过时

## 2. 目标与非目标

### 目标

1. **可交付**：学员能选教练、预约、建立关系、拿到并执行计划、记录、收到点评；免费用户能找计划、另存、编辑、发布、打卡。
2. **可维护**：模块边界清晰、契约单一来源、测试可回归、迁移可回滚、文档与代码同步。
3. **好看且一致**：设计 tokens 驱动、组件复用、状态完整（加载/空/错误/离线/无权限），有视觉走查门。
4. **可并行**：任何一张任务卡都能在不读全仓库的情况下交给子 Agent 完成，且不会和别人冲突。
5. **可安全上线**：健康数据最小化、授权即时失效、无越权路径、可删除可审计。

### 非目标（本计划不做）

- 平台内支付、分账、退款、订单、储值
- 医疗诊断、康复处方、疾病/孕产饮食方案
- 视频通话、动作识别、直播、自由发帖社区
- 多城市运营、工作室多人账号（模型预留，不在本计划开放）
- 原生 App（uni-app 保留跨端能力，本计划只交付小程序 + 后台）

## 5. 开发策略

1. **契约先行**：任何接口先改 OpenAPI、生成产物、跑回归，再写实现。
2. **垂直切片**：每个波次交付一条可演示的用户路径，而不是"先写完所有后端再写前端"。
3. **波次并行**：同波次不同目录并行；同文件只有一个写者；`tail` 任务负责接线与冒烟。
4. **先修缺口再铺量**：审核 R01–R05 直接决定 W5 能否跑通，必须在 W0 关闭。
5. **每个里程碑可演示、可回滚**：没有演示脚本与回滚方案的里程碑不算完成。

### 6.2 两条时间线

| 轨道 | 范围 | 日历估算 | 适合 |
|---|---|---|---|
| **试点轨道** | W0–W5 + W9 子集；后台用表格/人工处理；免费层只做另存与记录 | **8–10 周** | 先验证「教练愿不愿交付、学员愿不愿跟」 |
| **完整轨道** | W0–W10 全部 | **12–15 周** | 可对外交付、可维护、可运营 |

差异主要在 W6–W8 的免费发布、饮食异常、审核后台。两条轨道共用同一契约与任务板，试点轨道只是把部分卡片标为后续，不改变接口语义。

**与既有文档的口径差异（本计划取代旧估算）**

| 旧口径 | 新口径 | 原因 |
|---|---|---|
| 架构文档与 PRD：8–12 周 | 完整 12–15 周；试点 8–10 周 | 旧估算未含审核 R01–R05 修复、质量门、后台完整度与视觉走查 |
| README/成本清单：首年 3,000–8,000 元 | 约 1,000–5,900 元/月（分档） | 旧口径按更低配置且未计 AI 用量 |

这些差异不改变产品方向，只修正工期与成本的可信度；PRD 与成本清单在下一次修订时同步，不在本计划中直接改写。

## 9. 质量门

### 每波

```sh
python3 backlog/validate.py
npx --yes @redocly/cli@1.34.3 lint api/openapi.yaml
PYTHONDONTWRITEBYTECODE=1 api/tests/.venv-py311/bin/python -m unittest discover -s api/tests -p 'test_*.py'
# 脚手架完成后追加：make lint && make test && make build
```

### 每批开放的检查表（对应审核 R09）

每个当批开放的能力，必须能回答五行：

| 用户任务 | 接口/内容 | 空数据 | 失败与恢复 | 运营处理 |
|---|---|---|---|---|
| 例：学员另存计划 | POST /me/plans/from-template | 空列表引导 | 412 冲突提示、重试 | 内容下架与通知 |

填不满的行，不允许在演示中声称该能力可用。

### 安全与视觉

- 授权矩阵（SEC-01）逐条有预期状态码与"数据不可见"断言
- 视觉走查（QA-04）每页三列：通过 / 问题 / 负责人；阻塞项为 0
- AI 相关：结构合法、人工确认、内容安全、专业审查是四个不同状态，不得互相替代

## 10. 视觉与体验交付

1. **W1 冻结 tokens**：色彩、字号、间距、圆角、阴影、语义状态；两份候选主色待用户确认，先按默认值开发（见设计系统文档）。
2. **W2 基础组件**：Button、Card、List、Tag、Empty、Skeleton、ActionBar，之后所有页面只允许用这些组件与 tokens。
3. **页面模板**：列表、详情、表单/发布、工作台、空/错/离线/无权限；每个页面在任务卡里指定使用哪个模板。
4. **状态可见性**：草稿/已发布、AI 估算、信息不足、待复核、关系未生效、授权未开启，必须有非颜色手段（标签、文案、图标）。

## 11. 可读性与可维护性

| 措施 | 规则 |

**可读性验收**：让一个未参与本项目的 Agent 只读 AGENTS + 一张任务卡 + 对应规范，完成一个 S 任务；返工 ≤1 次即达标。

### 13.2 三档用量

| 档位 | 活跃用户 | 日均问答 | AI 月成本 | 基础设施月成本 | 合计/月 |
|---|---:|---:|---:|---:|---:|
| 试点 | 300 | 5 次 | ≈¥190 | ¥350–2,200 | **约 ¥550–2,400** |
| 正常 | 1,000 | 8 次 | ≈¥990 | ¥500–2,200 | **约 ¥1,500–3,200** |
| 高使用 | 3,000 | 10 次 | ≈¥3,700 | ¥800–2,200 | **约 ¥4,500–5,900** |

**重要修正**：PRD 中「免费学员 AI 成本 ≤0.5 元/月」在 10 次/天、无 token 上限时不可能成立（单日即约 ¥0.04）。FIX-07 必须给出三者之一：降低次数上限、限制上下文长度、或用缓存/轻模型把单次成本压到目标内；否则应修改该目标。**不要用平均数掩盖高使用用户。**

原 README「首年基础设施 3,000–8,000 元」是旧口径（不含 AI、按更低配置），本计划 §13 取代之；FIX-08 负责同步成本与资质清单。
