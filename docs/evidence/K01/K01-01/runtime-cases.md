# K01-01 运行时待验收案例

这些案例是后续真实 HTTP/数据库和三端集成的验收输入，并未因静态合同测试通过而执行或通过。认证主体、计划、训练安排、时区和隔离测试数据必须真实建立；所有状态断言需同时检查数据库与响应。不得连接生产数据。

1. **双模式与重复动作**：同一用户在训练后批量填写、切换为逐组记录，复用会话 ID、动作条目键和组键；同一库动作的两个条目各有不同 entry key，即使组序号相同也不可合并。应用重启及另一端读取后，实际值与身份一致。
2. **自定义动作**：用户填写名称、添加两组，两组共用条目键、各有组键；另一会话可用同名但不同键。条目首次写入时冻结名称；使用同一条目键提交另一动作/名称必须 422 且整批不变。库动作使用固定版本名称快照，源库改名或下架不改历史记录。
3. **批次原子性**：同批两个不同对象使用同一 recordKey、更新键与删除键重叠、恢复键不在 sets、恢复非本会话已删除组、更新和删除合计超过 200，各返回 422 且版本、组、条目、统计全部不变；不能只靠 JSON Schema 判断这些跨字段条件。
4. **删除和撤销**：删除一个组立即从读模型和统计移除实际值，未列出的组不受影响；再次以新请求及当前版本删除不存在的键无变化。新组不得复用已删除键；用户明确撤销时以原 recordKey、restoreRecordKeys 和完整数据恢复原条目。用户改为新动作时使用新条目/组键。删除最后实际组后会话为草稿，相关事项的完成投影和统计撤回，保留原安排/审计历史；再次保存前没有实际组应 409。
5. **已保存修订与日期**：完成后修改组和实际训练日，仍为原会话；日期早于或等于冻结时区当前日可用，未来日或无效 IANA 时区拒绝。跨时区重启不改变会话时区；原 scheduledDate 和固定计划版本不变，completedLate 及按期率重新计算。createdAt/updatedAt/recordedAt 来自服务端处理时间，不造训练开始/各组完成时间；未知 duration 不以零或计划目标代替。
6. **幂等与并发**：同主体同方法同路径同幂等键、同摘要在保留期内返回第一次结果，即使其 expectedVersion 已过期；同键不同摘要 409。两个不同键同时使用相同 expectedVersion 修改同一会话，仅一个可提交，另一请求 412；幂等记录、组、键注册、会话版本和统计一致。保留期外按新请求处理，但 clientEventId 与组键防重不失效。
7. **权限、恢复和异常**：未登录、其他主体、已撤权教练不能读取或变更健康记录；日常日志与通知不泄露组值或自定义动作名。断网重试、服务进程中途失败和客户端切账号均不能把输入写给另一主体；412 后先保留本地草稿、读取完整最新 session，再让本人处理同组冲突。
8. **服务端精度和范围**：weightKg 按十进制拒绝超过两位小数，RPE 拒绝超过一位小数；校验数值上下限、空白/半行及 `completed=false`；`resolvedExerciseName` 由服务端生成，不接受客户端冒充可信快照。schema 对数值范围有静态覆盖，精度和客户端只读字段行为须在服务端实测。

每条结果记录设备/版本、实际命令或请求、响应、数据库前后状态、失败恢复、证据路径及同一集成提交。删除/备份/健康信息保留配置仍以 L01-03 的实际核定为准。
