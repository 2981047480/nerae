## 兼容与发布约束

1. 保留既有 `clientEventId`、动作段键、`recordKey` 和组身份；可见编号顺排不重用或合并旧键。记录名称保留当时快照。按历史键回读和同键重试必须有正反例。
2. 旧客户端若无法完整表示新增空组、左右状态、恢复快照或新计量，不得以旧版全量写回抹除新字段。K01-05/06 必须给出可复核的协议版本、兼容读、拒绝不安全写或升级路径；未选定方案前不提前指定具体版本号。
3. MySQL 字段本身为 nullable 不等于允许缺值：现有 CHECK 约束仍拒绝。A04 必须新增有版本的迁移，先在隔离库验证备份、原有数据回读、失败恢复和旧客户端；不能直接改已执行的历史迁移。
4. 本人草稿、已完成记录、离线待发和教练可见投影分别定义。未获得有效持久化/服务端回执时不得显示已保存/已同步；缓存不授予权限。迁移或版本不兼容时保护原输入并明确提示。
5. 本表中的界面样式、细节手势、未决定的数字精度、全部素材来源与报告周期不由工程自行升级为已确认需求。动态人体资源须取得可用权并核对准确性。
