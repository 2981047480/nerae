# A01-21 事务内回执复查

`Handle.RecheckExisting` 只接受取得原回执的同一未结束事务，重新按身份 epoch、回执 epoch、邮箱槽、挑战和回执锁顺序核对请求摘要、密文结构及数据库时钟到期；不会因复查过期而删除回执。它不验证签名或当前用户授权，也不解密或释放凭据。

`python3 -B docs/evidence/A01/A01-21/mysql_smoke.py` 在隔离的仅 Unix socket MySQL 上退出 0，覆盖同事务成功、跨事务拒绝、事务内摘要篡改、事务结束、过期不删除，以及现有回执并发和回滚回归。此任务工作树的清单有 13 项，脚本按顺序加载它们并追加本任务的 `0009`，不是生产迁移验收。

首次运行因测试中错误使用了未导入的 `bytes` 包而编译失败；修正为项目已有的 `bytes32` 测试辅助函数后复跑通过。失败目录 `/private/tmp/nerae-a01-21-mysql-xaw45q69` 按规则保留，成功的测试目录由脚本自行清理。

新增 `LockExisting`：只读锁定既有回执，明确区分缺失与过期，过期查询不会删除数据。一次复测的密文篡改用例返回 `ErrLedger`，失败目录 `/private/tmp/nerae-a01-21-mysql-7jq91bqj` 保留；原测试把随机密文的一字节固定改为 `0xff`，该字节本来就可能是 `0xff`，因此存在未实际篡改的偶发风险。改为对原字节 XOR 后，随后四个全新隔离数据库运行均通过；无法仅凭失败日志断定该概率事件是唯一原因。

独立复核发现仅查询既有回执时，若原事务回滚、邮箱槽随后换绑，缺失记录可能被误分为冲突。现有记录查询在槽已换绑但回执缺失时返回空句柄；槽或原挑战本身缺失/不匹配时按存储不可用处理。新事务创建记录的 `Lock` 仍拒绝旧槽位。相应私有 MySQL race 测试退出 0。
