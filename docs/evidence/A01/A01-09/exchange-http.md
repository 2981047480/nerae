# 新设备审批轮询 HTTP 及合成双设备联调

2026-11-03：新增匿名审批轮询 handler，由可信来源解析器取得地址后先消费 IP／全局额度，再解析路径、幂等键和请求体；能力额度在进入数据库前消费。状态仅返回等待、拒绝或过期；批准后重新验证当前会话并返回受合同约束的认证响应，所有响应禁止缓存。原请求精确重试保持原状态或认证回执，新的状态查询需要新随机键及新设备签名。

验证：`python3 -B docs/evidence/A01/A01-24/mysql_redis_smtp_http_smoke.py` 使用独立 socket MySQL、Redis、本机 TLS 及合成 SMTP，运行 `go test -race`。测试用两把合成设备密钥完成挑战、登录、新设备申请、已有设备批准、兑换与精确重试；第一设备创建训练，第二设备读取并保存一组，第一设备可重放及读取同一记录，其他主体不能访问。等待／批准走实际事务；拒绝和过期的 HTTP 映射通过测试库直接改变状态构造，实际拒绝事务另有独立测试。错误设备与额度耗尽不返回令牌；脚本检查所需 PASS 标记，防止跳过被误判通过。

`go test -race -count=1 ./internal/modules/auth/transport -run '^TestApprovalExchange'` 覆盖限额拒绝和非法路径时不读取 body、非法 body 不进入兑换器、错误脱敏，以及认证响应生成期间剩余时效变化和临近到期的拒绝。独立只读复核未发现 P0/P1；当前不覆盖真实反向代理源地址配置。

最终联调在授权的本机环境 exit 0。普通沙箱内的两次尝试均在 MySQL 初始化阶段因映射权限 `SIGSEGV` 退出，未运行到业务测试，失败目录分别保留在 `/private/tmp/nerae-a01-24-f48qxlfw` 和 `/private/tmp/nerae-a01-24-m_6e_521`；成功测试仅清理其自己的临时数据目录。

限制：handler 仅由测试 TLS server 手动挂载；没有接入实际 API 进程、客户端、生产代理或服务器。上述双设备均为合成测试，不代表 App 同步或 iPhone 验收。成功会话提交后若原证明过期或来源授权撤销，结果可能无法重取且已提交目标会话保留；过期回执的清理与跨机时钟偏差尚未验收。
