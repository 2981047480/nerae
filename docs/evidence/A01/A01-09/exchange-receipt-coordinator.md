# 新设备兑换回执协调器

2026-11-03，新增的 `ReceiptExchanger` 是内部认证协调器，不是公开接口。

- 首次兑换将设备证明防重标记、设备与会话、审批消费和加密回执放在同一事务。提交成功后，通过新事务重新检查原申请、设备证明、来源权限和目标会话，再返回令牌。
- 同键同请求重放已提交会话；同一申请使用不同键或不同有效请求发生冲突。证明、来源会话、目标会话或回执不再有效时不返回令牌。回执期限最多与会话期限相同。
- 幂等键按合同接收 22–128 个字符，不再要求特定 base64url 编码；原始键的 HMAC 算法不变。客户端仍须使用至少 128 位安全随机数，服务器无法从文本形状证明随机性。旧密码组件证据描述的是当时的更窄校验。
- 协调器采用 `READ COMMITTED` 并显式锁定主体、来源设备与会话、审批和回执。默认 `REPEATABLE READ` 下的并发精确请求曾因旧快照无法读取新 session 而失败，失败夹具保留于 `/private/tmp/nerae-approval-mysql-wycx6f6g`；调整隔离级别后复测通过。

验证：`python3 -B docs/evidence/A01/A01-09/mysql_smoke.py` 使用 socket-only 私有 MySQL、合成主体与设备并运行 `go test -race`；覆盖精确重放、并发、不同键/证明、来源与目标 session 撤销、回执缺失及篡改、失败写入回滚、锁等待时证明到期、会话寿命限制。测试驱动器对真实 MySQL 的一次成功 COMMIT 注入确认错误：首次调用无令牌，原请求重试取回同一会话且数据库只有一个会话。`go test -race -count=1 ./internal/modules/auth/approvalreceipt` 覆盖重试键边界和密码组件回归。

限制：精确重试仍要求原设备证明未过期、来源与目标授权当前有效。若首次提交后、结果送达前证明过期或来源撤销，调用方无法取回该结果，已提交目标会话可能保留；失败恢复不自动撤销，因为同一个结果可能已交付给并发调用方。须重新登录并按实际状态处理。应用时钟与数据库时钟的部署偏差仍未验收。公开 HTTP 的状态/错误语义、匿名限流、配置与密钥 epoch 启动、客户端页面、服务器部署及真实双设备均尚未完成。
