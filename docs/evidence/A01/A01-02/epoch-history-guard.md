# A01-02 设备证明防重密钥记录缺失保护

状态：active，隔离 worktree 验证；不是实际登录或上线接受证据。

在原实现中，`auth_device_proof_key_epoch` 不存在时，消费设备证明会直接写入当前配置的 key tag。若版本记录丢失但旧的防重标记仍在，换密钥后同一个 JTI 可产生不同摘要，绕过旧标记。现在缺少版本记录时，在同一事务先对防重表做 `FOR UPDATE` 当前读；只要存在任何标记或数据库查询失败，就拒绝初始化和消费。已有版本与配置不符仍拒绝。空表首次初始化保留原有并发失败关闭语义。

`python3 -B docs/evidence/A01/A01-02/mysql_smoke.py`：exit 0。私有 Unix socket MySQL 与 Go race 测试覆盖空表并发初始化、单次消费/回滚、版本记录丢失后原密钥和更换密钥均不能重建、已有防重记录不能被重放，以及旧 REPEATABLE READ 快照不能隐藏并发提交的标记。测试只使用合成数据并清理自己的成功临时目录。

边界：仅当防重表确实为空时仍允许首次请求自动初始化；此修复无法证明同时丢失版本和全部防重数据后的历史状态。生产部署仍需受控初始化/备份恢复、密钥管理、清理策略和跨实例测试。无生产路由或真实设备登录。
