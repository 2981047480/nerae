# 已登录设备确认新设备

2026-11-03：App 认证运行时新增已登录设备确认 API 和未挂载面板。列表只读取当前主体的待确认项，批准需用户核对匹配码后明确点击，拒绝不携带批准确认参数。列表条目绑定当前会话和最新列表；退出或切号时清除面板内容并使迟到响应失效。批准／拒绝响应未知时保留同一个 body、随机键和 session 供显式重试；面板重开时可继续同一进程内的原请求。

独立复核发现过期申请或未满足近期重新认证条件时，服务端拒绝可能使重试停滞。由于拒绝响应也可能发生在服务端提交后的授权复核阶段，客户端不把它简单解释为“未提交”：用户可明确停止等待并重新查看列表，界面提示旧操作仍可能完成；它不会自动换键或自动再发另一决定。具体近期重新认证的产品流程尚未实现，最终授权由服务端判定。

验证：认证及面板 Node 定向测试 13 项通过，覆盖条目归属、显式确认、拒绝、精确重试、限流、缺少 no-store、过期/拒绝后的停止等待、列表与决定期间退出、面板重开和迟到响应。`vue-tsc --noEmit -p tsconfig.json` 通过。锁定 5.26 的 `scripts/quality/verify_uts_plugin_build.py` 编译引用两侧组件的 App 与小程序探针，检查确认文案存在；小程序中的 App 原生接口仍只提供不可用回退。

`NERAE_RUN_API_ASSEMBLY_TEST=1 python3 -B docs/evidence/A01/A01-24/mysql_redis_smtp_http_smoke.py` 在私有 MySQL／Redis、本机 TLS 和合成设备上运行真实 `ApprovalOwnerApi` 与新设备登录协调器：在已提交的批准决定和已提交的新设备兑换后分别丢弃首次成功响应，双方精确重试并读取同主体训练记录。旧设备 session 和 vault 为合成测试，未运行原生 Keychain。近期重新认证失败后的 UI 恢复只由客户端合成响应测试覆盖，未完成真机联测。

编译探针首次对小程序在 JS 中寻找静态按钮文案而失败；实际生成器将文案写入 WXML，检查已修正。正式首页尚未挂载这些组件，尚未进行实际屏幕或 iPhone 视觉验收；进程重启会丢失内存中的未决请求，不能声称跨重启恢复。
