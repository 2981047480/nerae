# 新设备兑换加密回执存储

新增独立的审批兑换回执表、密钥 epoch 和未挂载的事务内存储组件。每个申请的 keyed scope 最多保存一份密文回执；同申请不同请求或不同幂等键不能覆盖，过期回执不自动重建。服务端需提供独立生成的三把回执密钥，epoch 缺失而已有历史或密钥不匹配时失败关闭；迁移清单追加 `auth/0011_approval_exchange_receipt.up.sql`。

存储层在调用者事务内锁定回执，验证密文与当前会话绑定，并以数据库时间检查到期。它**不验证新设备签名或 JTI，不消费审批，不提交事务**；`Open` 也无法自行阻止上层在提交前泄露明文。后续协调器必须在同一个事务中完成授权、证明防重、目标设备／会话创建、审批消费和回执写入，并且只在成功提交后向客户端返回令牌；暂不接 HTTP。

## 本机验证

- `python3 -B docs/evidence/A01/A01-24/approval_ledger_mysql_smoke.py`：私有 socket MySQL 和 Go race 测试通过，覆盖 epoch 并发初始化、历史存在但 epoch 缺失、密钥不匹配、单申请唯一、精确重放、请求冲突、跨主体拒绝、密文篡改、过期、等待锁跨过到期，以及故障时调用方事务回滚。首次执行因合成测试令牌不足 32 字符导致加密组件拒绝，修正测试数据后复测通过；失败数据目录保留。
- `python3 -B docs/evidence/A01/A01-07/mysql_smoke.py`：私有 MySQL 和 Go race 测试通过，将实际 `session.Store` 核验器、加密组件和新存储放在同一事务，验证正常回执及撤销设备后的拒绝。测试事务回滚，不代表真实兑换已提交。
- `go run ../../scripts/dev/migrate.go check`：清单及 17 项迁移校验通过；对应迁移工具 Go race 测试通过。新增 SQL 已在私有 MySQL 直接应用；实际部署迁移、现网数据和回滚策略未验证。
- `go test -race -count=1 ./...`：允许本机回环监听后退出 0；首次在沙箱内运行时邮件传输测试因无法监听 `127.0.0.1` 失败。全量命令未配置隔离数据库，因此需要数据库的测试以各自私有 harness 的结果为准。
- OpenAPI 静态检查 102/102 和 `scripts/plan.py check` 通过；这不是运行时、部署或设备验收。

测试未接真实 QQ、手机或线上数据库。审批兑换本身、提交确认丢失后的完整恢复、HTTP 错误脱敏和客户端页面仍未完成。
