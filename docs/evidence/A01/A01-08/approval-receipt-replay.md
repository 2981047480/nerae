# A01-08 新设备申请回执重放

## 范围

`ReceiptRecoverer` 在解密前核对完整原请求、已消费的原设备签名、活动邮箱身份、主体版本、申请状态与到期、目标设备状态及审批密钥 epoch；解密后以审批秘密摘要、nonce、比较码和到期时间核对当前申请。提交后在新事务重复上述检查，再验证证明及申请/回执时效，才返回轮询凭据。已兑换的申请，以及目标设备被撤销或归属其他主体时不能恢复；这不批准设备或签发会话。

## 验证

`python3 -B docs/evidence/A01/A01-08/mysql_smoke.py` 在仅 Unix socket 的新建私有 MySQL 上运行新旧两项 Go race 集成测试，退出 0；测试加载所需 8 项迁移。覆盖提交前不释放、原申请恢复、旧 REPEATABLE READ 快照、身份/账号版本与设备撤销、待批准或已批准状态、合成已兑换状态拒绝、同一请求变更、跨事务、回滚、过期、密文篡改、取消上下文及证明到期。实际持有用户行锁并停用账号，重放在等待后拒绝；时钟测试不模拟真实慢提交。

首次尝试设置 Go 测试过滤时脚本内部固定了旧测试名，因此只运行了旧用例；已调整脚本明确选择两项测试，并确认两项均实际执行通过。独立只读复核未发现具体 P0–P2 问题；其未运行测试。

## 限制

尚未接邮箱登录协调器、公开 HTTP 或真实设备。批准兑换及其幂等重放仍需单独完成，合成已兑换状态不是实际兑换端到端测试。提交后的撤销仍由后续请求重新鉴权；真实 SMTP、跨实例时钟与双设备同步未验证。
