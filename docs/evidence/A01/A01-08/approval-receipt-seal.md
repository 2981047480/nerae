# A01-08 新设备申请凭据事务内加密

## 范围

`Pending.SealForReceipt` 只在原事务和已验证邮箱证明仍有效时加密新设备申请的秘密、nonce、比较码和到期时间；密文绑定原请求摘要与申请引用。封装前检查原身份、主体版本、目标设备指纹、审批密钥、申请状态与有效期，且只能封装仍待本人决定的申请。`AfterCommit` 也会检查当前邮箱身份索引未变。

## 验证

`python3 -B docs/evidence/A01/A01-08/mysql_smoke.py` 退出 0；使用新建、仅 Unix socket 的私有 MySQL 和 Go race。覆盖跨事务、错误挑战、身份撤销、申请已决定、事务回滚、密文不含秘密、身份索引变化后拒绝释放；在提交后重新验证设备签名及当前申请状态，再检查加密回执可还原为原申请数据。原有本人决定、其他主体拒绝与并发决定测试同时通过。

## 限制

封装调用者仍负责从同一实际请求生成摘要，并把密文与挑战消费在同一事务写入仓储。真实回执读取、签名和授权复验的统一编排、批准兑换的幂等恢复、HTTP、真实邮件和双设备测试尚未完成；不能仅凭邮箱验证码为旧主体签发会话。
