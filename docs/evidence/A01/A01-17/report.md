# A01-17 客户端邮箱认证适配器：阶段证据

## 范围

实现邮箱挑战、验证码和设备证明登录、新设备批准状态与兑换的类型化 HTTP 合同适配。调用方提供请求键和签名，适配器不生成或替换凭据，不自行重试。网络错误及响应异常不能证明服务端是否提交：恢复时由调用方保留原请求键和完全相同的签名正文；一次明确得到 pending 的后续轮询属于新请求，应使用新键及新设备证明。适配器不实现持久恢复，也未接入页面、原生设备、服务或微信登录。

服务地址仅接受不含用户信息、查询、片段的 HTTPS；请求正文按合同构建，所有认证响应（包括错误）必须含 `Cache-Control: no-store`，非预期结构、状态、字段与已禁用用户拒绝处理。凭据、nonce 放在内部 WeakMap；普通结果对象不能直接 JSON 序列化，只有明确的签名/安全存储访问器可获取相应值。访问器取出后的数据仍由调用方负责保护，JavaScript 内存保护不是安全硬件。

## 验证

- `/opt/homebrew/bin/node --test apps/client/src/api/auth/emailAuthApi.test.mjs`：7 项通过。测试使用合成端口和合成数据，涵盖正常挑战、已认证/待批准、待定/拒绝/过期、无自动重试及重放请求内容一致、参数和 HTTPS 校验、缓存头、恶意/畸形响应、错误脱敏。
- `/opt/homebrew/bin/node apps/client/node_modules/typescript/bin/tsc --noEmit --strict --skipLibCheck --target ES2022 --module ESNext --moduleResolution Bundler .../emailAuthApi.ts`：类型检查通过；集成后还须完整客户端类型检查与资源编译。

## 限制

- **没有实现生产传输层**。注入的传输层必须验证系统 TLS、拒绝所有重定向（含跨域及 HTTPS 降级）、不缓存/持久化/记录正文或凭据、限制响应大小，并保留原请求正文。接口类型不能证明实现满足这些条件；未经验证不得挂载。DCloud 官方 [uni.request 文档](https://uniapp.dcloud.net.cn/api/request/request.html)列出证书校验配置，但未提供禁止重定向的明确选项；`sslVerify` 配置也不覆盖所有平台，不能凭文档认定安全。
- 键的字符、长度和无填充 base64url 规范编码校验不证明随机性；生产调用方必须使用本机已验证的密码学随机源。设备证明、账号归属、权限、验证码和服务端幂等仍由服务端独立校验。
- 合成端口测试不是 HTTP 实网、QQ 投递、跨设备同步或可安装包证据。账号切换/重启恢复、安全存储接线、年龄声明、受信设备批准及完整错误体验仍需后续实现。

独立 security review 指出错误响应未校验 `no-store`；修复后对 401 缺失、错误及重复缓存头均拒绝，同时保持合规错误状态的脱敏映射。

集成版本 `8dc2541`：客户端完整 `vue-tsc --noEmit` 通过；认证适配器与训练模块共 101 项 Node 测试通过。没有真实传输、页面、登录或设备验证。独立 reviewer 发现错误响应也应校验 no-store；现已修复并增加缺失、错误及大小写重复头的反例。
