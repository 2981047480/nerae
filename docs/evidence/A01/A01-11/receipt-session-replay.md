# A01-11 可信设备会话回执重放接线

## 范围

`ReceiptLogin.VerifyInTransaction` 对首次可信设备登录写入会话和密文回执后创建不可直接序列化的候选结果；对同幂等键、完全相同的后续请求复验原设备证明和当前会话，再恢复同一候选结果。`AfterCommit` 重新读取已提交回执、复核身份/设备/会话与时效，才返回原令牌。错误验证码回执和新设备待批准回执的重放仍明确不可用；本代码未挂载 HTTP 或限流。

## 验证

定向和完整 `docs/evidence/A01/A01-11/mysql_smoke.py` 在两个新建仅 Unix socket 的私有 MySQL 上通过 Go race，退出 0。覆盖相同请求并发返回同一令牌且只创建一份会话、账号停用后拒绝、事务回滚不释放、请求摘要冲突、新验证码替换槽位后仍可恢复原有效结果；新设备仍只能创建待批准申请。

首次并发测试失败：第二个事务的 REPEATABLE READ 旧快照看不到刚提交的会话，误返回登录拒绝；失败目录 `/private/tmp/nerae-email-flow-mysql-_ggotswm` 保留。会话授权改用按身份、用户、设备、会话顺序的当前锁定读取后，旧快照定向测试与应用层并发测试复跑通过，详见 [会话证据](../A01-07/session-receipt-replay.md)。

## 限制

尚无提交确认丢失的网络故障注入、完整 HTTP 响应资料、真实 QQ 发信、生产服务或真机。错误码、新设备审批及审批兑换的重放仍未接通；不能仅凭这条内部会话路径声称真实登录或跨设备同步完成。
