# A01-11 邮箱登录首次请求与加密回执的事务组合

## 范围

新增未挂载的 `ReceiptLogin.VerifyInTransaction`。同一实际请求产生幂等摘要和验证码/设备证明，按邮箱槽串行；错误验证码的尝试次数、可信设备会话或新设备待本人批准申请与对应密文回执在同一调用方事务内写入。所有写入及锁获取后再次核对原签名、防重标记、挑战时效与回执到期。结果对象不暴露会话令牌或申请秘密；错误或 `CommitRequired=false` 时调用方必须回滚。

已有回执暂返回 `ErrReceiptReplayUnavailable`，不同请求复用未过期键返回冲突；尚未实现重放、HTTP、限流接线或提交后凭据释放，禁止把此内部入口公开为登录接口。

## 验证

`GOFLAGS='-run=^TestReceiptLogin' python3 -B docs/evidence/A01/A01-11/mysql_smoke.py` 与不带过滤条件的脚本分别退出 0；使用新建的仅 Unix socket 私有 MySQL 与 Go race，脚本加载本测试所需 11 项迁移，包括登录回执迁移。覆盖错误码计数和回执同事务、首设备会话、新设备待批准、同键同请求与异请求、换键复用已消费证明不增加次数、非法签名、凭据与回执回滚、配置密钥不匹配、时钟失败、插入后模拟过期、同键并发只创建一份结果，以及密文不包含请求材料。所有成功的测试数据库目录由脚本清理。

独立只读复核最初将 challenge 的 `consumed_at` 与 JTI 标记混淆；经核对 `s.replay.Consume` 在验证码比较之前执行，复核已更正，并补充换幂等键复用相同 JTI 的数据库负例通过。

测试的时钟推进使用可控时钟，不代表实际数据库锁阻塞或跨实例时钟偏差。提交确认丢失、客户端重试解密、真实邮件、真实设备和生产服务仍未验证；本卡仍为 active。
