# App 新设备确认查询与本机联调

2026-11-03：邮箱登录在收到需要设备确认后保留本次设备身份和受保护的确认参数。用户显式检查时，以现有设备密钥对 `approval_exchange` 生成签名：收到 pending 后下次使用新签名及新随机键；限流、断网、响应不确定或 vault 写失败时保留同一请求精确重试。拒绝／过期不会创建会话，退出或切换账号使迟到响应失效。成功登录仍需当前会话复验，并经过原有的 18+ 本人声明门槛。

登录组件新增“检查确认状态”，未重新设计视觉；它仍未挂载正式首页，旧设备的批准界面尚未实现。确认参数目前仅保存在本次进程内；进程退出后需要重新开始验证码登录，不能描述为跨重启恢复。App 信任的服务地址、部署和真实原生安全存储仍待接入。

验证：认证和组件相关 Node 测试 97 项通过，覆盖等待后重新签名、丢响应和限流精确重试、vault 写失败、拒绝／过期、退出时迟到响应、品牌化设备签名及成年声明门槛。`vue-tsc --noEmit -p tsconfig.json` 通过。锁定 5.26 的 `scripts/quality/verify_uts_plugin_build.py` 编译引用新组件的 App 和小程序探针，并检查确认按钮代码被包含；探针不是安装包或真机执行。视觉未在真实 iPhone 或小程序中验收。

`NERAE_RUN_API_ASSEMBLY_TEST=1 python3 -B docs/evidence/A01/A01-24/mysql_redis_smtp_http_smoke.py` 使用私有 MySQL／Redis、本机 TLS 和合成 SMTP 执行 Go race 联调。新增 Node 进程实际运行项目的 `EmailLoginFlow`、`EmailAuthApi` 和会话协调器，使用合成设备私钥与内存 vault；旧合成设备通过真实 HTTP 批准，新设备兑换的首次成功响应在测试中被丢弃，原请求重试取得同一会话并读取已有训练记录。测试验证码由隔离夹具的固定合成密钥派生，并非真实邮件投递，也没有使用原生设备签名或 Keychain。独立只读复核未发现明确 P0/P1。
