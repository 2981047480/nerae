# A01-04 登录回执的设备证明复验

## 范围

增加基于挑战 ID 的受保护邮箱索引查询，以及事务内 `ReceiptProof`：从受锁定的原挑战读取 nonce 和公钥，按原策略与当前较严格策略重新验证 ES256 签名，再检查该设备的 JTI 防重标记已存在。锁定标记后重新读取时间并复验签名；句柄在每次同事务使用时重新检查数据库状态。验证码重发后允许核对旧证明，但不能借此新建登录。

首次消费时校验挑战期限；回执重试不会再次消费挑战，原挑战到期本身不使仍有效的签名和结果失效。回执、签名及当前用户、身份、设备、会话或审批授权均需分别复验，证明对象不能授予权限或释放凭据。

## 验证

```sh
GOFLAGS='-run=^TestEmailReceiptProofRevalidation$' python3 -B docs/evidence/A01/A01-04/mysql_smoke.py
python3 -B docs/evidence/A01/A01-04/mysql_smoke.py
```

两次退出 0，分别使用新的仅 Unix socket 私有 MySQL 和 Go race 测试；成功后测试脚本移除自己创建的数据库目录。独立测试覆盖回滚标记、错误码已消费证明、不同密钥签名、从未消费的 JTI、原挑战与设备绑定、同事务修改、事务结束、槽位换绑、挑战过期而签名仍有效、签名过期及锁后时钟推进；完整挑战事务回归也通过。测试中用可控时钟模拟等待后的时间变化，并未制造实际阻塞的 SQL 行锁或跨实例时钟偏差。

## 限制

证明复验不匹配回执摘要，不核对凭据撤销，不解密回执，也不签发或重放会话；协调器必须在同一事务绑定这些步骤，提交后再次核对并处理提交确认未知。当前没有登录 HTTP、真实 QQ 邮箱投递或真机验收。

补充 `ReceiptProof.ForRequest` 将句柄绑定原挑战和完全相同的 compact 签名；不同签名即便由同一私钥对相同 JTI 再次签名也不能混作原请求。独立和完整挑战私有 MySQL race 测试均重跑退出 0。验证码和幂等键仍须由回执摘要独立匹配。

`ReceiptProofDetails.VerifyTimeOnly` 允许在慢提交后仅重验同一签名的时间和密码学有效性；它不核查数据库、不授予身份或会话权限。有效、过期、零值及完整挑战事务在私有 MySQL race 测试通过。
