# U02-01 · 双模式有序投影与回执核对

状态：partial，未接受。基线 `e87bea5`，Lead 实现；独立 reviewer 复核了提交范围、完整基线、版本递增和主体绑定，并提出回执漏组、创建时间及自定义动作恢复显示名的边界，已补测试和修复。最终只读复核未发现会误认回执或直接丢失记录的新阻断；schema 的 null 与省略可能代表同一无值，但合同尚未明示该等价，客户端保守要求核对，可能增加一次恢复操作。集成证据以本卡后续记录为准。

两模式都从相同的草稿和当前登录下取得的完整服务端快照准备写入。逐组模式只提交用户选中且已确认的组，其他草稿不被顺带提交；训练后模式提交有效的非空组。已保存组、动作顺序、稳定组序号或服务器版本与本机状态不符时，暂停提交并保留输入，不能盲目覆盖。只在当前登录会话内使用本适配器签发的不可变快照；账号或登录代次变化阻止旧请求继续生效。

保存请求以快照预测完整活动组和动作顺序；只有返回的组、未变更组、已确认值、冻结名称、日期、时区、状态、创建/确认时间及版本增量都符合预期，才把响应交给调用方。时间按完整瞬间比较，允许同一时刻的不同合法时区或零填充表示。无变化批次同时要求更新时间不变；完成请求需绑定同一基线，并核对完成状态、版本递增、全部实际组和明确填写的完成字段。HTTP 200 本身不构成同步成功。请求对象在途修改不改变已编码内容或核对条件；冲突和不符的响应不会自动重试。
