## 统一错误响应增量

提供服务端随机生成的请求标识、固定错误类别到 400/401/403/404/409/412/422/429/503/500 的响应映射及 `no-store`；响应体通过当前 `Error` schema 校验，未知类别回退通用 500。工具不接收上游错误正文或调用方消息；写入错误和短写只返回脱敏错误。`go test -race -count=1 -v ./internal/middleware` 9 项主测试通过，含全部状态、请求 ID 一致、编码失败、写入错误和短写；独立 reviewer 只读复核未发现阻断问题。

这只是未挂载的输出工具。真实 handler 仍须通过可识别领域错误选择正确状态，按资源访问规则决定 403/404，接通 requestId 与脱敏日志，并针对每个 operation 和客户端验证；响应头 `X-Request-ID` 尚未列入合同声明。写入开始后无法撤销已发送的状态码，调用方不能将写入失败当作可重新发送完整响应。

## 真实会话请求边界增量

`AuthenticateRequest` 仅读取单个 Bearer 凭证，调用已有签名与数据库会话验证；不从请求头、角色或客户端字段构造主体。它返回与调用方事务绑定的受保护 Principal，业务写入仍须在同一事务内做资源/年龄授权并在提交前重新检查。底层会话存储当前把无效凭证与数据库故障都合并为不可用错误，因此本入口的 `ErrSessionRejected` 不能直接、无条件映射为 401；真实路由前须补齐错误分类。

`go -C apps/api test -race -count=1 ./internal/middleware` 通过（无 DSN 时数据库用例跳过）；本卡 `mysql_smoke.py` 启动新建的仅 Unix socket 私有 MySQL，绑定本次临时目录后运行同包测试，通过后关闭并只清理自身成功的临时库。数据库测试使用合成密钥、签名会话和直接写入的隔离身份数据，不表示邮箱挑战或真实登录已完成。测试覆盖伪造身份/角色头、无效签名、跨事务和回滚后使用、同事务撤销，以及观察到真实锁等待后的并发撤销；还覆盖账号禁用、令牌版本变化、身份和设备撤销。首次在仓库根目录直接运行 `go test` 因找不到 go.mod 失败，改为指定 `-C apps/api` 后通过。独立 reviewer 初审指出测试 DSN 应绑定本次目录，并建议补充分事务撤销；这些均已补充并复验。
